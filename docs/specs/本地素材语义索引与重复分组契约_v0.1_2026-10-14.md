| 字段 | 内容 |
|---|---|
| 文档编号 | SPEC-LIBRARY-SEMANTIC-001 |
| 状态 | 有效 |
| 版本 | 0.1.0 |
| 日期 | 2026-10-14 |
| 适用范围 | `ai-ad-editor library index/search/duplicates` |
| 网络策略 | 禁止联网；索引与查询只读本地文件 |

## 1. 目标和边界

素材库需要让 Agent 能按文件名、目录、字幕侧车、媒体属性和精确内容哈希选择素材。当前契约提供可复现的确定性本地索引，解决基础资产检索、时长/分辨率/音频流过滤和重复素材发现。它不是视觉语言模型、向量数据库或内容级人物/物体识别器。

模型级能力必须以后续显式本地模型适配器接入，并把模型路径、模型许可证、版本和推理结果写入索引 provenance；没有这些证据时，Agent 应把结果解释为 `metadata_search`，不能解释为“理解了画面内容”。

## 2. 索引输入与输出

`library index --root ROOT --output CATALOG` 递归索引受支持的本地媒体、字幕和字体扩展名。媒体由本机 `ffprobe` 探测；字幕由本地解析器读取 cue 文本；字体只登记文件和哈希，不尝试执行或解析网络字体服务。

目录版本为 `0.3.0`，确定性语义索引版本为 `0.2.0`，每条记录至少包含：

| 字段 | 语义 |
|---|---|
| `id` | 由内容哈希和相对路径摘要组成的稳定记录 ID；相同字节但不同路径仍是不同记录 |
| `sha256` | 文件内容哈希，格式为 `sha256:<hex>` |
| `probe` | 本地媒体流、时长、分辨率、编码和字幕 cue 数量 |
| `rights` | 许可证和验证状态，沿用索引调用参数，不能替代 Rights Ledger 证据 |
| `semantic` | 确定性索引层，包含 `source=deterministic-local`、规范化文本、token 和媒体 facets |
| `semantic.facets.subtitle_text` | 同相对 stem 的 `.srt/.vtt/.ass/.ssa` 侧车文本；单条最多 16,000 字符 |
| `semantic.model` | 当前固定为 `null`，表示未调用模型 |

索引顶层还写入 `semantic_search.vector_index=false`、`duplicate_groups`、`index_refresh` 和 `network=disabled`，让 Agent 可以在规划前识别能力边界。增量刷新和可选的 FFmpeg 感知候选见[本地素材库增量刷新与感知候选契约](./本地素材库增量刷新与感知候选契约_v0.1_2026-10-14.md)。

## 3. 侧车字幕关联

当 `product.mp4` 与同目录同相对 stem 的 `product.srt` 同时存在时，字幕文本会写入视频记录的 `semantic.facets.subtitle_text`，并参与搜索。关联使用相对路径 stem，避免不同目录中同名文件误关联；`product.en.srt` 不会自动猜测为 `product.mp4` 的侧车。

字幕文件本身仍作为独立 `subtitle` 记录。解析失败不会阻止其他文件索引，错误进入目录 `errors`。

## 4. 查询契约

```powershell
python -m ai_ad_editor library search --catalog .\catalog.json --query "product launch" --kind video --has-audio
python -m ai_ad_editor library search --catalog .\catalog.json --min-duration 2 --min-width 1080 --duplicate-only
python -m ai_ad_editor library duplicates --catalog .\catalog.json
```

`library search` 支持：

| 参数 | 规则 |
|---|---|
| `--query` | 在规范化文件名、相对路径、类型和侧车字幕文本中做词组/token 匹配；CJK 采用字符 token；空查询返回过滤后的全部记录 |
| `--kind` | `video`、`audio`、`image`、`subtitle`、`font` 等记录类型 |
| `--verification-status` | 按索引记录的权利验证状态过滤 |
| `--min/max-duration` | 以秒过滤；使用媒体探测时长 |
| `--min-width/--min-height` | 以像素过滤；非视频记录按 0 处理 |
| `--has-audio/--no-has-audio` | 按实际探测到的音频流过滤 |
| `--duplicate-only` | 只返回 SHA-256 精确重复组中的记录 |
| `--limit` | 返回上限，至少返回 1 条的有效上限 |

结果按确定性分数排序：完整文件名、文件名包含、文本词组和 token 命中依次加权；同分按相对路径排序。结果 envelope 会声明 `search.source=deterministic-local` 和 `vector_index=false`。

## 5. 重复组契约

`library duplicates` 按 `sha256` 分组，只报告字节完全相同的文件。默认隐藏单成员组；`--include-unique` 可用于审计全部哈希组。组结果包含哈希、成员数、最大文件字节数、记录 ID 和相对路径。它不会把相似画面、转码版本或感知哈希近似误报为重复。

## 6. 权利与发布门禁

索引只是发现层。搜索结果进入项目或发布前必须经过项目资产登记和 Rights Ledger；`LicenseRef-UNVERIFIED` 不能满足商业发布。精确重复组也不会继承或合并许可证，复制文件必须逐条保留来源和证据。

## 7. 验收证据与后续扩展

当前验收覆盖：媒体/字幕/重复文件索引、同 stem 字幕搜索、音频流过滤、精确重复组、stat 签名增量刷新、可选感知哈希候选和能力清单边界。仍未关闭的扩展包括：本地 VLM 标签、可复现向量索引、OCR、人物/物体 embedding 和大规模性能压测。这些扩展进入本地模型或索引版本升级时，必须增加独立 fixture、许可证审计和质量报告。
