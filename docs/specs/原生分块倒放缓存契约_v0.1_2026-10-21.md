## 功能范围与编号

| 编号 | 约束 | 行为与边界 |
|---|---|---|
| RC-01 | 激活条件 | 普通原生视频叶片段倒放，且整段倒放预计帧缓冲超过整个图共享的 256 MiB 配额时，自动计划分块缓存。嵌套名义 CFR 时钟、内联合成面不在此分支内。 |
| RC-02 | 帧区间 | 读取原生时间戳与时长，按作者请求的半开源区间镜像显示区间；保留覆盖小数入点的帧、VFR 长短不等的持帧、非零 demux 起点和真实短源前的空隙。 |
| RC-03 | 分块 | 每帧保守按原生宽×高×16 字节估算，顺序执行一个块；每块不超过 256 MiB 的选中帧栅格估算。该数字不是整个进程的 RSS 或总峰值内存保证。 |
| RC-04 | 寻址 | 按原生帧索引倒序划块；从块起点之前寻址，保留 GOP/B 帧预卷，再按原生绝对 PTS 裁切。 |
| RC-05 | 中间格式 | 原生像素格式用 FFV1/NUT 保存。`+pix_fmt` 禁止静默转换为另一种位深或丢弃 alpha；本地编码器不支持时显式失败。 |
| RC-06 | 中间时钟 | 缓存的 25 Hz 仅为连续帧编号和无损拼接时钟，不代表源视频帧率或原始 VFR 时长。渲染器读取后重新应用镜像区间时钟，再做常速/源相对非线性变速及全局 CFR 采样。 |
| RC-07 | 方向 | 缓存编码时禁用自动旋转，保留原生编码平面；读取时重建正交旋转、镜像显示矩阵。非正交、带平移或透视的矩阵拒绝执行。 |
| RC-08 | 输入锁定 | 缓存 key 包含源字节、帧索引、选区、格式、原生 FFmpeg/ffprobe、缓存实现与时钟实现的 SHA-256。路径属于 key；换工程根目录会重新构建。 |
| RC-09 | 就绪缓存 | 复用前验证清单、输出字节和帧数/格式；渲染发布前再次验证缓存及输入。已损坏、已移除或发生变化时拒绝发布成片，保留原始诊断。 |
| RC-10 | 磁盘预算 | 保守预约为两份选中帧的 16 字节/像素估算，另加每块 1 MiB 和固定 16 MiB；上限 128 GiB，最低保留 64 MiB 磁盘余量。运行时继续检查单个输出体积和磁盘余量。 |
| RC-11 | 事务与取消 | 使用项目内 `renders/.tmp/` 暂存，逐块检查取消，并监控原生子进程；完成并复核后原子发布缓存目录。失败临时文件清理与就绪缓存保留分别处理。 |
| RC-12 | 显式清理 | `cache list/prune` 只盘点、清理当前工程 `cache/reverse-video/<key>/` 中已知的派生文件；默认不会自动淘汰。当前工程引用的缓存受保护。 |
| RC-13 | 目录约束 | 路径在解析前检查符号链接与 Windows 目录联接；目录内只接受 `frames.nut`、`receipt.json`。遇到陌生文件停止清理；逐个删除已知文件后移除空目录，不递归删除陌生树。 |
| RC-14 | 内容验收 | 10-bit 平面与 alpha 的缓存保真不等于最终合成管线的 HDR、线性光或自然素材质量验收；本版本不作此承诺。 |

## Agent 使用

正常使用现有 `render`、`preview frame/range` 即可触发，`--dry-run` 只返回计划，不编码或创建倒放缓存。

```powershell
ai-ad-editor render --project E:/video/project --output E:/video/project/renders/out.mp4 --dry-run
ai-ad-editor render --project E:/video/project --output E:/video/project/renders/out.mp4
ai-ad-editor cache list --project E:/video/project --kind reverse-video
ai-ad-editor cache prune --project E:/video/project --kind reverse-video --keep-mib 1024 --dry-run
ai-ad-editor cache prune --project E:/video/project --kind reverse-video --key <64位缓存key> --dry-run
```

清理命令省略 `--dry-run` 才执行删除。指定 `--key` 时，保留配额必须为 0；其他 key 不受影响。盘点结果 `media_integrity_checked=false` 明确表示盘点不校验媒体内容，不能将其作为画面验收结果。实际复用由执行器另行验证。

缓存命中回执中的 `new_encodings`、`new_source_decodes` 只统计缓存准备阶段的块编码/源解码。当前 `build_filter_graph` 仍会通过 `ffprobe -show_frames` 解码建立完整源帧索引；缓存命中不等于整个渲染流程免解码。此外仍有源/工具哈希读取、缓存包计数扫描和最终成片编码成本。

## 预算与性能边界

128 GiB 的保守磁盘预约会先于压缩收益进行准入判断：4K、25 fps、16 字节/像素且双份预约时，仅约 20 秒就可能触达该上限。高压缩率的画面也可能被保守估算拒绝。当前核验的原生 4K 选区为 8 帧、0.32 秒，不能据此声称长片延迟、长片 4K 容量或整体内存峰值已验收。

原生索引最多 1,000,000 帧，最多 65,536 块，表达式最多 64 MiB，工作时间基分母最多 2,147,483,647；超过边界显式失败。索引探测超时 300 秒，每个缓存原生工作进程超时 3,600 秒。输入媒体仍受现有项目导入、时长、尺寸和本地策略约束。

分块缓存改善的是整段 `reverse` 过滤器的帧缓冲形态。下一步仍需持久化帧索引、合理的压缩磁盘预算、长片自然素材和 4K 吞吐/峰值内存实测。倒放音频、一般嵌套 VFR 等效、自然素材审美与剪映整体等价均未因此验收。
