# 本地节拍卡点与混剪时间线契约 v0.1

| 项目 | 内容 |
|---|---|
| 文档编号 | SPEC-BEAT-CUT-001 |
| 状态 | 有效 |
| 日期 | 2026-10-15 |
| 适用范围 | `media beat-cut`、本地 FFmpeg 音频分析、Agent Project 视频轨道 |
| 运行边界 | 原生 Windows、项目内本地素材、FFmpeg 本地执行、网络关闭 |

## 1. 目标

为 Agent 提供剪映式“音乐卡点/节拍混剪”能力的无 GUI 契约。命令读取本地音频或视频中的音频流，用 `ffmpeg` 转换为 PCM 后进行确定性能量峰值分析，生成源范围合法的片段计划，并可在创建快照、项目校验和操作记录后写入视频轨道。

该能力是可审计的卡点时间线生成器，不把能量峰值解释为音乐结构、歌词、情绪或语义节拍。计划中的每个源视频必须已经登记为项目资产，避免 Agent 绕过 Rights Ledger 直接把未知素材写入时间线。

## 2. CLI

先预览参数和本地输入：

```powershell
python -X utf8 -m ai_ad_editor media beat-cut `
  --project .\work\demo `
  --input .\media\music.wav `
  --source-asset-id product_a `
  --source-asset-id product_b `
  --track-id track_video_1 `
  --dry-run
```

用真实本地音频生成报告但不写入时间线：

```powershell
python -X utf8 -m ai_ad_editor media beat-cut `
  --project .\work\demo `
  --audio-asset-id bgm_asset `
  --source-asset-id product_a `
  --track-id track_video_1 `
  --output .\work\demo\validation\beat-cut.json
```

应用前应检查报告，再显式加 `--apply`。目标轨道有现有片段时，命令默认拒绝重叠；确认需要重建该轨道时才使用 `--replace-track`：

```powershell
python -X utf8 -m ai_ad_editor media beat-cut `
  --project .\work\demo `
  --audio-asset-id bgm_asset `
  --source-asset-id product_a `
  --source-asset-id product_b `
  --track-id track_video_1 `
  --source-mode cycle `
  --max-clips 128 `
  --apply `
  --replace-track
```

`--input` 只接受本地路径；远程 URL 会在进入 FFmpeg 前拒绝。`--audio-asset-id` 只负责节拍证据，自动生成的片段仍引用 `--source-asset-id` 指定的项目视频资产。

## 3. 输入与输出

### 3.1 输入

| 字段/参数 | 约束 |
|---|---|
| `--audio-asset-id` / `--input` | 必须二选一；资产 URI 必须是本地文件 |
| `--source-asset-id` | 至少一个；资产 `kind` 必须是 `video`，并有有效 `probe.duration_tick` |
| `--start-seconds` / `--end-seconds` | 音频分析区间，不能越过输入时长 |
| `--min-segment-seconds` | 必须大于 0，过滤过短节拍区间 |
| `--max-clips` | 正整数；超过后截断并写 `BEAT_PLAN_TRUNCATED` 警告 |
| `--source-mode` | `cycle` 循环使用素材；`ordered` 按顺序使用，耗尽后复用最后一个 |
| `--timeline-start-seconds` | 目标轨道中的写入起点，不能为负数 |

### 3.2 计划结构

报告 `validation/beat_cut_*.json` 的 `plan` 至少包含：

```json
{
  "beat_cut_version": "0.1.0",
  "engine": "ffmpeg-local-energy-beat-v1",
  "network": "disabled",
  "analysis": {"status": "ok", "bpm": 120.0, "anchors": [0.5, 1.0]},
  "duration_tick": 180000,
  "source_assets": [{"id": "asset_a", "duration_tick": 90000}],
  "clips": [
    {
      "id": "beatcut_..._000",
      "beat_start_seconds": 0.0,
      "beat_end_seconds": 0.5,
      "timeline_start_tick": 0,
      "duration_tick": 45000,
      "asset_id": "asset_a",
      "source_in_tick": 0,
      "source_out_tick": 45000,
      "speed": 1.0
    }
  ],
  "warnings": []
}
```

所有 `source_out_tick` 都必须不大于所引用资产的 `probe.duration_tick`。源素材短于节拍区间时，计划缩短源范围并写入小于 1 的 `speed`；这保持项目引用合法，但属于需要听感和画面质量复核的近似。

## 4. 应用事务与证据

带 `--apply` 的成功操作必须：

1. 在改写目标轨道前创建 `before-beat-cut` 快照。
2. 将片段 ID、节拍区间、源范围和速度写入 `project.json`。
3. 更新序列时长，运行内置项目语义校验。
4. 写入 `validation/beat_cut_*.json`，包括 `operation_id`、快照 ID、分析源哈希和校验结果。
5. 写入 `operations/<operation_id>.json` 和 `provenance.change_log`。

目标轨道存在重叠且未指定 `--replace-track` 时返回 `BEAT_CUT_TRACK_OVERLAP`，不会写入项目。应用后校验失败返回 `BEAT_CUT_APPLY_INVALID`；项目事务恢复机制负责恢复元数据，FFmpeg 分析本身不产生渲染副作用。

## 5. 本地算法与质量边界

`detect_beats` 使用本地 FFmpeg 输出单声道 PCM，按固定窗和 hop 计算 RMS 能量，在自适应阈值和最小间隔内寻找局部峰值，并从峰值间隔估计 60–180 BPM。它适合强节拍广告音乐的第一版卡点候选，不等同于 librosa beat tracking、音乐结构分析或人工听感确认。

必须在发布前检查：

- 报告中的 `anchors` 是否与听感和音乐段落一致；
- `BEAT_SOURCE_SLOWED` 是否造成可接受的慢放、音画或重复感；
- 节拍素材的 Rights Ledger、渠道和许可证门禁；
- 应用后的渲染质量、黑帧、音画时长和目标 LUFS。

以下能力仍属于后续扩展：多层节拍（小节/强拍/弱拍）、歌词/语义节拍、智能镜头内容匹配、转场句柄自动优化、速度曲线与补帧联合规划、跨轨音频自动铺设和 GPU 音乐分析。
