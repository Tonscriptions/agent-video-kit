# 离线 OCR 与文字运镜锚点契约

V62 产品增量；目标是补齐录屏/素材文字识别和由识别框生成可编辑运镜的实际内核。保留完整剪映功能与效果目标，本契约不是整体等价验收。

| 编号 | 实现和预先验收要求 |
|---|---|
| G62-01 | `ocr adapter register/list/inspect` 使用 `extensions.local_ocr`；显式已有原生 Python、PP-OCRv4 det/rec ONNX、来源许可证据；所有文件及本地实现绑定 SHA。默认 internal/unverified，不运行安装、下载或在线服务。开发获取与运行分离。 |
| G62-02 | `ocr scan` 只接受登记视频/图片；实际解码选中的源帧，输出源帧号、PTS、原画布四边形/归一化框、原识别文本及 det/rec 分数。使用真正的 DB 检测和 CTC 识别模型，不读测试答案或 DOM。 |
| G62-03 | CPU ONNX Runtime，关闭遥测；原生隔离 worker 的 Python 网络调用拒绝；禁止 ONNX 外部张量、自定义算子域/代码，限制输入、帧、候选框、识别宽度、报告及执行时间；FFmpeg 子进程由自身 Windows Job 管理，不操作其它进程。Python guard 不是系统级沙箱。 |
| G62-04 | 显式 CFR 源帧选择，不把抽样时钟称为真实点击/帧级变化检测；拒绝旋转、非方形像素、非零源 PTS 或不一致帧格。默认最多 120 帧、单帧 16M 像素、检测长边 1536、单帧 128 框、识别宽度 2048。 |
| G62-05 | 注册和 scan 的 dry-run 不执行模型、不保存或更改项目；实际报告在项目 validation 下，保留 source/model/implementation 摘要与权利依赖，随现有 package 保留。失败不提交报告/项目登记；取消/超时回收自建进程。 |
| G62-06 | `ocr anchors` 在指定源帧精确查找文字，默认区分大小写；多个匹配明确拒绝，不以最高置信度暗选。输出基于文字框的作者位置/缩放关键帧，可 dry-run 或 apply，原片段音频/范围/时钟不变。 |
| G62-07 | 首版锚点要求同尺寸直接媒体、正向一倍速、无已有变换/裁切/同通道关键帧；聚焦后显式返回全景，边缘目标采用有限画布可见约束。不把文字框等同按钮可点击区域或自动动作识别。复杂坐标组合继续开放。 |
| G62-08 | 英文真实受控录屏和原创中文测试图分别独立写预期文字及几何。英文指定至少 4 个目标、中文至少 3 个目标：逐目标精确识别，识别框覆盖文字真值 ≥0.8、中心差 ≤12 源像素。保持原识别输出，失败不修改原答案、不降阈值。 |
| G62-09 | 实际生成锚点成片，逐帧 PTS、实际目标边缘/中心投影最大差 ≤5 像素，回全景 RGB 最大差 ≤3、PCM 最大差 0；样例包含原片、实际输出和 GIF。静帧/连续播放/听审分别报告。 |
| G62-10 | 单元测试验证 CTC 重复/空白、几何、模糊匹配拒绝、来源/实现篡改、边界/预算、dry-run、事务、依赖和取消。完整产品回归、原生离线发行安装及安装版模型/CLI 实测；子集与全量不叠加。 |
| G62-11 | 原模型不随发行包自动分发；保留 Apache 2.0 来源/声明，字体单独许可。自然场景小字、竖排/方向分类、隐私覆盖、任意 UI 动作/语义、自然质量与完整剪映等价保持未验收；OCR 不能作为“已找全敏感信息”的证据。 |

DB 预后处理依据 PaddleOCR/RapidOCR 的公开算法；本地实现使用已有 OpenCV/NumPy/ORT，矩形外扩用解析几何，不引入或安装 pyclipper/shapely，不执行上游下载器。CTC 识别字典直接使用已登记 ONNX 的模型 metadata；缺字典或形状不符明确拒绝。

2026-10-19 原生成片开发检查补充：G62-05 的报告属于观测数据。审计仅将有明确 OCR 报告/锚点结构的识别 `text`、一致的精确查询 `query` 视为普通文本，原样保留冒号及画面里的 URL；不得将它们当作资源地址执行。source/model/program/extra 字段仍逐项拒绝远程引用，伪造报告不能豁免这些字段；锚点应用前仍校验项目登记、报告及来源摘要。FFmpeg 管道命令保留确定性摘要及协议白名单，不把 `pipe:1` 当作媒体引用。发现此问题前启动的 full-r1 仅作开发回归，最终验收重跑固定源码全量；G62-08/09 阈值不变。
