# OpenFilm 可拆模块与现有内核降本清单

结论：**可以复用，适合提取小型纯模块、规则和上游测试夹具。现有项目已经采用了它的大部分高价值基础能力；新增收益主要在开放编辑工程的交换适配，以及自建 Agent 宿主时的图片上下文管理。** 不需要迁移整个编辑器。OpenFilm 的云模型适配层也不能补齐本项目尚缺的离线 AI 算法和自然质量验收。

本页为 **R14 研究复核**。检查以已发布 `d1ae0967` / V79 为本地基线，不新增产品功能、模型推理或成片验收；并行产品发布不计入本轮结果。历史评估中的“候选”不能继续当作尚未开发的功能重复计费。

## 3. 能真正独立拆出的边界

静态顶层 import 闭包检查显示：`nle.mjs` 为 **3 个本地文件＋Node 内置模块**；`fcpxml.mjs` 为 **5 个本地文件＋Node 内置模块**；`pi-config.mjs` 为 **1 文件、无 import**；诊断为 **4 个本地文件＋Node 内置模块**。这四个候选的本次调用没有启动 Studio、Electron、Chromium、模型 SDK 或网络服务。闭包仅表示检查的静态 import，不代表执行任意函数都没有副作用；例如 `nle.mjs` 的 `probeSource` 会调用本地 ffprobe，本轮规划观察没有调用它。

推荐保留现有主链：**Agent → 本地 CLI → Agent Project → 已有 FFmpeg / 本地模型 / 受控 HTML 出帧**。上游纯函数和测试通过薄适配层接入；开放工程交换继续从 Agent Project 导出。不增加第二种作者时间线作为主工程格式。

| 观察编号 | 本次实际结果 | 必须补的宿主适配 |
|---|---|---|
| OF14-B01 | `nleFps(48/90/120)` 分别选择 **50/60/60** | 不直接把“最近支持帧率”当作用户请求已被精确保留；拒绝或显式报告转换 |
| OF14-B02 | 30 fps 下 `frameSpan(0, 0.001)` 得到 `[0,0)` | 极短片段会量化为空；作者 tick、交换帧与音频采样必须分开报告 |
| OF14-B03 | 25 fps 源、30 fps 序列、源入点 1 秒，计划记录 source-in 30；FCPXML 源格式写 1/25 秒，xmeml 文件 rate 写 30 | 这是已观察的序列化结果，**尚未证明外部程序中的音画错误或正确**。混合帧率须在实际目标开源程序打开、重链接、重渲染后比较源帧和 PCM |
| OF14-B04（5 组） | 变速 1.5、旋转、CSS look、淡变、HTML 均产生 `render` job；示例为 60 帧带透明视频 | 拿到的是待执行烘焙计划，没有执行就没有成片；烘焙会损失原参数可编辑性，必须写入损失报告 |
| OF14-B05 | 隐藏轨道的片段保留，`enabled=false` | 可以借用保留可编辑对象的规则，禁止导入后无提示丢弃 |
| OF14-B06 | 向规划输入额外加 Agent Project 的 `rgb_curves` 字段，仍为 link job，输出不保留该字段 | 宿主工程效果不属于上游输入契约；必须先识别每种能力并原生映射、明确拒绝或烘焙，不能直接传额外 JSON 字段 |
| OF14-B07 | FCPXML format 固定 `1-1-1 (Rec. 709)` | HDR / 色彩管理不在本次可直接复用验收范围 |
| OF14-B08 | 图片预算设为 4，8 字符图片被移除、原会话不变；序列化请求仍 **20,341 字节** | 图片 base64 预算不是整个 JSON、文本、token 或宿主保留内存预算；另设总请求和本地模型上下文上限 |

FCPXML 的第十项原测试需要 `/Applications/Final Cut Pro.app/.../FCPXMLv1_10.dtd` 和系统 xmllint，本机不具备，按上游条件**实际跳过 1 项**。本轮没有下载该专有程序、借此要求安装它或将跳过写成通过。XML 生成、原始断言与实际目标 NLE 兼容是三个不同验收层次。

## 4. 剩余成本与排期建议

以下为一名熟悉现有工程的开发者的**规划估计**，非本次实测人时，也不是已经节省的天数。生产化包含限定适配、失败 / 取消、内容身份、损失报告、包重放与真实离线安装；不包含新建 Agent 框架或全效果无损双向互通。

| 顺序 | 限定交付 | 原型 / 生产化 | 采用条件 |
|---|---|---|---|
| 1 | 保存 A10–12 的固定源码、纯函数测试与风险夹具，后续开发按编号引用 | 本轮已完成研究，不再安排一次重复调研 | 继续现有内核和产品缺口排期 |
| 2 | 若建设自有本地多模态 Agent 宿主，拆 `fitImages` 并加完整请求 / token / 文件重读预算 | **0.5–1 /2–4 人日** | 已有可控的消息管线；新建该管线的工程量另算。外部 Codex 使用场景不默认排此项 |
| 3 | 若明确需要一种新的基础 NLE 导出，提取轨道 / 资源规划和对应 XML writer | **3–6 /8–15 人日** | 确认目标开源程序实际支持的格式；验基本剪切、源范围、轨道、静态布局、音频及字幕，不引入专有运行依赖 |
| 4 | 将 A10 的轨道 / 重叠等夹具用于改进现有 OTIO / MLT | 包含在相应交换功能修复内，不与第 3 项重复相加 | 以当前适配器的具体失败为触发，不为移植而增加一套导出系统 |

第 2、3 项若都满足前提，限定生产化预算合计 **10–19 人日**；它不是当前必须花费，也不含整个剪映对标产品。已经完成的 HTML、组件、字幕、缓存、诊断和硬件探测不重复计费。没有实际工时对照，本轮不宣称节省了整个项目的某个百分比。

仍应独立开发验收：自然素材上的 AI 抠像 / 人像 / 跟踪 / 补帧 / 修复质量、完整特效与转场、长片及 HDR、实时能力、版权素材与模板库。网页能画出效果、云 API 有同名能力或存在一个导出按钮，都不足以认定已有本地算法内核或与剪映效果等价。
