## 1. 统一像素接口

用户素材和后续效果/合成器使用 straight RGBA；进行空间插值时，先将 RGB 乘 alpha，再以相同坐标与滤波处理 RGB 和 alpha，结束后除以 alpha。alpha 为零的隐藏 RGB 不得污染可见边缘。插值阶段采用 `gbrapf32le`，不通过 8-bit 乘除来保存软覆盖。

普通 `scale` 沿用 v0.1。仿射使用浮点预乘→既有逆映射 `geq`→反预乘→RGBA；旋转、锚点、位移、缩放及其时间表达式不改变。动态尺寸 crop 对有 alpha 的输入，在 crop 逆采样和最终 canvas resize 全程保持预乘；最后才返回 straight RGBA。

## 2. 适配与补边

| 编号 | 路径 | 本版本接口 |
|---|---|---|
| G01 | 普通 fit/fill/stretch 与标量 scale | 浮点预乘缩放；原有功能和时间线参数保持 |
| G02 | 媒体/独立文字的仿射路径 | 浮点预乘逆采样，输出画布仍固定大小；画布外 alpha/RGB 为零 |
| G03 | 有 alpha 的动态尺寸 crop | 逆采样与最终 Lanczos resize 在同一预乘阶段；fit 补边 alpha=0 |
| G04 | 不透明素材的动态尺寸 crop | 保留原 8-bit 路径和不透明黑色 fit 补边；不是把所有黑色都改成透明 |
| G05 | 透明输出 canvas | 动态 fit 补边按透明接口处理，与普通 fit 一致 |

Alpha 识别继续依靠已登记探测格式和透明输出设置；现有 rgba/bgra/argb/abgr、yuva、gbrap、ya、pal8 保守识别不变。clip 的 opacity、蒙版、blend、转场继续消费 straight RGBA。没有新增 CLI 参数、模型、GUI、联网服务或下载。

## 3. 独立文字源

`drawtext` 在透明黑画布上产生的 RGB 已按覆盖率混合，不能直接再当 straight RGBA 使用。独立文字图层完成初始绘制后，先转换浮点并反预乘一次，随后按 G01/G02 变换。该转换只发生在独立透明文字图层；直接烘焙到媒体上的字幕不执行这一步。

同一图层上的多次 drawtext、word timing 和文字样式继续沿用原绘制顺序。源转换后，字形软边缘、opacity 和旋转不会再次重复覆盖率。明确的黑色描边/阴影是作者样式，应保留；“白字叠白底保持白色”的核验必须关闭这些样式。

## 4. 验收证据

1. 同 alpha、同非零 alpha RGB、仅隐藏 RGB 不同的 PNG/alpha MOV，通过正式 CLI 动态 fit/fill/stretch 后，所有编码 RGB 帧的差为零。
2. 旋转、动态 scale、锚点、位移、动态 crop 组合和独立文字分别接受白底白图层核验。背景为白且无作者黑色样式时，出现暗边或不透明黑条应失败。另用深底正向对照证明前景/文字实际存在。
3. 不透明动态 fit 保留黑色补边；对照采样避开编码块边界，不用透明修复改变该语义。
4. 公开组合样例含原视频、原 RGBA、真实旧/新成片、白底白图层结果、GIF、源码/媒体摘要和复现脚本。旧版固定本地 Git 提交，不以新代码模拟旧版。
5. 复用已编码人物素材时保留来源/模型权利依赖、原素材摘要与原失败；不把合成修复记成新模型推理或抠像质量验收。

实际范围和结果见[本轮实测](../validation/仿射动态裁切与文字透明合成实测_2026-10-16.md)。

## 5. 保留限制

仍在输入的编码 RGB 域进行运算，没有据此完成线性光/HDR 色彩管理。一般特效、畸变、其他空间滤镜仍需各自审查采样；本版本不证明所有第三方效果符合该接口。浮点中间缓冲和 CPU geq 的 1080p/4K 总内存、P50/P95、长期吞吐尚未独立验收。

编码帧的压缩、4:2:0、字形初始 8-bit 栅格和多次变换仍可产生误差，受控阈值不自动适用于所有广告素材。全源时钟、嵌套坐标、自然遮挡身份、人物/手持物完整抠像、修复结构、连续播放/听审与完整剪映等价继续按各自契约验收。
