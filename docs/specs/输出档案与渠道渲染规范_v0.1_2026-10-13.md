# 输出档案与渠道渲染规范 v0.1

| 项目 | 内容 |
|---|---|
| 文档编号 | SPEC-OUTPUT-PROFILE-001 |
| 状态 | 评审中 |
| 版本 | 0.1.0 |
| 日期 | 2026-10-13 |
| 运行边界 | 原生 Windows、Python、FFmpeg；默认离线 |

本规范定义 Agent 如何在同一项目时间线生成不同交付画布。档案只改变一次渲染的输出 settings，不改写项目源时间线，因此可以从同一工程重复生成竖屏、方形和横屏版本，并在 manifest 中追溯实际参数。

## 1. 内置档案

| 档案 | 画布 | 用途示例 |
|---|---:|---|
| `vertical` | 1080×1920 | 竖屏广告、短视频 |
| `square` | 1080×1080 | 方形信息流 |
| `landscape` | 1920×1080 | 横屏广告、演示视频 |
| `vertical_720` | 720×1280 | 低带宽竖屏预览 |
| `landscape_720` | 1280×720 | 低带宽横屏预览 |
| `custom` | `--width × --height` | 设备或渠道提供明确像素规格 |

调用示例：

```powershell
python -m ai_ad_editor render --project .\work\demo --profile vertical --output .\work\demo\renders\vertical.mp4
python -m ai_ad_editor render --project .\work\demo --profile square --output .\work\demo\renders\square.mp4
python -m ai_ad_editor render --project .\work\demo --profile custom --width 640 --height 360 --output .\work\demo\renders\preview.mp4
python -m ai_ad_editor render --project .\work\demo --profile vertical --container webm --video-codec libvpx-vp9 --audio-codec libopus --crf 32 --output .\work\demo\renders\preview.webm
python -m ai_ad_editor quality check --project .\work\demo --input .\work\demo\renders\square.mp4 --profile square --require-audio --expensive --target-lufs -14 --lufs-tolerance 1.5 --max-true-peak-dbfs -1
```

`--width` 与 `--height` 必须同时提供，范围为 64 至 8192，且必须为偶数以兼容 `yuv420p`。预设档案不能再叠加自定义宽高；需要自定义尺寸时使用 `custom`。

## 2. 几何与时间语义

- 时间线、素材源入出点、关键帧和音频混音保持项目原始时间基准。
- 视频片段先按源片段的裁剪、效果、关键帧和变速计算，再缩放并以黑色填充到目标画布；不会拉伸破坏宽高比。
- 透明素材和图层按照目标画布执行合成；默认输出为 H.264、`yuv420p`、AAC，但 Agent 可以声明 `mp4`、`webm` 或 `mkv`，并选择本地 FFmpeg 可用的 VPX/AV1、Opus 或 PCM 编码。webm 强制 VPX/AV1 视频加 Opus 音频；mp4 当前拒绝 Opus/PCM 组合。
- 档案渲染不会把覆盖档案写回 `project.json`；`outputs[]` 和 `.manifest.json` 记录 `profile`、实际 `settings.canvas`、输入哈希和质量结果。
- `quality check` 如果不传档案，则按项目原始 canvas 检查；如果传档案，必须与渲染时的画布一致。

## 3. 失败与证据

参数错误返回退出码 2；宽高不成对、超范围或奇数尺寸必须在启动 FFmpeg 前拒绝。渲染失败返回退出码 6，不能生成可被误认为完成的最终文件。每次成功渲染至少保存：

1. 目标档案和实际 canvas；
2. FFmpeg 命令、输入资产和源哈希；
3. 输出 SHA-256、ffprobe 摘要和 `quality` 报告；`quality check --expensive` 可读取 integrated LUFS 和 true peak，并用 `--target-lufs`、`--lufs-tolerance`、`--max-true-peak-dbfs` 形成门禁；
4. 所有降级警告，例如复杂转场句柄不足，或 Bezier 控制点缺失/无法映射时的近似。

## 4. 编码参数

`render` 支持 `--container`、`--video-codec`、`--audio-codec`、`--crf`、`--video-bitrate`、`--audio-bitrate` 和 `--pixel-format`。参数会写入 `settings.output`、操作计划、manifest 和 `outputs[]`；续跑会把编码设置纳入输入指纹。编码器缺失或容器组合不合法时在启动 FFmpeg 前返回结构化参数错误。

透明交付使用 `settings.output.video.pixel_format = "yuva420p"`，并要求 WebM 容器与 `libvpx-vp9`/`libvpx`。渲染器会把画布初始化为 RGBA 透明底，输出 WebM 的 `alpha_mode=1` 元数据；其他容器或编码器组合会在启动 FFmpeg 前拒绝。透明输出只保证视频 alpha 轨，音频仍按 WebM 的 Opus 约束编码。

HDR 输入到 SDR 渠道可以在 `settings.color` 中显式设置 `tone_map`，并补充 `input_transfer`、`input_primaries`、`input_matrix` 和 `input_range`。本地链路使用 `zscale` 转线性浮点、FFmpeg `tonemap` 执行 `linear`、`gamma`、`clip`、`reinhard`、`hable` 或 `mobius`，再转回 bt709；未声明 HDR 输入不会自动猜测，透明画布组合会输出明确的近似/不支持 warning。

## 5. 当前边界

色彩转换、HDR/10-bit 交付、平台专用安全区、硬件编码调度和逐平台码率建议仍属于后续档案版本；当前档案保证画布、宽高比、请求的基础音视频编码和可追溯 manifest，不宣称自动满足任意平台的完整审核规则。
