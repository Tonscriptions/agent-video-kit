## 3. 自然样例中的真实失败

仍使用前序同一段 4 秒、512×288、8 fps 自然双人场景，源摘要 `813bc758f73cdb49f2ec206dc5946497279a92f5f900efb042a733249d60c207`。**选中对象是男孩 2，女孩 1 应保留**；保留人物的腿不能直接标成移除残留。原始发布权利记录为 unverified，私有输入、局部图和衍生视频均留在忽略的本地运行目录；公开证据只保存摘要、结构与数值。

先在原始选择蒙版上核验 5 点：第 0 帧男孩躯干 selected、背景 clear；第 31 帧男孩头部与手腕 selected、女孩前臂 clear。后二者发现真实漏选/误选。追加第 31 帧对象 2 的框、头部/手腕正点和女孩前臂负点，原生 SAM2.1 Hiera Tiny CUDA 实跑一次，结果如下：

| 帧/像素（零基） | 断言 | 修正前 alpha | 修正后 alpha | 结论 |
|---|---|---|---|---|
| 31 / (41,100) | 男孩头部 selected | 255 | 255 | 两次通过 |
| 31 / (15,209) | 男孩手腕 selected | 0 | 0 | **两次失败**；正点不保证最终二值像素选中 |
| 31 / (64,90) | 女孩前臂 clear | 255 | 0 | 此点由失败变为通过 |

第 0 帧两个控制点两次均通过。独立 FFmpeg 解码复核了全部 32 帧和三处 alpha；修正只改变末帧，前面 31 帧不回改，RGB 分量改变为 0。完整末帧选区仍可能漏掉未检查的其他身体部位；5 点不是密集真值。当前仅能认定一个排除点改善，不能由通过点数推导完整分割或背景修复改善。

worker 状态峰值 288,917,816 bytes，Torch CUDA 峰值已分配 640,108,544 bytes；二者均不代表整个进程或系统峰值。worker 使用 `torch-cuda`、32 次状态更新、2 次提示事件、0 次 reset，规范化提示与模型/输出摘要见机器证据。模型沿用既有本地权重，无下载或云调用。

初始评估包装器将“修正应通过”设为预期，遇真实退出码 2 后以 1 终止；没有据此删除项目或重跑模型。后续从保留状态继续独立解码及 validate/policy/rights，保存两份失败报告。这个失败保留在 README V10/V14，不调整阈值或检查点使其通过。

## 4. 结论与继续验收

该入口为 Agent 提供可复核的范围检查和明确断言，未把检查自动接入现有渲染发布门禁，也不自动推断对象身份、运动补偿 IoU 或应用修复扩张。扩张后的有效蒙版须另行检查，避免侵入保留对象。`semantic_quality_accepted` 始终为 false。

自然选区完整性、漏选补全、保留对象误伤、真实人物移除纹理和时序仍未通过；#55/#56 保持原有降级状态。下一步应在明确目标身份后建立密集选区/多场景真值，再评估修正与修复，不用稀疏检查代替画质验收。所有原始剪映对标、开放素材/模板库、权利、性能和发行要求继续有效。
