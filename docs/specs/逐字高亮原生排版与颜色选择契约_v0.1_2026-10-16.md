## 1. 排版不随激活词改变

`subtitle.text` 是完整源文本，`word_timing` 只定义哪些字符范围在何时使用活动颜色。普通文字与活动文字分别绘制完整段落，字体、字号、换行、描边、阴影、盒子和位置完全相同；二值蒙版从两份完整画面选择像素。活动词不再以短字符串单独覆盖到已画好的整句上，避免重复抗锯齿、词宽度改变默认居中位置和两种排版引擎的 advance 差异。

显式换行与软换行保留源字符区间。重复词通过有序匹配或 `start_char` 定位；一个范围可以跨换行，拆为各行的颜色区域。换行作为布局分隔，各个完整行使用共享段落原点、行高和基线绘制，盒子只绘制一次；LF 本身不送去塑形，避免本机整段 drawtext 出现额外占位字形和宽度。空白与未标注的标点/词继续存在，不用删除普通文字来制造“高亮对齐”的通过结果。

`start_char` 从原始 `subtitle.text` 的第 0 个 Unicode 码点计数，不是 UTF-8 字节偏移、UTF-16 code unit 或显示字素序号；它不因软换行改变。范围边界仍须满足完整字素/塑形簇约束。

```json
{
  "text": "FEATURE  BENEFIT  FEATURE",
  "style": {"font_asset_id": "local_font", "fontsize": 28,
            "box": false, "active_color": "yellow", "expansion": "none"},
  "word_timing": [
    {"text": "FEATURE", "start_char": 0, "start": 0.1, "end": 0.8},
    {"text": "BENEFIT", "start_char": 9, "start": 0.8, "end": 1.5},
    {"text": "FEATURE", "start_char": 18, "start": 1.5, "end": 2.2}
  ]
}
```

## 2. 同一原生引擎的度量

字形绘制与选区坐标使用同一个本地 FFmpeg 二进制、同一字体文件和相同样式参数。度量阶段读取原生 `width64` 小数 advance，以及 drawtext 的段落宽高、行高、字形 ascent/descent、首行 ascent 和字体指标。每批最多 24 个短文本探针，16×16 单帧空画布，不生成媒体素材、不调用 Pillow 排版引擎、不请求网络。

度量缓存位于项目 `cache/text-metrics/`，键包含协议、FFmpeg/字体 SHA-256、字号、行距、tabsize、shaping 和全部查询文本。可重建，不是作者数据。缺少本地字体或原生度量格式不兼容会结构化失败，不能回退平均字宽后仍称为精确高亮。`max_width` 的**换行选择**仍使用既有可选 Pillow 机制；原生度量用于所选行内的颜色坐标，不能据此接受任意语言/字体的精确自动换行。行间颜色边界取上一行字形下沿与下一行上沿之间的空白中点，不使用基线中点，避免染到下一行顶端。

默认 `(w-text_w)/2` 与 `h-text_h-120` 使用完整段落指标。支持既有 left/right/center、top/bottom/middle、boxw/boxh 和 fix_bounds；空间表达式中的 `t` 仍服从[原作者字幕时钟](./嵌套字幕与文字动画时钟契约_v0.1_2026-10-16.md)。位置表达式需要无状态，不允许引用 x/y、rand/random、st/ld、print 或 metadata；含百分号的逐字文字使用 `expansion=none`。

原理可对照 [FFmpeg 官方 drawtext 源码 n7.1](https://github.com/FFmpeg/FFmpeg/blob/n7.1/libavfilter/vf_drawtext.c)。这是算法参考；运行时直接度量本机二进制，不用该旧源码推断本机版本的字宽。

## 3. 时间与栅格

`word_timing` 的秒数仍为字幕片段局部秒，显示区间为 `[start,end)`，净祖先倒放的半 tick 规则保持。每个词的原作者时间判断通过原生 drawbox enable 每帧计算一次，写入内部像素标记；后续颜色蒙版读取标记，避免对每个像素/通道重复计算复杂嵌套 Bezier 逆映射。像素标记只存在于临时蒙版，不出现在成片，也不写回项目。

固定尺寸内嵌字幕复用透明栅格与 source-over，独立标题复用现有 transform/keyframes/mask/blend。动态尺寸视频内嵌逐字高亮目前返回 `RENDER_FEATURE_UNSUPPORTED / subtitle_word_dynamic_raster`，保留整句、抑制高亮；需改为独立字幕轨道。不能忽略这个 warning 后宣称高亮已完成。

## 4. 可追溯性与拒绝边界

manifest 的 `subtitle_time_mapping.text_layout` 记录引擎 `drawtext-whole-paragraph-masked-highlight`、度量协议、缓存键、FFmpeg/字体摘要、查询数、段落指标、各行词范围、两次完整绘制和每帧时间判断方式。项目 assets/settings/sequences 和 Rights Ledger 保持不变；render 的正常 outputs/provenance 登记另计。

| 情况 | 行为 |
|---|---|
| 缺少字体 / 原生探针失败 / 不完整度量 | `SUBTITLE_WORD_FONT_REQUIRED`、`SUBTITLE_NATIVE_METRICS_FAILED` 或 `SUBTITLE_NATIVE_METRICS_UNAVAILABLE` |
| 拆开组合字符、emoji 字素 | `SUBTITLE_WORD_GRAPHEME_BOUNDARY`，在 render 规划阶段拒绝 |
| 西文词内部的连字/塑形簇边界 | `SUBTITLE_WORD_CLUSTER_LAYOUT_UNSUPPORTED`，需提供完整词范围 |
| 双向文字、方向控制符 | `SUBTITLE_WORD_BIDI_UNSUPPORTED`，整句字幕仍可另用普通路径 |
| 有状态/互相引用的位置表达式 | `SUBTITLE_WORD_POSITION_UNSUPPORTED` |
| 多行段落有状态/互相引用的位置 | `SUBTITLE_PARAGRAPH_POSITION_UNSUPPORTED` |
| 多行 boxw/boxh 小于完整段落 | `SUBTITLE_PARAGRAPH_BOX_CLIP_UNSUPPORTED`，尚未实现该组合的显式裁切 |
| 范围/文本/度量预算超限 | `SUBTITLE_WORD_LAYOUT_BUDGET`；最多 128 范围、16384 源字符、512 查询、131072 查询字符总量；单行度量宽度上限 500000 像素 |
| 动态尺寸内嵌 | 显式 warning，整句保留，高亮不执行 |
| 逐字与文字动画组合 | `subtitle_word_animation` 近似警告；高亮保留，不能接受整套组合动画 |
| 多行打字机 | `subtitle_multiline_typewriter` 近似警告，尚未共享段落排版 |
| 负行距 | `subtitle_word_overlapping_lines`，交叠笔画的独立颜色未接受 |

当前 compose 仍检查源匹配和时间合法性；上述字形/引擎限制在 render 规划阶段检查。拒绝不生成成片，不修改已存在的作者时间线或权利账本。

## 5. 验收口径

白色普通段落与黄色激活段落具有相同的 R/G 通道。通过真实 CLI 以 `libx264 / crf=0 / yuv444p` 编码，再解码全帧比较 R/G；≤3 是 RGB/YUV 往返容差，能检测字形位移、重复描画和不应改变的阴影/背景。另检查蓝色变化是否只落在相应词、同色高亮是否逐字节一致、活动透明颜色能否替换原不透明词。普通字幕对照与活动字幕同源同配置，不能用图片拼接冒充产品输出。

该测试不直接接受任意 fontcolor alpha 的数值语义、非白/黄颜色的色彩精度、HDR/线性光、紧密交叠字形、完整双向与字体回退、定格/VFR、4K 性能或剪映整体等价。连续播放、声音听审、抽帧目检、逐帧自动检查分别记录。公开原片、许可、编码参数和 SHA-256 由[复现生成器](../../scripts/smoke_word_layout.py)记录。
