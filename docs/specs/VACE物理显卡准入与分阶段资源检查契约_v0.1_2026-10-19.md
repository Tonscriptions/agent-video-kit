# VACE 物理显卡准入与分阶段资源检查契约

V60 产品增量。依据 V59 实测中 PyTorch 可用显存与整卡快照不一致的问题，为已注册本地 VACE 补充真实物理设备准入。ROSE 维持原研究结果；本契约不改变自然画质门槛，不将资源检查计为模型质量通过。

| 编号 | 要求与验收证据 |
|---|---|
| G60-01 | 资源探测与真模型链路只使用原生 Python/Torch 与本地 NVIDIA 驱动工具；不下载、不安装、不调度虚拟化、浏览器、GUI 或其它用户进程。完整回归另含既有 HTML 动效的原生无头浏览器测试，其页面和自建浏览器进程必须按生命周期清理 |
| G60-02 | 用 Torch 逻辑 CUDA 0 的完整 GPU UUID 查询同一物理设备；不能按整卡列表顺序、名称、CUDA_VISIBLE_DEVICES 字符串或显存大小猜测设备；缺 UUID、MIG、无效/多行/错设备/非整数结果明确拒绝 |
| G60-03 | 单次采样分别保存 Torch free/total 与物理 free/total；以两个 free 的较小值判断预算。记录本地命令、查询时间、阶段与 required bytes；两次 API 调用不是原子快照，不保证同时性 |
| G60-04 | 文本加载前要求显式 GPU 权重预算＋768 MiB 余量，必须先检查再导入大模型组件、创建 tokenizer 或加载 checkpoint；不满足时没有权重加载、模型前向或半注册输出 |
| G60-05 | 文本编码器释放后，按实际 CPU 视频模型参数/缓冲区字节与提示词嵌入字节，加 768 MiB 检查，再执行 GPU 转移；每个非空窗口前再检查 768 MiB 可用余量。余量是准入下限，不是激活峰值估计或 OOM 保证 |
| G60-06 | 成功响应保存两个加载阶段的完整检查、窗口检查数量与最小值/首末检查；父进程验证 UUID、数值、阶段、预算和调用数，拒绝漏报、错设备、低于预算或虚假预约/保证标记。摘要不冒充每个中间窗口的独立原始快照 |
| G60-07 | 失败响应保留结构化当前采样/错误码；已有管道取消、超时、诊断、事务回滚继续生效。查询失败不自动换 CPU、其它设备、其它引擎或线上服务 |
| G60-08 | 新辅助模块加入适配器实现摘要闭包；旧适配器需要显式重新登记，不修改保存的历史摘要。无选区时继续绕过模型和驱动工具 |
| G60-09 | 定向测试覆盖 UUID 映射、两种 free 各自不足、边界、工具缺失/超时/错结果、模型加载前拒绝、阶段汇总及父进程拒绝/回滚。用真实本地 CUDA/驱动完成一次采样、有限小分配和预算拒绝；协议夹具与真实模型质量分别标注 |
| G60-10 | 原生离线包应包含新模块并核对安装字节、实际入口与准入行为；完整产品回归必须按本轮冻结输入运行。README、Skill、进度、机器证据与实际失败同步更新 |
| G60-11 | 使用已有固定 VACE 权重，重跑原有 8 帧受控夹具、30 步/5 帧窗口/2 帧重叠的正式 CLI 交付；核对所有阶段的物理准入元数据、Alpha/区外 RGB、音频及编码。公开原创输入/实际结果/GIF，原生成器、逐文件 SHA 和原命令可追溯。仍单列 ≥30 dB 画质门槛及商业权利阻断，不增加自然来源场景，也不据资源通过关闭自然修复质量差异 |
| G60-12 | 首轮真实执行在第一个视频窗口前因 Torch free 低于 768 MiB 拒绝，保留原响应、日志和 188 个原版输入字节。复测补充当前 worker 的 allocator 证据：确认设备身份后同步自身 CUDA 流，记录已分配/已保留字节，释放自身未占用缓存，再重新采样同一预算。有效张量的已分配字节必须前后相同，已保留字节不得增加；记录释放量，父进程验证。不得释放其它进程或有效模型张量，不降低 768 MiB 门槛、分辨率或步数，不把清缓存当成显存预约或 OOM 保证。使用原生小额有效分配和真实模型重新核验 |

本轮不宣称全局显存预约、跨应用互斥、独占设备、全部引擎覆盖、自然修复画质或剪映完全等价。其它进程可在检查之后分配显存；真正运行中的 CUDA OOM 仍须按原失败管道处理，不能静默重试或降低质量。
