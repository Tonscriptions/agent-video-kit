## 1. 状态枚举

| 状态 | 含义 |
|---|---|
| `proposed` | 产品目标或研究建议，尚未形成契约 |
| `contracted` | 已写入 schema/CLI/模块契约，但没有实现证据 |
| `implemented` | 代码路径存在，尚未完成完整回归 |
| `verified` | 固定版本、固定样例和质量门禁已通过 |
| `degraded` | 只能近似、固化或部分支持，差异已记录 |
| `blocked` | 依赖、许可证、平台或安全门禁阻断 |
| `unsupported` | 当前路线明确不支持，必须有替代或拒绝策略 |

## 3. 单项验收字段

后续应将此矩阵扩展为 CSV/数据库，至少包含：

`capability_id`、`matrix_row`、`requirement_id`、`priority`、`status`、`owner_module`、`backend`、`schema_path`、`cli_command`、`fixture_id`、`expected_quality`、`license_gate`、`evidence_path`、`last_verified_at`、`known_limits`。

例如“位置/缩放/旋转关键帧”应登记为：P0、项目 schema 的 `keyframes[]`、`timeline compose`、fixture `P0-003`、状态初始为 `contracted`，只有渲染样例通过后才改为 `verified`。

## 4. 状态推进规则

1. 新能力先进入 `proposed`，写清用户价值、输入输出、风险和许可证。
2. schema、CLI 或模块契约完成后进入 `contracted`。
3. 有代码和单元/契约测试后进入 `implemented`，但此状态不等于视觉质量通过。
4. 固定版本、固定样例、媒体质量和权利门禁全部通过后进入 `verified`。
5. 近似、固化、外部模型或版本限制必须进入 `degraded`，并关联转换报告。
6. 许可证、平台、性能或安全阻断进入 `blocked`；明确不做的能力进入 `unsupported`。

## 5. 发布门禁

发布候选必须生成覆盖摘要：P0 `verified` 数量、P0 `implemented` 但未验证数量、P1/P2 未完成数量、`degraded/blocked/unsupported` 清单，以及每项的替代方案和风险。没有摘要就不能把“达到剪映水准”写成总体结论。
