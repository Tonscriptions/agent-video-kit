# 透明视频交付与音画端点契约

本契约先于 V52 产品修改声明。目标是修复 V51 的两项实际交付失败，同时保持真实错位检查和已有作者时钟；不以放宽原 Alpha 门槛或全局增加音画容差使结果通过。上轮记录和媒体保持原样。

原失败证据：[VP9 透明交付](../assets/nested-freeze-v51-final-20261018/NF07-delivery-verification.json)、[10 fps /4.01 秒 MP4](../validation/evidence/nested-freeze-fractional-delivery-20261018/verification.json)。V51 的原生无损图不是正式 WebM 编码验收。

## 范围和编号要求

| 编号 | 必须实现的行为 | 验证证据与门槛 |
|---|---|---|
| DP01 | 最终 RGBA 的 Alpha 与 RGB→YUV 色彩转换分离；原 8 位覆盖率直接合回 yuva420p | 全 0–255 级渐变、空间变化与逐帧变化的实际 VP9 输出；逐像素 Alpha 最大差 **0** |
| DP02 | VP9 无码率覆盖且 CRF=0 明确使用无损模式；有损编码不得标为像素精确 | 检查原生计划、编码后全部 Alpha、元数据与有损范围说明；RGB 仍受 YUV 4:2:0 影响，不宣称 RGBA 无损 |
| DP03 | VP8 透明输出禁用不兼容的自动 alt-ref；VP8 不承诺逐像素无损 | 实际短片编码/显式 alpha 解码，透明与不透明检查；保留量化误差 |
| DP04 | 透明 VP8/VP9 本地素材入轨时选用能读 Alpha 的 libvpx 解码器，不因 ffprobe 的 yuv420p 报告丢覆盖率 | 将实际 WebM 重新登记并作为视频源；与原独立 Alpha 逐像素比较；在深浅背景检查真实覆盖，记录所选 decoder |
| DP05 | 无透明输出保持现有编码、原片 RGB/PCM 和作者工程语义；不写中间渲染片 | 已有不透明片的固定 V51 对照，作者工程/包交换和原生安装复验 |
| DP06 | 视频端点遵循 `[0,D)` 内全部显示帧；`Nv=ceil(D·F)`，视频末端 `Nv/F` | 10、1、30000/1001 fps，整帧、恰好一 tick 超出、非整帧时长；实际帧数与 PTS，原 float 边界不得多算一帧 |
| DP07 | 音频保持作者时长，48 kHz 原生图输出 `Na=ceil(D·48000)`；不为了对齐视频补长或裁短音频 | 实际 PCM 逐样本/长度核对；AAC/Opus 单独记录编码填充，不冒充 PCM 相等 |
| DP08 | 质量检查分别记录两个流的开始、时长、末端和测量来源，读取 Matroska 的流 DURATION 标签 | 实际 MKV/WebM 与构造缺失/损坏标签；容器总时长不能替代未知音频时长 |
| DP09 | 已知作者 D 时只扣除可推导的视频末帧/音频样本量化差；原始差值仍保留 | 10 fps /4.01 秒 MP4 在原 80 ms 上限通过，原始 90 ms 仍出现在报告，解释的量化尾差与残差分列 |
| DP10 | 真实开始偏移、提前结束、额外延后、等长但错位的音频，以及共同整体偏移均不得被量化修正隐藏 | 独立构造正负偏移与短/长音轨；保持 80 ms 约束；无作者 D 时维持原始检查 |
| DP11 | 使用原质量 gate 的 CLI render、quality check 和 golden 均采用同一端点语义 | 实际 CLI 通过与拒绝、golden 捕获/核验；不能只让单元 mock 通过 |
| DP12 | 项目包导出/导入及原生离线安装能重建相同 Alpha 和端点；默认不开网络 | 固定 wheel、实际 `-I -S` 安装入口、媒体逐帧/逐样本；无 Docker/WSL/venv、无新模型或云服务 |

## 质量计算

作者 D 由工程整数 ticks 表示，显示帧率和音频采样率均保留有理数推导。质量接口接收秒数时，只有浮点 ULP 范围内的作者 tick 表示误差才可恢复为对应整数 tick；真实一 tick 越界不能吞掉。

已知 D：预期视频时长为 `ceil(D·F)/F`，预期音频时长为 `ceil(D·S)/S`。质量报告同时保留原始时长差、开始差、末端差、预期量化差和剩余误差，并分别检查实际末端偏离作者预期的程度。开始时间默认为输出时间轴 0；视频与音频共同偏移也属于交付错误。默认上限继续为 80 ms，可由调用方设定更严格值。未知流时长必须说明无法验证，不伪造为容器总时长。

这只验证结构时钟，不证明内容口型、语义同步、自然变速音质、连续播放、听感、VFR/HDR、全媒体格式、跨硬件一致性或完整剪映等价。透明精度仅接受当前已验证的 VP9 无损 YUV/Alpha 路径；有损 VP8/VP9、任意缩放/旋转/重建核及 RGB 色彩保真分别验证。

`render` 自带所选序列的作者 D。独立 `quality check` / `quality golden --mode capture` 应明确传 `--sequence-id` 绑定作者时长，之后 golden verify 可沿用所存序列。省略序列时保留未知作者 D 的原始严格检查，不从容器总时长猜测豁免。这是既有 CLI 的显式绑定方式；不为通过本轮测试更改默认的未知时长语义。
