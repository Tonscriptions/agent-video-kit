# 广告计划与时间线应用契约 v0.1

## 目标

`ad plan` 根据本地 brief 和可选的本地分析报告生成可审计的阶段、时间标记和 `timeline_operations`。`ad apply` 将已生成的计划写入 Agent Project 序列，形成可重放的“规划→时间线”闭环。两条命令都只读取本地 JSON，不调用网络、模型服务或剪映运行时。

## 输入

`ad apply --input` 可以接收 `ad plan` 生成的报告（顶层含 `plan`）或直接接收 plan 对象。必须包含非空 `timeline_operations`；当前应用器只接受 `add_marker`，每个操作需要非空 `id`、非负 `at_tick` 和可选 `label`。如果计划包含 `duration_tick`，默认同步设置目标序列时长；已有片段末尾超过计划时长时拒绝写入，使用 `--preserve-duration` 可跳过时长更新。

## 写入与重放

- 命令受项目原生写锁和全局幂等键框架保护。
- 写入前创建 `before-ad-plan-apply` 快照，验证序列、轨道、时间标记和项目引用后才保存。
- 已存在同 ID 标记默认返回 `ARGUMENT_INVALID`，防止 Agent 无意中重复应用；需要明确使用 `--replace-markers` 才替换。
- `--dry-run` 返回计划版本、序列 ID 和待应用操作，不写项目、不生成快照。
- 成功操作写入 `provenance.change_log` 和 `operations/*.json`，报告包含应用列表、验证结果和恢复快照。

## 当前边界

当前版本应用阶段标记和序列时长，不自动选择素材、不生成字幕/配音、不把阶段消息变成文字片段，也不替换已有片段内容。素材选择与模板槽位由 `library` 和 `template` 契约分别负责；后续可在保留显式操作和权利门禁的前提下增加本地候选绑定与阶段级模板操作。
