本轮继续补齐 OpenFilm O02 研究指出的专业时间线缺口。以下六项为本项目 Python 原生新实现，复用现有关联/碰撞规则与完整作者输出窗口，不是 `timeline-edit.ts` 整体移植。产品仍使用本地 FFmpeg；没有引入 GUI、浏览器、云端接口或新的模型推理。

## 1. 时间语义

所有时间为本项目 timebase 的整数 tick，不能传布尔、小数、负落点或字符串。区间为半开 `[at_tick, at_tick + duration_tick)`。现有素材的完整作者 source、倒放、曲线、定格、关键帧、片段效果与片段音频保持原值；需要裁切时，只改变 `presentation_window` 的可见区间及序列落点。轨道和根序列处理仍在新时间线上执行，不能以整片混音切片替代复杂总线的重新处理。

新增片段必须引用已登记本地资产/序列/生成器；接口不下载、不自动导入素材，也不自动验证新素材发布权利。新片段可以带此前完整输出窗口，但不能借窗口绕过跟踪、转场、R3、栅格与其他既有门禁。

## 2. 编号操作表

| 编号 | action | 结果 | 保持的边界 |
|---|---|---|---|
| E01 | `insert` | 在落点插入一组新片段；跨落点旧片段拆为两块，右侧移动组时长 | 输入片段的 `timeline_start_tick` 为组内相对位置；显式组内空白、尾部空白保留；序列变为 `max(旧时长, 落点)+组时长` |
| E02 | `overwrite` | 擦除目标范围后放入新组；范围两边旧片段保留原完整作者输出 | 后续内容不波纹移动；序列为 `max(旧时长, 范围结尾)`；组内空洞也属于覆盖范围 |
| E03 | `lift` | 选轨范围删除，留下空白 | 其余片段位置和序列时长不变；彻底移除的片段在计划中明确记录 |
| E04 | `extract` | 选轨范围删除，并将所选范围之后内容左移范围时长 | 作用范围闭包后只执行一次公共位移；根时长至少旧时长减范围、至少一 tick，并覆盖所有保留片段的自然结尾，避免截断未选背景床 |
| E05 | `roll` | 同轨相邻两片段的剪口移动；正 delta 延长左片段、裁右片段头 | 左起点、右结尾和序列时长保持；联动音轨需要唯一连续左右对；仅使用此前保留的完整作者输出句柄 |
| E06 | `slide` | 中片段完整内容与时长保持、位置移动；左邻尾部和右邻头部随剪口调整 | 三元组连续且不共享成员；左右外边界和序列时长保持；这不是移动片段内部源内容的 `slip` |

`lift/extract` 范围必须完整位于现有序列内，越界拒绝，不自动截断。`insert/overwrite` 允许落在结尾之后，并保留显式空白。零 `roll/slide` 保持项目数据不变，但仍核对目标与连续关系；非零操作不得产生零长片段或负时间。

既有 `compose.slip_clip` 是直接媒体资产的源入/出点整体偏移，`compose.slide_clip` 是单片段序列落点平移；不能把它们当作本轮完整关联规划或三元组滑动。E06 会同时改变两侧邻居可见句柄；复杂关联 slip 的统一预览/锁/引用规划不在本轮六 action 中。

## 3. CLI 和请求

以下命令从仓库根目录执行，仅请求文件内容决定操作：

```powershell
C:\Python313\python.exe -B -m ai_ad_editor timeline edit --project <本地项目> --input <request.json> --dry-run
C:\Python313\python.exe -B -m ai_ad_editor timeline edit --project <本地项目> --input <request.json> --expected-project-sha256 <计划摘要> --idempotency-key <本次编辑键>
```

源目录启动需要已有 `product/src` 的 Python 路径配置；离线安装命令见 [CLI 契约](AgentCLI契约_v0.1_2026-10-13.md)。`base_project_sha256` 是现有规范化项目指纹，不是文件原字节摘要。

插入与覆盖（将 action 改成 `overwrite`）：

```json
{
  "action": "insert",
  "at_tick": 90000,
  "duration_tick": 90000,
  "items": [
    {
      "track_id": "track_video_1",
      "clip": {
        "id": "new_picture",
        "asset_id": "product_video",
        "timeline_start_tick": 0,
        "duration_tick": 90000,
        "source_in_tick": 540000,
        "source_out_tick": 630000,
        "link_id": "new_av"
      }
    }
  ],
  "options": {"sync": true, "linked": true, "linkage": false}
}
```

`items` 数量为 1..256，每项只接受 `track_id/clip`。`clip` 为完整原生片段；必须显式提供 ID、相对落点、时长、源入点/出点。省略组 `duration_tick` 时取所有新片段的最大相对结尾；显式值不能短于该结尾。新片段 ID 在拆旧片段、生成 ID 前全局预留；资产、序列、轨道、片段、标记、源转场 ID，以及本轮将被移除的旧 ID，均不能冲突。同批可共享新 link ID；新 link ID 不能隐式并入项目已有组。`link_id=null` 允许，其他非空值必须符合 ID 格式。

留空删除与波纹提取（把 action 改成 `extract`）：

```json
{"action":"lift","at_tick":90000,"duration_tick":90000,"track_ids":["track_video_1","track_audio_1"],"options":{"linked":true}}
```

滚动剪口和滑动片段：

```json
{"action":"roll","left_clip_id":"left_video","right_clip_id":"right_video","delta_tick":45000,"options":{"linked":true}}
```

```json
{"action":"slide","clip_id":"middle_video","delta_tick":45000,"options":{"linked":true,"linkage":true}}
```

批量事务入口复用既有接口；后续操作失败时，前面的范围编辑不写入项目：

```json
{"operations":[{"op":"linked_edit","edit":{"action":"extract","at_tick":90000,"duration_tick":90000,"track_ids":["track_video_1"]}}]}
```

未知 action/字段、错误类型和多余 options 明确拒绝。普通 `timeline edit` 先验证原工程，再规划、验证候选；正式执行复用快照、变更日志和幂等事务。干跑不改 `project.json`；旧摘要拒绝，同键重试返回原结果。规划器本身只编辑副本，不调用媒体进程。

## 4. 联动、锁和冲突

| 编号 | 约束 | 具体行为 |
|---|---|---|
| L01 | 默认开关 | 沿用 `sequence.editing`；未配置时 `linked=true`、`sync=false`、`linkage=false`，主轨为最低 order 的 video 轨 |
| L02 | 直接目标轨 | 即使为空，锁定的直接目标轨也拒绝；`sync_lock=false` 不排除用户直接指定的轨 |
| L03 | insert/extract 的 sync | 加入未锁定且 `sync_lock!=false` 的其他轨；跨落点片段也参与拆分/删除；覆盖和 lift 不因 sync 擦除全部轨 |
| L04 | linked | 按已有 link ID 扩展成员；锁定的关联成员拒绝整个操作。范围编辑与主轨骑乘扩展求闭包，防止从音轨间接触达主轨后漏掉骑乘内容 |
| L05 | linkage | 对范围编辑扩展所选主轨片段的骑乘内容；跨多个主轨剪口的背景床不作为单片段骑乘。slide 额外移动中片段的完整骑乘组；roll 不移动骑乘片段的整体位置 |
| L06 | roll 的 sync | 只加入在主剪口具有唯一、精确连续左右片段的轨，再扩关联组；不猜测没有对应剪口的音频床 |
| L07 | roll 的关联几何 | 每轨必须唯一左/右成员且连续。此前 split 使两侧共享 link ID 时按主剪口筛选左右；不同组的唯一关联音频对可有自身剪口偏移，保持自己的连续性 |
| L08 | slide 的关联几何 | 每个关联中片段必须有唯一连续两邻居；所有三元组互不共享片段，邻居关联组必须完整。sync 只补相同中片段起止的唯一候选；不猜测不完整关联 |
| L09 | 碰撞 | 沿用既有辅助新轨规则；保留原有重叠。新增输入同轨重叠需 `overlap_policy=allow`，否则拒绝；主轨不产生未声明新碰撞 |
| L10 | 轨道语义 | 需要换轨但轨道效果/音频闪避总线无法保真时拒绝；新轨完整元数据写入计划；锁轨最终做数据不变校验 |
| L11 | 字幕 | 完整移动 sequence-time 文件字幕时修正 `asset_time_offset_tick`；已有完整作者窗口继续使用作者字幕钟，避免重复偏移。内嵌字幕保留原作者字段 |
| L12 | 标记与引用 | 标记保持绝对 tick。完整源转场组可整体移动；所有视频/音频端点一起删除才移除声明。只删部分端点、拆开剪口或裁端点拒绝。跟踪源/目标内部裁切拒绝，删除后仍被引用拒绝；完整换轨时更新未锁定目标的 `source_track_id` |

多轨联动是明确范围的规则，不等于完整剪映磁吸。计划必须先检查 `selected_clip_ids`、`incoming_clip_ids`、`changes`、`cut_pairs`、新增轨、重绑定/字幕偏移、移除转场及前后序列时长。`changes` 包含创建、修改、移除全部差异；不存在的一侧为 null。

## 5. 作者句柄与拒绝边界

`roll/slide` 的可延长范围为 `presentation_window.authored_duration_tick` 内此前保留的输出，而不是素材文件中任意未编辑范围。缺少句柄返回 `EDIT_RANGE_HANDLE_SHORTFALL`；不补帧、不延长音频、不按平均变速比反算 source。向完整作者源范围外延伸、复杂关联 `slip` 的统一规划、全磁吸、自动附着策略和真实转场端点重规划仍需后续实现。

| 编号 | 代表错误 | 含义 |
|---|---|---|
| G01 | `EDIT_RANGE_REQUEST_INVALID` | tick、输入/标识符/开关/字段不合法；未知非范围 action 沿用 `EDIT_REQUEST_INVALID` |
| G02 | `EDIT_RANGE_ID_CONFLICT` / `EDIT_RANGE_LINK_CONFLICT` | 全局 ID 重复或新输入隐式并入既有组 |
| G03 | `EDIT_TRACK_LOCKED` | 直接/关联编辑涉及锁轨 |
| G04 | `EDIT_RANGE_OUTSIDE_SEQUENCE` | lift/extract 超出现有序列 |
| G05 | `EDIT_RANGE_CUT_INVALID` / `EDIT_RANGE_LINK_GEOMETRY` | 连续左右对/三元组或关联几何不成立 |
| G06 | `EDIT_RANGE_EMPTY_SIDE` / `EDIT_RANGE_HANDLE_SHORTFALL` | 邻居变空、负落点或完整作者输出句柄不足 |
| G07 | `EDIT_RANGE_BINDING_UNSUPPORTED` / `EDIT_RANGE_TRANSITION_UNSUPPORTED` | 需先解除或移除受影响的跟踪/源转场，或改为编辑完整容器 |
| G08 | `EDIT_PROJECT_CHANGED` | 候选基于过期工程，须重新规划 |

窗口仍受现有 64 个直接窗口、16 层窗口嵌套、完整投影/工作栅格预算、Alpha 与格式转换边界约束。完整作者图可能对每个可见碎片重复计算；栅格配额不是进程 RSS 上限。`items<=256` 不是承诺能同时渲染 256 个窗口。首轮实际证据仅 90k tick / 10fps 的短 240×136 合成素材；非整数 FPS、复杂总线、长片内存、自然广告画质和听感不可由这些样例推定。

实际权利台账与 `--strict-rights` / `render --publish` 继续生效；新能力不授予素材、字体、模型、模板的使用权。输出可移入既有片段组库，但跨上下文与外部 NLE 不自动获得完整作者窗口语义。
