真实测试生成 2 秒、25 fps 的 50 张独立纯色帧和确定性双声道音频。短机位只保留 8 帧，音频保持 2 秒；另一个机位将这 8 帧的 PTS 推迟 1 秒。音频同步估计仍沿用原有有界 50 Hz 包络，本组音频起点为 0；没有验收非零音频流起点或设备漂移。

应用 `trim` 后，每一帧完整无损 RGBA 与独立原色卡/黑背景序列比较；显式主音轨的全部 float32 PCM 与生成样本比较。尾部样例为 8 彩色帧＋42 背景帧；延迟样例为 25 背景帧＋8 彩色帧＋17 背景帧。两者作者时长仍为 2 秒，音频仍为显式主音轨。该原专项阶段没有制作有损观看副本；本次新媒体已补 MP4/GIF。编码 MP4/AAC 不声明完整字节一致。

`dry-run` 缓存缺失时只探测、不写缓存；命中时核验既有帧索引并报告 0 次源帧扫描。仍会读取实际源/运行时 SHA，不能称为 0 I/O 或 0 解码。损坏索引在读取后明确拒绝并保留，工程、报告、快照和所有已存在文件字节不变。原生帧索引的条目/帧数/时间预算以及完整源扫描成本沿用已有实现。

已修正仅音频分析的过度拒绝：有效音频偏移保留，视频覆盖以 unknown 状态和明确诊断报告；请求生成该机位切换段时仍拒绝。原两项控制一失败/一通过（2.355 秒），同一断言修复后两项通过（2.459 秒），再执行当前 104 方法。这两项使用真实本地音频和模拟的视频 EOF 未知状态，不能写成未知末帧封装文件的真实成片验收。源 SHA 变化、损坏索引等完整性错误不会转换成仅分析成功。旧 0.1/0.2 函数输入只有容器时长时会明确警告；新 CLI 自己生成 0.3 的原生覆盖证据，不静默降级。

没有自然多机位、HDR、长片吞吐、总 RSS、设备时钟漂移、非零音频流起点、连续播放、听审或完整剪映效果等价验收。没有 Docker、WSL、容器或虚拟环境；没有调用远程模型。专项临时素材在各测试自有目录内生成和回收；本次另行生成真实公开样例，并记录原生/安装输出的全部 SHA。
