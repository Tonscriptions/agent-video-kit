# 本地音频提取与派生资产契约 v0.1

| 项目 | 内容 |
|---|---|
| 文档编号 | SPEC-AUDIO-EXTRACT-001 |
| 版本 | 0.1.0（实现版本 `audio_extract_version=0.1.0`） |
| 日期 | 2026-10-15 |
| 状态 | 有效 |
| 运行边界 | 原生 Windows、Python、FFmpeg；网络关闭 |
| 关联命令 | `audio extract` |

## 1. 目标

`audio extract` 把本地视频或音频资产的第一条音频流提取为项目内无损 PCM WAV，登记为新的 `audio` 派生资产，并可选写入项目音频轨道。它关闭“只能在渲染时隐式使用视频原声、没有可复用原声资产”的基础缺口，为后续人声/背景声分离、替换原声和混音提供稳定输入。

该命令只使用本地 FFmpeg，不访问网络、不下载模型、不调用剪映运行时。它不把通道抽取或频段滤波描述为 AI 人声分离；真正的源分离需要另行登记并验证离线模型适配器。

## 2. 输入与命令

```powershell
python -X utf8 -m ai_ad_editor audio extract `
  --project .\work\demo `
  --asset-id camera_source `
  --derived-asset-id camera_audio `
  --track-id track_audio_1 `
  --apply
```

- `--asset-id` 和 `--input` 二选一；资产路径必须解析到本地文件并含音频流；
- 默认输出 `assets/derived/audio_<derived_asset_id>.wav`，也可用项目内 `--output` 指定；
- `--sample-rate` 只接受 8/16/22.05/24/32/44.1/48/96 kHz；`--channels` 只接受 1 或 2；
- 只分析并返回计划时使用 `--dry-run`，不创建 WAV、项目资产、快照或操作记录；
- 指定 `--apply --track-id` 时，在目标 audio 轨道追加直接媒体片段；`--replace-track` 才会清空该轨道已有片段；
- 输出固定为 16-bit PCM WAV，避免派生资产再次经过有损编码。

## 3. 报告与权利链

正式执行创建 `before-audio-extract` 快照，报告写入 `validation/audio_extract_<operation_id>.json`，并记录：

| 字段 | 语义 |
|---|---|
| `extraction.engine` | `ffmpeg-local-audio-extract-v1` |
| `source_sha256` / `output_sha256` | 输入与派生 WAV 的内容哈希 |
| `input_probe` / `output_probe` | 本地 FFprobe 流、时长、采样率和通道证据 |
| `asset.kind` | 固定为 `audio`，URI 位于项目内 |
| `rights.derived_from` | 从项目源资产继承时指向父 Rights Ledger 资产 |
| `generated_clip` | 使用 `--apply` 时的时间线片段与项目时基 tick |
| `validation` | 应用后结构、时长、引用和权利校验结果 |

源资产存在 Rights Ledger 记录时，派生记录继承许可证、用途、限制、验证状态和父依赖；直接 `--input` 使用显式本地来源和许可证参数。报告、provenance、operation record 与项目保存必须指向同一 operation ID。

## 4. 失败码与边界

- `AUDIO_STREAM_MISSING`：输入没有可读取的音频流；
- `AUDIO_EXTRACT_FAILED`：本地 FFmpeg 解码或 PCM 写出失败；
- `AUDIO_EXTRACT_INVALID`：输出没有可读取的音频流；
- `RIGHTS_RECORD_MISSING`：从项目资产派生但父权利记录缺失；
- `AUDIO_EXTRACT_APPLY_INVALID`：派生资产或时间线写入后项目校验失败；
- 输出路径越出项目根目录、覆盖已有文件、轨道类型错误或时间线起点为负数时，在写入前结构化拒绝。

## 5. Agent 交付门禁

1. 先执行 `--dry-run`，检查源 SHA-256、音频流、输出路径、采样率和通道；
2. 正式执行后检查 `before-audio-extract` 快照、报告、Rights Ledger `derived_from` 和 operation record；
3. 写入时间线后运行 `validate --project`，渲染后使用 `quality check --require-audio` 检查音频流、时长和音画差；
4. 将派生 WAV 交给 `audio` 轨道或后续离线音频处理；不要把该命令的结果宣称为人声/伴奏 AI 分离。
