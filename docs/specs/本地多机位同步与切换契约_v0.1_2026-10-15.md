# 本地多机位同步与切换契约 v0.1

| 项目 | 内容 |
|---|---|
| 文档编号 | SPEC-MULTICAM-001 |
| 版本 | 0.1.0（实现版本 `multicam_sync_version=0.1.0`） |
| 日期 | 2026-10-15 |
| 状态 | 有效 |
| 运行边界 | 原生 Windows、Python、FFmpeg、NumPy；网络关闭 |
| 关联命令 | `media multicam` |

## 1. 目标

`media multicam` 为 Agent 提供本地多机位的第一层产品化内核：从两个或以上项目视频资产的音频流提取有限时长 PCM，构造低采样率能量特征，用有界归一化互相关估计相对偏移，并把偏移用于显式的切换计划。它可以解决拍板声、对白或同步音乐在各机位之间的时间对齐问题，不能代替视觉导演、人物识别、镜头审美或说话人识别。

## 2. 输入与命令

```powershell
python -X utf8 -m ai_ad_editor media multicam `
  --project .\work\demo `
  --source-asset-id camera_wide `
  --source-asset-id camera_close `
  --reference-asset-id camera_wide `
  --sample-rate 8000 `
  --analysis-seconds 120 `
  --max-offset-seconds 30 `
  --switch-seconds 4 `
  --track-id track_video_1 `
  --dry-run
```

每个 `source-asset-id` 必须指向项目内包含视频和音频流的本地 video 资产。`--reference-asset-id` 默认使用第一个机位。同步分析不读取网络 URL、不下载模型，项目内相对路径由资产记录解析。

切换计划有两种形式：

- `--switch-seconds N` 按固定时长循环使用源机位；
- `--switch-plan plan.json` 使用项目内的本地 JSON，内容可以是数组，也可以是 `{ "segments": [...] }`，每个段包含 `start_seconds`、`end_seconds` 和 `camera_asset_id`，也可以用 `camera_index` 指向源数组。

`--switch-seconds` 与 `--switch-plan` 互斥。只做同步报告时可以省略二者；正式 `--apply` 必须提供其中一个和 `--track-id`。

## 3. 分析与报告

报告的 `sync` 包含：

| 字段 | 语义 |
|---|---|
| `engine` | 固定为 `ffmpeg-local-audio-envelope-xcorr-v1` |
| `reference_asset_id` | 偏移计算的参考机位 |
| `offsets[].relative_delay_seconds` | 候选机位的匹配事件相对参考机位延迟；正数表示候选事件更晚 |
| `offsets[].correction_seconds` | 写入时间线时的建议校正量，为相对延迟的负值 |
| `offsets[].score` | 有界重叠区间的归一化相关性；低分会产生 `MULTICAM_LOW_CONFIDENCE` |
| `offsets[].overlap_seconds` | 偏移估计实际使用的重叠时长 |
| `offsets[].evidence` | 本地路径、媒体 SHA-256、原始时长、采样率和特征点数 |

默认只分析每个文件的前 120 秒，`analysis_seconds` 最大 600 秒；`max_offset_seconds` 最大 300 秒。较短分析窗口或周期性音乐可能产生多个相似峰，Agent 必须检查 score、波形和报告 warning。

## 4. 应用语义

应用前命令会读取并校验目标视频轨道的现有片段重叠。每个切换段生成一个直接媒体片段：

- `timeline_start_tick` 和 `duration_tick` 使用项目时基；
- `source_in_tick/source_out_tick` 根据相对音频延迟映射到源素材；
- 候选源范围不足时使用小于 1 的 `speed` 填满时间线并返回 `MULTICAM_SOURCE_SLOWED`；
- `--replace-track` 才允许清空目标视频轨道，默认重叠返回 `MULTICAM_TRACK_OVERLAP`；
- 正式写回前创建 `before-multicam` 快照，写入报告、provenance、操作记录并通过项目校验；
- 切换计划是确定性执行输入，不会根据画面内容自动选择镜头。

没有可用的音频流、音频特征过短或特征平坦时分别返回 `MULTICAM_AUDIO_MISSING`、`MULTICAM_AUDIO_SIGNAL_SHORT` 或 `MULTICAM_AUDIO_SIGNAL_FLAT`。未知机位、重叠计划和越界时间段在应用前结构化拒绝。

## 5. Agent 交付门禁

1. 先执行 `--dry-run`，检查每个机位的哈希、`relative_delay_seconds`、`score` 和 `MULTICAM_LOW_CONFIDENCE`；
2. 只有在偏移可信且切换计划经过 Agent/创作者确认后才使用 `--apply`；
3. 应用后检查 `before-multicam` 快照、报告、操作记录和项目校验；
4. 渲染后用 `quality check --require-audio` 验证输出时长、音画同步和音频流；
5. 本契约不宣称视觉镜头审美、面部/主体识别、说话人分离、自动导演或剪映级多机位预览体验。
