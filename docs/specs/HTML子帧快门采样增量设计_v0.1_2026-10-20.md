## 复用决策

借用 OpenFilm `render.mjs:encode` 的“同一输出帧内重新绘制多个时刻，再合成一帧”组织方式，接入现有 HTML 动效 worker。

## 拟采用的产品语义

仅为显式本地 HTML 源新增可选渲染参数；默认 samples=1，保持现有输出路径和字节契约。
拟议 `motion html-render --shutter-samples 8 --shutter-fraction 0.5` 尚不存在，不能按已支持命令调用。
samples 为整数 1–16，快门比例为有限 0–1。samples=1 或快门为 0 时直接采用原帧路径，不创建无意义的重复截图。

采用中心区间中点采样：

```text
t(frame, k) = (frame + ((k + 0.5) / samples - 0.5) * shutter_fraction) / fps
```

其内部帧平均偏移为零。该选择与上游左端点公式不同，必须在 manifest 中写明 `sampling_phase=midpoint_centered`，不宣称输出与上游逐字节等价。
samples=1 始终使用原始 `frame/fps`，不施加半子帧偏移。
每个子帧均通过现有 `filmHost.time/film.frame/settle` 完整重绘；不能把一张输出截图复制 N 次当作子帧。

采样首先裁到该 HTML 源的有效半开区间。素材之间的剪切在序列组合层发生，采样不跨独立 HTML 源边界。
HTML 内部离散换场需新增显式、排序且唯一的 cut anchors；已知切点应裁在当前输出锚点所属区间内。
没有内部切点声明时必须记录该边界未检查，不能从 DOM 跳变静默推断已通过场景质量。
记录每帧所有请求时间、实际 clamp 时间、重复时刻数量和权重，不只留下平均图片摘要。

## 透明与色彩

第一阶段限定为当前 Chromium 的 8-bit sRGB 预览链。使用预乘 Alpha 合成，避免透明像素隐藏 RGB 污染有色边缘。
对每像素和等权样本，先累计 `alpha` 与 `channel×alpha`，再按明确的舍入规则还原 RGB；总 alpha 为零时 RGB 为零。
samples=1 直接原样传递，包含原隐藏 RGB，保证默认路径不被规范化改写。
这属于编码域 sRGB 平均，manifest 写明色彩域，不声明线性光、HDR 或电影级曝光模拟。
线性 sRGB 合成若后续增加，需独立模式、转换表与验收，不能仅靠 BT.709 封装标签宣称完成色彩转换。

## 预算与工程路径

现有 HTML 源上限为 1800 输出帧和 20 亿个输出像素；现有确定性检查另有两个重绘遍历。
新增预算必须计入 `width×height×output_frames×samples×passes`。8 次采样、3 个遍历意味着每个输出帧 24 次绘制；实际耗时仍需实测。
保持现有单子帧 ACK 背压，流式累计一个输出帧；成功、取消、超时均关闭自身 context/browser 并交由 Windows Job 清理后代进程。
不得下载运行时、使用 Docker/WSL 或为了该功能占用共享 GPU。

原 [R09 估算](../OpenFilm最新复用评估与成本取舍_2026-10-20.md) 的 **3–5 人日**仅针对限定 HTML 原型：先完成协议/预算，再实现合成与时钟，最后做像素、默认兼容、安装和文档核验。
该估算不包含自然镜头质量、4K/长片性能、所有模板兼容或剪映完整效果验收；当前研究实验的执行时间不作为完成这些工作的证明。

## 必须独立通过的验收

1. samples=1 与快门 0 的默认输出逐字节/逐帧一致；原有模板变量和字幕时钟没有变化。
2. 解析运动矩形在子帧位置和边缘覆盖率上匹配独立参考；有 alpha=0 隐藏 RGB、半透明重叠和全透明控制。
3. 整数/有理 FPS、首尾、显式切点、零运动和重复 clamp 的实际时刻与输出 PTS 一致。
4. 同一子帧在新鲜上下文顺序/逆序/重排中完全一致；有状态或未冻结时钟仍明确拒绝。
5. 默认/增加采样的真实 CPU 工作量分别记录，取消/超时/写盘失败保留证据，全部自有浏览器进程退出。
6. 独立离线安装、模板重放/打包、清晰的资产来源、媒体摘要和当前字节冻结完整回归通过。
7. 透明联系表可辅助静看；另用自然动效与连续播放检查运动观感。未完成该项时保持质量未接受。
