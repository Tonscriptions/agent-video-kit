本契约补齐整片段关联、共同波纹、主轨跟随和闭隙规划。产品仍使用 Agent Project JSON、整数 tick、原事务与 FFmpeg；运行此功能不启动 Node、浏览器、GUI、模型、媒体下载或网络服务。它不是 OpenFilm 全部规划函数的移植，也不关闭完整剪映等价目标。

## 1. 模型

`sequence.editing` 可省略/null，或为只包含 `main_track_id`、`sync`、`linkage`、`linked` 的对象。后三项严格布尔，默认 false/false/true。显式主轨必须是本序列 video 轨道；省略时选 order 最小的 video，同 order 按 ID 排序，subtitle/data 不成为主轨。没有 video 时允许关联与普通编辑；省略 track_id 的闭隙需先明确目标。

`track.sync_lock` 严格布尔，省略视为 true；它控制全局 sync 到达的其他轨道，显式编辑的轨道仍参与。`track.locked` 的关联成员会导致整个关联编辑拒绝，不能通过只改未锁一半造成不同步；全局 follow 会跳过其他锁定轨道。

`clip.link_id` 为有效 ID 或 null；同序列同值构成关联组。关联操作合并所选组的所有成员；解除关联只清所选成员，若只剩一个成员也清掉该孤立成员的关联。元数据关联操作不缩短作者保留的序列尾部。整片段移位/删除默认展开关联组，可显式 options.linked=false 只编辑所选片段。

## 2. CLI 与请求

先 `timeline edit --project <本地工程> --input <本地JSON> --dry-run` 查看计划；正式相同命令省略 dry-run 后应用。可传 `--expected-project-sha256 <计划摘要>`，若工程内容已改变，返回 EDIT_PROJECT_CHANGED、退出 2。该摘要包含所有作者工程 JSON 值；元数据时间变化也使旧计划失效。幂等重试仍先返回已保存的相同请求结果。

```json
{"action":"remove","clip_ids":["shot_b"],"options":{"ripple":"main","linkage":true}}
```

| action | 必要字段 | 行为 |
|---|---|---|
| link | clip_ids，至少两片段；link_id 可选 | 合并所选及既有关联组，不改时钟 |
| unlink | clip_ids | 解除指定关联及剩余孤立成员 |
| remove | clip_ids | 整片段删除；ripple=false 留隙，true 闭所删跨度，main 只闭主轨所删跨度 |
| close_gap | at_tick；track_id 可省略为主轨 | 只闭包含该 tick 的现有间隙；不含最后片段之后的尾部 |
| close_gaps | track_id 可省略为主轨 | 从后往前批量关闭开头及片段之间的间隙 |
| shift | clip_ids、delta_tick | 整片段平移及可选关联/主轨骑乘成员；不做插入、覆盖或主轨重排 |

options 只允许 sync/linkage/linked/ripple；tick 必须为整数，布尔/浮点/重复 clip ID、未知字段和无关 action 字段都拒绝。ripple 仅为 true/false/main。shift 的同步锁不意味着把所有后续镜头做插入式重排；主轨碰撞明确拒绝。

compose 可把 `{"op":"linked_edit","edit":<上述请求>}` 放入同一 operations 批次；进入该项之前的中间工程必须已通过原生校验，失败由原事务整体回滚。通过 update_sequence.patch.editing、update_track.patch.sync_lock、append_clip.link_id/update_clip.patch.link_id 编排作者配置。

## 3. 跟随规则

sync 优先于 linkage。同步闭隙/波纹先合并重叠删除跨度，按从后往前顺序移动各可达轨道上从跨度末尾开始的片段；左移量由这些轨道共同的空闲距离限制。空间不足保留 `short_tick` 和 EDIT_RIPPLE_SHORTFALL 警告，所有到达轨道使用同一位移，**不回退为单轨闭合**。跨越编辑点、从编辑点之前开始的片段不被裁切。

只有 linkage 且编辑涉及主轨时，其他未锁轨道的骑乘片段随主轨移动。宿主为片段开始点落入的主镜头，或主轨末端之后的最后镜头；落在主轨间隙则无宿主。跨过最多一个主轨边界点者骑乘；跨多个剪口的长配乐固定在序列时间。删除宿主同时删除骑乘成员，并继续遵守显式关联组原子性。此为固定上游的骑乘规则，不是对所有剪映版本行为的实测结论。

联动造成副轨碰撞时，保留未移动片段，移动者优先进入同 kind、相同 mute/audio 处理且有空间的未锁副轨；无合适轨道则复制原轨处理配置，新 order 为现有最大值+1。它不冒充上游 GUI 的“最近显示轨”。有轨道 audio.effects 或 duck_under_voice 的音频自动换轨拒绝，避免静默改变非线性、有状态或依赖其他轨道的总线语义。主轨平移碰撞拒绝，不隐式裁切/覆盖。原本未受影响的允许重叠区间保留。

## 4. 时钟、引用及提交

存活片段的 source in/out、speed/curve/reverse、keyframes、mask/effects、权利依赖保持。移动文件字幕时，若 asset_time_base=sequence（含默认），累加 `subtitle.asset_time_offset_tick -= 位移`；渲染在输入文件字幕滤镜前应用此整数偏移，再恢复最终显示时钟。clip 基准字幕和内联文字不加该偏移。该字段允许负整数；元数据记录不修改原 SRT/ASS 文件。

自动换轨若移动一个 tracking_binding 的源片段，同步更新仍引用它的 source_track_id；锁定依赖目标不能更新则整批拒绝。删除后仍有依赖引用源也明确拒绝，不隐式解除绑定。其他序列引用的绑定同样检查。markers 保留绝对序列 tick，不自动随镜头移动。实际内容编辑后序列尾部按剩余片段最大结束点重算；空序列至少 1 tick。

dry-run 返回候选校验、完整片段前后差异、新轨设置、锚定名单、共同位移和 short_tick；不写项目、快照或操作。正式操作在现有项目写锁和跨元数据事务中创建 before-timeline-edit 快照、保存项目、登记 operation/provenance。保存或操作记录失败必须回滚；幂等请求不能重复产生快照。

原生 Agent JSON/package 保留上述字段。OTIO、Kdenlive、明文草稿把编辑开关/关联与非零字幕偏移报告为 Unsupported；旁车保存不是外部执行证明。V33 当时普通 ripple_delete 的片段内部裁切仍有缺口；后续 V38 以新的[输出窗口契约](./片段输出窗口裁切与波纹编辑契约_v0.1_2026-10-18.md)补齐完整作者轴内的拆分/裁切/内部波纹插删，实测单独记录。后续 V39 按[范围编辑契约](./范围编辑插入覆盖与滚滑剪口契约_v0.1_2026-10-18.md)原生补齐插入/覆盖/lift/extract/roll/slide；源作者范围外扩、复杂关联 slip 与完整主轨磁吸仍需继续实现验收。V33/V38/V39 的局部通过不能视为全部完成。

## 5. 接受条件

必须有：同步与联动分开的真实视频/音轨；长配乐不动；锁定、短移、单 tick/分数帧率、关联原子性；冲突副轨与处理配置；复杂原动画原时钟保留；sequence/clip 文件字幕的连续多次位移；dry-run/旧计划/幂等/回滚；原生往返及外部损失报告。对照固定 OpenFilm 需声明毫秒触碰容差、单轨回退、最短片段和锁定规则差异，不能把所有不同结果都算作本产品失败或兼容。
