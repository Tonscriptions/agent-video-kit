# 本地模型适配器注册与音频分离门禁契约 v0.1

| 项目 | 内容 |
|---|---|
| 文档编号 | SPEC-MODEL-001 |
| 日期 | 2026-10-15 |
| 状态 | 有效 |
| 适用版本 | Agent Video Kit 0.1.x |
| 运行边界 | 原生 Windows、Python、FFmpeg；网络禁用，不启动 Docker/WSL/容器/GUI |

## 1. 目标

本契约把 Demucs、UVR、Open-Unmix、ONNX 或其他离线音频模型从“用户口头声明可用”变成 Agent 可以检查的本地适配器记录。注册只记录用户已经准备好的本地文件或目录，不下载、不复制大模型、不执行未知命令，也不把登记动作误报成模型已经可推理。

音频适配器 registry 位于项目内 `models/audio-adapters.json`。模型目录、模型文件和可选执行器保留在原路径；registry 保存绝对路径、确定性 SHA-256、文件数量、输出契约、许可证和 `network=disabled`。模型路径离开机器后需要重新登记或重新校验。

## 2. 命令

### 2.1 登记前 dry-run

```powershell
python -X utf8 -m ai_ad_editor audio adapter register `
  --project .\work\demo `
  --adapter-id demucs_local `
  --engine demucs-local-v1 `
  --model-path E:\models\demucs `
  --license-spdx MIT `
  --verification-status verified `
  --evidence local://model-license `
  --dry-run
```

dry-run 计算路径、模型哈希、许可证字段和 Rights Ledger 记录，但不得创建 registry、快照、操作记录、项目变更或媒体文件。

### 2.2 正式登记与检查

```powershell
python -X utf8 -m ai_ad_editor audio adapter register --project .\work\demo --adapter-id demucs_local --engine demucs-local-v1 --model-path E:\models\demucs --license-spdx MIT --verification-status verified --evidence local://model-license
python -X utf8 -m ai_ad_editor audio adapter list --project .\work\demo
python -X utf8 -m ai_ad_editor audio adapter inspect --project .\work\demo --adapter-id demucs_local
```

正式登记创建 `before-audio-adapter-register` 快照，在 `models/audio-adapters.json` 追加适配器，向 Rights Ledger 追加 `kind=model-adapter` 记录，并把 adapter ID、engine、模型哈希、registry 路径和操作 ID 写入 `project.json` provenance。重复 adapter ID 必须返回 `MODEL_ADAPTER_EXISTS`。

## 3. Registry 字段

每个适配器至少包含：

| 字段 | 约束 |
|---|---|
| `adapter_id` | 项目内稳定 ID；不得包含路径分隔符或空白 |
| `engine` | 见 4 节白名单；未知 engine 直接拒绝登记 |
| `model_path` | 本地文件或目录；必须存在并写入 `model_sha256`、`model_kind`、`model_file_count` |
| `executable` | 可选本地执行器；`command-json-v1` 必须提供并记录 `executable_sha256` |
| `output_contract` | 当前固定为 `center_side_wav_v1` |
| `network` | 固定为 `disabled`，不能由输入参数覆盖 |
| `verification_status` | `unverified`、`verified` 或 `restricted`；状态不代表运行器已实现 |
| `registered_at` | 登记时间；仅作 provenance，不参与哈希 |

目录哈希按相对 POSIX 路径、文件大小和文件 SHA-256 排序后再哈希，避免 NTFS 遍历顺序造成 registry 漂移。`audio adapter inspect` 不执行模型，只检查路径存在性和已登记哈希；发现变更时返回 `verification.ok=false` 与 `MODEL_HASH_MISMATCH` 或执行器对应错误。

## 4. Engine 与执行门禁

当前白名单如下：

| Engine | 登记 | `audio separate --adapter-id` | 当前状态 |
|---|---:|---:|---|
| `ffmpeg-local-mid-side-v1` | 是，可省略模型路径 | 可执行 | 已实现的声道相位近似 |
| `command-json-v1` | 是，必须提供本地执行器 | 拒绝，直到命令协议 runner 完成 | 仅 metadata |
| `onnx-audio-separation-v1` | 是，必须提供本地模型 | 拒绝，直到 ONNX runner 完成 | 仅 metadata |
| `demucs-local-v1` | 是，必须提供本地模型 | 拒绝，直到 Demucs runner 完成 | 仅 metadata |
| `open-unmix-local-v1` | 是，必须提供本地模型 | 拒绝，直到 Open-Unmix runner 完成 | 仅 metadata |
| `uvr-local-v1` | 是，必须提供本地模型 | 拒绝，直到 UVR runner 完成 | 仅 metadata |

传入已登记但尚无对应本地 runner 的 adapter 时，命令必须返回退出码 10、错误码 `AUDIO_SEPARATION_ADAPTER_UNAVAILABLE`，并说明当前没有 runner。不得把未知模型当作可执行，不得静默 fallback 到 `ffmpeg-local-mid-side-v1`，也不得调用网络服务。

## 5. Rights Ledger 与发布

模型适配器登记为 `kind=model-adapter`，`asset_id` 为 `adapter:<adapter_id>`，`sha256` 使用模型文件/目录哈希，`source_url` 使用 `local://adapter/<adapter_id>`。许可证、作者、允许用途、证据和 `verification_status` 必须沿用 Rights Ledger 字段；`license-spdx` 默认为 `LicenseRef-UNVERIFIED`，发布前仍需要明确许可证和证据。适配器记录不会自动授权模型输出素材的商业使用，输出音频仍需单独继承或登记其素材权利。

## 6. 错误、恢复和审计

| 错误码 | 触发条件 | Agent 处理 |
|---|---|---|
| `MODEL_PATH_MISSING` / `MODEL_PATH_EMPTY` | 模型路径不存在或目录为空 | 修正本地路径后重新 dry-run |
| `MODEL_ADAPTER_EXISTS` | adapter ID 重复 | 使用 inspect 或新的稳定 ID |
| `MODEL_ADAPTER_NOT_FOUND` | separate/inspect 未找到 ID | 先 list，不能猜测路径 |
| `MODEL_ADAPTER_HASH_INVALID` | 执行前模型/执行器哈希变化 | 重新登记并复核许可证 |
| `AUDIO_SEPARATION_ADAPTER_UNAVAILABLE` | engine 已登记但 runner 未实现 | 停止该计划，等待对应本地 runner；禁止 fallback |

登记写入走项目原生写锁和事务；异常恢复遵循 `project recover`。模型大文件不纳入项目快照复制范围，快照只保存 registry、Rights Ledger 和项目元数据，因此恢复后必须再次执行 `audio adapter inspect`。

## 7. 验收条件

1. dry-run 不创建 registry 或 Rights Ledger 记录。
2. 正式登记保存模型/执行器哈希、快照、Rights Ledger 和 provenance。
3. list/inspect 只读检查哈希；模型内容变化可被发现。
4. 已登记但没有 runner 的 engine 结构化拒绝，并且不执行 FFmpeg fallback。
5. 全量 `unittest`、`compileall`、Skill 审计和 `docs/` 链接审计通过。

该契约关闭“离线模型可以被随意声明、无法复核来源或被静默回退”的工程缺口；它不声称 Demucs、UVR、Open-Unmix 或 ONNX 推理 runner 已经完成。每个 runner 仍需另立实现契约、固定本地模型样例、输出哈希、质量 golden 和许可证复核。
