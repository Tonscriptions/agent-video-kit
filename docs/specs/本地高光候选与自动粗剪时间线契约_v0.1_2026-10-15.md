# 本地高光候选与自动粗剪时间线契约 v0.1

| 项目 | 内容 |
|---|---|
| 文档编号 | SPEC-HIGHLIGHTS-001 |
| 状态 | 有效 |
| 版本 | 0.1.0 |
| 日期 | 2026-10-15 |
| 适用入口 | `media highlights` |
| 运行边界 | 原生 Windows、Python、FFmpeg、本地文件；网络关闭 |

## 1. 目标与边界

本契约把本地媒体理解结果转成可审阅的高光候选，并提供一个显式的 Agent 粗剪应用路径。它服务于“先证据、后写入”的无 GUI 工作流：命令先生成 hash 绑定的候选报告，只有调用方明确传入 `--apply`、已登记 `--asset-id` 和视频 `--track-id` 时才修改项目。

候选排序只使用本地 `scene_change`、`silence` 和可选 `beat_anchors` 证据，并由 `recommend_highlights` 生成确定性分数、源时间范围和候选 ID。该路径不声称语义理解、人物/物体识别、镜头审美判断、剪映智能导演或模型级高光选择；应用后的 `HIGHLIGHTS_REVIEW_REQUIRED` 必须交给 Agent 或人工复核。

## 2. CLI 入口

```powershell
# 先规划并写入项目内报告，不改时间线
python -m ai_ad_editor media highlights --project .\work\demo --asset-id asset_source --beats --top-k 5 --output .\work\demo\validation\highlights.json

# 预览应用目标与参数，不分析媒体或写项目
python -m ai_ad_editor media highlights --project .\work\demo --asset-id asset_source --sequence-id sequence_main --track-id track_video_1 --timeline-start-seconds 0 --top-k 5 --apply --replace-track --dry-run

# 在快照和重叠检查后写入目标视频轨道
python -m ai_ad_editor media highlights --project .\work\demo --asset-id asset_source --sequence-id sequence_main --track-id track_video_1 --timeline-start-seconds 0 --top-k 5 --apply --replace-track --output .\work\demo\validation\highlights-apply.json
```

`--input` 可以用于只读候选报告；`--apply` 必须使用项目内已登记的 `--asset-id`，避免绕过资产哈希、Rights Ledger 和来源追踪。`--sequence-id` 缺省使用主序列，`--track-id` 是必填的目标视频轨道，`--timeline-start-seconds` 必须为非负数。`--replace-track` 只在应用时生效，会先清空目标轨道；省略它时，任何时间范围交叠都返回 `HIGHLIGHTS_TRACK_OVERLAP`。

## 3. 报告与时间线语义

非应用报告保留原有 `recommendation` 结构，并增加以下审计字段：

| 字段 | 语义 |
|---|---|
| `source` / `source_sha256` | 实际分析文件及 `sha256:<digest>` |
| `analysis` | 本地 FFmpeg 场景、静音和可选节拍证据 |
| `engine` | 推荐器 `local-heuristic` |
| `pipeline_engine` | `ffmpeg-local-highlight-heuristic-v1` |
| `network` | 固定为 `disabled` |
| `apply` / `replace_track` | 请求意图，便于重放和审计 |
| `candidates` | 含 `id`、`start_seconds`、`end_seconds`、`score` 的源范围候选 |

应用报告外层 `report_version` 为 `0.2.0`，并额外包含 `applied=true`、`operation_id`、`before_snapshot_id`、`sequence_id`、`track_id`、`timeline_start_seconds`、`generated_plan`、`generated_clips` 和 `validation`。每个生成片段保持源范围合法，使用项目 `ticks_per_second` 转换时间，按候选源时间顺序连续排布到目标时间线；项目序列时长随后重新计算。

应用成功后必须同时产生：

1. `history/` 下标签为 `before-highlights` 的自包含快照；
2. `provenance.change_log` 中的命令、素材、序列、轨道、片段、报告和快照关联；
3. `operations/<operation_id>.json` 成功记录；
4. 通过 `validate_project` 的结构、时基、引用和轨道重叠校验；
5. 包含 `HIGHLIGHTS_HEURISTIC` 和 `HIGHLIGHTS_REVIEW_REQUIRED` 的 JSON envelope warnings。

## 4. Dry-run、错误和 warning

`--dry-run` 只返回输入、素材/序列/轨道、候选参数、应用意图和 `ffmpeg-local-highlight-heuristic-v1`，不执行媒体分析，也不写报告、快照或项目文件。

| code | 类别 | 触发条件 |
|---|---|---|
| `HIGHLIGHTS_HEURISTIC` | warning | 候选只由镜头/静音/节拍启发式证据排序 |
| `HIGHLIGHTS_REVIEW_REQUIRED` | warning | 候选已经写入时间线，发布前必须检查语义、连续性、音画同步和转场 |
| `TRACK_LOCKED` | error | 目标视频轨道被锁定 |
| `HIGHLIGHTS_PLAN_INVALID` | error | 候选缺少合法的源时间范围 |
| `HIGHLIGHTS_EMPTY` | error | 没有可应用的高光候选 |
| `HIGHLIGHTS_TRACK_OVERLAP` | error | 未使用 `--replace-track` 时与目标轨道已有片段重叠 |
| `HIGHLIGHTS_APPLY_INVALID` | error | 应用后项目校验失败 |

错误发生在项目保存前时，不应留下部分时间线写入。报告和操作记录路径必须位于项目受控目录内；远程 URI、网络媒体和未登记输入不属于此契约的运行输入。

## 5. 验收证据

最小回归必须覆盖：

- 非应用报告仍保留 `engine=local-heuristic`、源哈希、`network=disabled` 和启发式 warning；
- 应用路径生成至少一个片段、`before-highlights` 快照、操作记录和 review warning；
- `--replace-track` 的片段数量与报告一致，项目通过 `validate`；
- 未登记 `--input` 不能直接应用，锁定轨道、空候选和交叠分别返回结构化错误；
- 应用报告可通过 `source_sha256`、`operation_id` 和 `before_snapshot_id` 重放与追溯。

固定样例仍需补充真实广告素材、人工语义评分和跨设备渲染 golden。当前实现只关闭“高光候选无法进入 Agent 时间线”的工程缺口，不关闭高光语义理解、镜头内容匹配、自动转场设计或剪映级导演质量。
