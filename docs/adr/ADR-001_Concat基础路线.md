# ADR-001：Concat 作为 Agent 剪辑内核的基础路线评审

| 项目 | 内容 |
|---|---|
| 状态 | 评审中 |
| 日期 | 2026-10-12 |
| 关联基线 | [产品需求与开发路线基线_2026-10-12.md](../产品需求与开发路线基线_2026-10-12.md) |
| 决策范围 | 是否基于 Concat 构建无 GUI、面向 Agent 的广告剪辑内核 |

## 背景

项目需要一个不依赖剪映、面向 Agent 的开源视频编辑内核。此前评估认为 Concat 已具备多轨、关键帧、效果包、项目编辑接口和渲染相关能力，因此可以作为候选基础；同时它仍处于 Beta，GUI、CLI、服务端和各类接口的边界，以及 Windows 发布质量和 AGPL 义务，都需要在本地锁定版本后验证。

## 候选路径

| 路径 | 做法 | 优势 | 主要风险 |
|---|---|---|---|
| A：Fork 后拆分 | 保留 Concat 可复用核心，删除或隔离 GUI，新增 Agent CLI/API、项目格式和广告领域层 | 初始复用最多，较快得到可运行内核 | 上游耦合、GUI 假设、AGPL 合规、Beta 缺陷 |
| B：抽取核心 | 将媒体、时间线或效果包抽成独立库，重新设计 Agent 契约 | 边界更干净，长期维护可控 | 抽取成本高，容易失去上游修复和功能 |
| C：FFmpeg 上层重写 | 以 FFmpeg 为媒体层，从零实现项目模型、时间线、关键帧和编排 | 约束最清晰，格式和 API 可完全自定 | 工程量最大，需自行补齐编辑器大量语义 |

## 当前决策

暂不把 A、B、C 中任何一条标记为最终采用。项目采用“**Concat 优先验证、规范格式独立设计、随时可切换实现**”的策略：

1. 先固定 Concat 上游仓库、提交、许可证、依赖和本地构建方式。
2. 先定义 Agent Project JSON、时间基准、错误码和渲染/转换报告，避免项目格式被单一内核锁定。
3. 用 P0 golden project 验证无头调用、媒体摄取、多轨、关键帧、字幕、音频、转场、渲染和质检。
4. 只要 Concat 无法满足某个 P0 契约，就记录替换边界，允许抽取其局部能力或切换到 FFmpeg/其他开源组件。
5. 产品名称、包名和文档中要区分上游 Concat 与本项目派生物，遵守许可证和商标要求。

## 必须完成的决策门槛

### 技术门槛

- 能在原生 Windows 上编译或使用锁定的源码构建，不调度 Docker、WSL、容器或其他虚拟化环境；
- GUI 不是启动和渲染的隐含依赖，关闭 GUI 后 CLI/API 仍能完成 P0 样例；
- 能将轨道、片段、关键帧、效果、字幕和音频参数映射到规范项目格式；
- 渲染失败、素材缺失、项目迁移和取消重试都有稳定状态与错误码；
- 上游版本升级有回归夹具，能够识别输出或项目格式变化。

### 法律与分发门槛

- 锁定 AGPL-3.0-or-later、插件例外和第三方依赖许可证的适用范围；
- 如果提供网络服务，按许可证要求提供对应源代码和修改内容；
- 派生项目改名、保留版权与许可证说明，并避免把上游商标当作本项目品牌；
- 发布包中保留第三方通知、构建来源和可追溯的依赖清单。

### 产品门槛

- P0 广告样例的结果质量达到基线门禁；
- Agent 可以只通过结构化输入完成创建、修改、渲染、验证和重跑；
- 每个剪映或其他外部项目转换结果都能生成 Exact/Mapped/Approximate/Baked/Unsupported/Failed 报告；
- 资产和模板的 Rights Ledger 检查不依赖 Concat 的 GUI。

## 需要留存的证据

评审完成前，`docs/validation/` 或同层文档必须至少包含：

- 上游仓库 URL、提交哈希、许可证文件和第三方通知；
- 原生 Windows 构建日志、工具版本和复现步骤；
- P0 样例的输入项目、渲染清单、输出媒体检查和人工复核结果；
- Concat 项目模型与 Agent Project JSON 的字段映射表；
- 删除或隔离 GUI 后的启动依赖分析；
- Fork、抽取核心和 FFmpeg 重写的实际工时与缺口对比。

## 重新评审触发条件

出现以下任一情况时，必须重新评审本 ADR：

- 上游许可证、插件例外、商标或分发条件发生变化；
- Concat 关键接口在新版本中变化，导致 P0 golden project 失败；
- Windows 构建、渲染或性能门禁连续失败；
- 规范项目格式需要引入 Concat 私有字段才能表达 P0 能力；
- 用户将目标从 Agent 广告主链路扩大为完整消费级编辑器或移动/云协作产品。

## 结论边界

本 ADR 只决定验证顺序和可切换架构，不宣称 Concat 已经达到剪映水准，也不授予读取、解密或绕过剪映私有项目的权限。最终采用哪一条路线，要以锁定版本的样例测试、许可证审查和 P0 验收结果为准。
