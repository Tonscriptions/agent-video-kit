核查日期：2026-10-12，Asia/Taipei。目标：Agent 制作广告、素材混剪、关键帧与运镜预设；运行环境为原生 Windows。用户明确要求所有视频制作组件采用开源方案，且不得使用剪映。本报告替代上一份包含剪映客户端的推荐。

这套体系具备制作高质量常见广告成片的技术基础，值得以剪映同类成片的质量为验收目标；但它还不是已经搭建、实测达标的现成整包。当前没有核实到一套开箱即用、完全开源的程序 + Skill，能够全面等同剪映的 AI 特效、模板库、自动化覆盖和使用体验。

## Shotcut 主路线：已核实到什么

Shotcut MCP 实际编辑保存的 `.mlt` 工程，再由本地 MLT/FFmpeg 渲染。源码包含事务编辑、版本检查、工程验证、预览帧/联系表，以及完整工程、帧范围或命名标记导出。它不依赖剪映格式或客户端。

`animate_clip` 实际接受片内相对帧、中心位置、缩放、旋转、透明度、音量，编译为 Shotcut/MLT 滤镜。支持 linear/discrete/smooth 插值；另有恒速与速度关键帧接口。源码还会隔离片段的 producer，避免动画影响同素材的其他使用位置。因此可以在其上封装推近、拉远、横移、Ken Burns 等配方；**这些配方库仍待建设，接口存在不代表已有一键预设库。**

[结构化接口](https://github.com/matrodrigs/shotcut-mcp/blob/f1b78d350a9992296f0b7f11a55c04819ea25730/shotcut_mcp/tools.py)、[动画实现](https://github.com/matrodrigs/shotcut-mcp/blob/f1b78d350a9992296f0b7f11a55c04819ea25730/shotcut_mcp/project_document.py)

上游 CI 配置了 Windows/Python 3.10 的真实 MLT 渲染测试，覆盖 Shotcut 26.6.25/MLT 7.40.0 和 Shotcut 26.8.1/MLT 7.41.0，包含打包 MCPB 的 stdio 调用。动画测试实际渲染 PNG 并检查像素。这比只验证 JSON/XML 的测试更有参考价值；本次没有在本机重跑，也不能据此保证所有滤镜、字体、GPU 或编码器组合。

[安装与兼容范围](https://github.com/matrodrigs/shotcut-mcp/blob/f1b78d350a9992296f0b7f11a55c04819ea25730/docs/installation.md)、[Windows 渲染 CI](https://github.com/matrodrigs/shotcut-mcp/blob/f1b78d350a9992296f0b7f11a55c04819ea25730/.github/workflows/shotcut-integration.yml)、[实际渲染测试源码](https://github.com/matrodrigs/shotcut-mcp/blob/f1b78d350a9992296f0b7f11a55c04819ea25730/tests/test_integration.py)

它的边界也很具体：操作保存的工程文件，不能读取 Shotcut GUI 尚未保存的编辑；参数化动画不等于自动物体跟踪；安装的滤镜目录不等于全部滤镜都经过该接口验收。Shotcut 自身的调色、蒙版、跟踪和字幕等能力，要分别判断是否已有适用工具入口。[编辑器功能](https://shotcut.org/features/)、[MCP 工作流](https://github.com/matrodrigs/shotcut-mcp/blob/f1b78d350a9992296f0b7f11a55c04819ea25730/docs/workflows.md)

## Kdenlive：有现成 Skills，但不能把 GUI 能力全部算进 Agent

Kdenlive 是成熟独立开源编辑器，原生具备特效关键帧、插值、变速、标题、字幕等功能；官方文档也说明可以接入 Glaxnimate，并将 Blender 等专门工具的输出作为素材导入。[特效与关键帧](https://docs.kdenlive.org/en/effects_and_filters.html)、[标题与图形的分工](https://docs.kdenlive.org/en/titles_and_graphics/titles_and_graphics.html)、[原生 Windows 安装](https://docs.kdenlive.org/en/getting_started/installation.html)

`dcc-mcp-kdenlive` 当前源码提供项目、素材、时间线、特效、目录、导出、交换、设置和 native 共 9 个 Skill。README 常规列表仍写 8 个，额外的 native 为实验性桥接。文件编辑与 MLT 导出可以独立于 GUI 使用；实时桥接需要另外构建固定版本的 Kdenlive，不能当作现有官方安装包的开箱能力。

常规接口能追加片段、切分、删除/单轨 ripple，以及写入原生滤镜的关键帧字符串；不是完整的多序列/分组编辑 API。特效可能加在共享 producer 上，影响素材的多次使用，需要仔细管理。跟踪、语音识别等编辑器专有操作在该适配器中部分走 UI 路线，不能算已实现的原生 Agent 工具。

其 CI 有 Windows 单元/协议测试，真实 MLT 渲染任务目前配置在 Linux。这里仅审查该配置，没有运行 Linux 或虚拟化环境。**本机 Windows 的完整导出与工程重开仍需验收。**

[适配器能力与边界](https://github.com/dcc-mcp/dcc-mcp-kdenlive)、[真实 Skill 目录](https://github.com/dcc-mcp/dcc-mcp-kdenlive/tree/5a83cbad7c987e32b86a5314996951ac91311c3b/src/dcc_mcp_kdenlive/skills)、[导出实现](https://github.com/dcc-mcp/dcc-mcp-kdenlive/blob/5a83cbad7c987e32b86a5314996951ac91311c3b/src/dcc_mcp_kdenlive/render.py)、[CI](https://github.com/dcc-mcp/dcc-mcp-kdenlive/blob/5a83cbad7c987e32b86a5314996951ac91311c3b/.github/workflows/ci.yml)

如果把“上游现成标准 Skill”作为首要条件，它是更直接的备选；如果以本项目的 Agent 运镜与 Windows 交付证据优先，当前更倾向 Shotcut MCP。

## 高 Star Skill 的具体问题

CLI-Anything 的 Kdenlive 子模块确有 `SKILL.md` 和 JSON→MLT 工程路径。源码也包含直接调用 `melt` 的后端与相关测试，不能说它完全没有渲染代码。

但本次固定提交中，CLI 的 export 命令只注册了 `xml` 和 `presets`，没有 `render`；Skill 却给出了 `export render output.pdf` 示例。该调用既没有对应 CLI 子命令，扩展名也不适合视频。内置滤镜注册表主要是基础效果，不能据此宣称完整运镜/AI 特效工作流已经接通。因此需修复文档和实际调用路径后再评价整套交付。

[固定提交的 Skill](https://github.com/HKUDS/CLI-Anything/blob/34f519533bc175d2fe287ab8316b0dd99bb9cc43/kdenlive/agent-harness/cli_anything/kdenlive/skills/SKILL.md)、[实际 CLI](https://github.com/HKUDS/CLI-Anything/blob/34f519533bc175d2fe287ab8316b0dd99bb9cc43/kdenlive/agent-harness/cli_anything/kdenlive/kdenlive_cli.py)、[独立 melt 后端](https://github.com/HKUDS/CLI-Anything/blob/34f519533bc175d2fe287ab8316b0dd99bb9cc43/kdenlive/agent-harness/cli_anything/kdenlive/utils/melt_backend.py)

## 到“剪映水准”的能力分层

| 需求 | 优先体系的实现路径 | 当前判断 |
|---|---|---|
| 多轨广告剪辑、裁切、转场、混剪 | Shotcut/MLT + MCP 时间线编辑 | 已核实具体接口；本机样片待验收 |
| 9:16/16:9 工程与高质量导出 | 自定义工程尺寸 + MLT/FFmpeg | 技术基础具备；要检查画面适配、字体和编码 |
| 关键帧、推拉平移、旋转、淡入淡出 | `animate_clip` + 片内帧坐标 + 插值 | 已实现结构化接口；命名运镜预设待封装 |
| 卡点与变速 | 音乐节拍分析输出剪辑点 + 速度映射 | 速度接口已实现；节拍分析与广告配方待集成 |
| 中文字幕与 AI 转写 | Whisper → SRT/字幕 → 时间线 | 字幕接口与开源识别模型各自存在；中文端到端效果待验收 |
| AI 人像抠像、换背景 | MODNet 输出逐帧 alpha → 时间线合成 | 可用开源组件路径；非 MCP 内置现成流程，边缘与闪烁需检查 |
| 花字、产品展示、图形/3D 动效 | Glaxnimate/Blender 输出素材 → 时间线 | 开源制作路径；模板与 Agent 工作流待组织 |
| 调色、降噪、声音混合 | 安装的 MLT/FFmpeg 效果 + 响度检查 | 有编辑器和分析基础；参数需按素材验收 |
| 大量一键模板、完整 AI 特效体验 | 本地预设库 + 模型流水线 + 素材库 | 尚无已核实的完整现成整包 |
| 无人值守批量导出与可修改工程 | MCP 作业、预览、冻结工程、结果验证 | 有接口与上游测试依据；需本机重复运行验证 |

“支持关键帧”只表示能控制参数变化；“达到剪映常见广告的成片水平”还需要好的素材、预设设计与视觉验收；“全面等同剪映产品”又包含模板规模、AI 模型和操作体验。这三个结论不能互相替代。

## 纯开源组件与需要排除的默认组合

| 组件 | 在推荐中的位置 | 许可证 / 本次筛选 |
|---|---|---|
| Shotcut / Kdenlive | 独立时间线编辑器 | GPL 系列开源许可证 |
| shotcut-mcp / dcc-mcp-kdenlive | Agent 接口 | MIT；DCC-MCP Core 也公开 Rust/Python 源码并采用 MIT |
| MLT / FFmpeg | 独立渲染与媒体处理 | 开源；具体构建依组件采用 LGPL/GPL |
| Whisper | 本地语音转写 | 代码及模型权重为 MIT |
| MODNet | 本地人像抠像 | 官方说明代码、模型与 demos 为 Apache-2.0，指定 GIF 例外不用于本流水线 |
| Blender / Glaxnimate | 动效、图形与合成素材 | 开源应用；接入与模板仍待制作 |

[Whisper 代码与权重许可](https://github.com/openai/whisper#license)、[MODNet 许可](https://github.com/ZHKKKe/MODNet#license)、[DCC-MCP Core](https://github.com/dcc-mcp/dcc-mcp-core)、[Blender 源码](https://github.com/blender/blender)、[Glaxnimate](https://glaxnimate.org/)

剪映客户端、pyJianYingDraft、JyWrapper、依赖剪映渲染的 VectCutAPI 路线不符合本项目约束。它们的接口开源不能使最终制作链变成独立开源方案。

Remotion 官方 FAQ 明确说明其内核是 source-available，而非符合 OSI 定义的开源软件，因此当前不纳入严格纯开源方案；其 Skills 的许可证不能改变内核许可证。[官方说明](https://www.remotion.dev/docs/license/faq#is-remotion-open-source)

HyperFrames 主仓库为 Apache-2.0，本次 Star 为 60,764；它有多种动画路径。但现有 GSAP 工作流需要单独处理许可证，不能仅凭顶层 Apache 标签认定默认组合完全开源。Lumen 的 MIT 主项目本次为 7 Star，其 `package.json` 和第三方声明明确包含 GSAP 3.15，适用 GSAP Standard License。该许可证有用途限制，不能将其直接当作 MIT/Apache 同类依赖；这不等于断言广告制作违法。若后续选用，应替换该路径并重新检查预览/渲染。

[HyperFrames](https://github.com/heygen-com/hyperframes)、[其 GSAP 相关包声明](https://github.com/heygen-com/hyperframes/blob/main/packages/core/package.json)、[Lumen 第三方声明](https://github.com/Mas-inx/lumen-ai-video-editor/blob/main/THIRD-PARTY-NOTICES.md)、[GSAP 官方许可证](https://gsap.com/community/standard-license/)

Concat 本身为 AGPL-3.0，符合独立开源内核方向；当前主要障碍是成熟度与交付验证。维护者在 2026-10-11 确认 Windows x86_64 的 0.2.6 发布二进制存在问题，因此暂不把该发行包作为本机主路线。其他版本/源码修复要独立验证。[问题 #303](https://github.com/jub0t/concat/issues/303)

## 应补的本地 Skill 与预设

现有 `$video-cut-ad-creative` 可以承担广告角度与文案，`$video-cut-ffmpeg` 可以承担素材预处理；它们本身不是 Shotcut 编辑接口。项目主路线还需要下列配方层，**这些名称是待建设建议，尚未创建或注册**：

| 建议调用名 | 职责 |
|---|---|
| `$video-cut-shotcut-pipeline` | 素材检查、广告节奏、MCP 编辑、预览与交付的整体工作流 |
| `$video-cut-motion-presets` | 推近、拉远、横移、Ken Burns、卡点缩放、变速配方；约定片内时间与画面裁切 |
| `$video-cut-open-ai-effects` | Whisper/MODNet 等开源模型的输入输出、质量检查和时间线接入 |
| `$video-cut-render-qa` | 中文字形、字幕时间、关键帧、黑帧、音量、输出尺寸与工程可修改性验收 |

若改用 Kdenlive 的上游 Skills，安装时必须将目录与 frontmatter 的调用名改为 `video-cut-kdenlive-*`，并同步关联引用。native 实验包不应成为普通文件编辑和渲染的前置依赖。原始 Skill 快照保留上游名称是为了审计，不代表已本地加载。

## 达标前的实际验收

先用一支 30 秒、1080×1920、30 fps 的中文产品广告验收：多来源素材、至少两条视频轨、字幕、旁白和 BGM；包含推近、横移、变速和一个实际需要的 AI 抠像片段。选择已有参考广告明确字效、运动和节奏目标，参考素材仅用于对照，不调用剪映。

交付必须同时包含 MP4、可修改 `.mlt` 工程、字幕和预览联系表。检查字体无缺字、运镜无意外黑边、字幕与声音一致、抠像无明显闪烁、预览与导出相符，并重复运行/换料验证结果。更高分辨率或 GPU 编码也需要另验，不能由单支短片推断。

本轮已完成官方文档、固定提交源码、许可证、Star、Skill 文件与上游测试配置的核查；没有安装候选编辑器、执行候选仓库代码或制作渲染样片。因此结论是“优先验证的体系与缺口已确定”，不是“已在本机达到剪映水准”。全程未使用 Docker、WSL 或浏览器自动化标签页。
