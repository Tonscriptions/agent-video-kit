# HTML 文字布局与字体覆盖核验契约 v0.1

状态：有效（V46 受控范围；初始条款于开发前声明）。延续 V41/V45 离线 HTML、固定源包、参数/覆盖及原生 Job 约束；本轮补齐 Agent 可消费的实际帧文字诊断和显式渲染门禁。

1. 新命令 `motion html-quality` 接受已登记源码或已有输出配方、参数和覆盖；遍历全部有理 CFR 帧，在独立上下文反向重绘，逐帧比较 PNG 与诊断。只写 validation 报告与 cache/html-quality 预览，不修改工程、资产或权利台账；dry-run 不启动浏览器。失败报告有 report_version，事务回滚后仍可读；预览缓存不在元数据回滚删除范围。
2. 对实际可见 DOM 直接文字检查每个 Range 的行矩形、画面边界及祖先 overflow 的独立 X/Y 裁切。完全出框与部分裁切分别报告；不可见祖先、opacity 0 和空白不当成正常可见文字。显式预算失败不得静默截断成通过。
3. 提取 OpenFilm 固定 MIT `cutText` 的原始算法作对照及来源保留，产品扩展完全出框、独立 overflow 轴和逐帧证据。旋转/3D、clip-path/mask、复杂 SVG/Canvas 文字与字形墨迹边界不以 DOM 矩形冒充验收，报告未核验范围。
4. Chromium CDP 返回实际平台字体、PostScript 名和绘制 glyph 数；本地源字体用标准库解析 SFNT/WOFF1 的 name/maxp/cmap。检查实际使用字体的来源与 Unicode→非零 glyph 映射；系统/未知来源、格式不支持、歧义和变体序列保留未核验结论，不能凭字体加载成功宣布缺字检查通过。
5. 映射覆盖不是字形美学、复杂脚本塑形或中文排版观感验收。WOFF2、动态/彩色字体的完整语义及任意浏览器差异继续独立验收；字符 fallback 不能自动提升发布权利。
6. `html-render --layout-check strict` 在编码前用相同已验证计划执行全帧核验；错误或未核验布局/字体使输出失败，保留报告，工程/台账/新编码资产不变。未配置的源码及旧配方默认 off；已有配方省略参数时继承其 strict/off。此增量不隐式将旧工程全部标成已验收。
7. 预声明验证包括：正常/部分/完全出框、祖先独立轴裁切、动态帧/后段文字、不可见文字、真实系统 fallback、原创缺字/完整字体、嵌套文字、字体格式/表边界、帧序与诊断一致性、严格失败回滚、网络/取消与原生浏览器回收。发布原创输入、实际失败/修复 MP4/GIF、源码/帧/媒体摘要；人工静帧、连续播放和听审分开记录。

预算：每帧最多 5000 文本节点、128 可见直接文字范围、32768 字符、每范围 128 行矩形；CSS 最多 5000 规则、64 字体声明。字体源最多 64 文件，累计解析不超过 128 MiB 解压表或 262144 映射单元；未执行的输入预算失败返回明确错误。worker 原始布局证据 8 MiB、主进程报告计算数据 16 MiB、最多 8 帧 PNG 预览；这些是逻辑工作/存储预算，不是总进程 RSS 保证。严格预检与正式编码共用命令总期限；严格模式保存在新配方中，省略参数的重建继承并重新执行门禁。

完整剪映等价、自然广告黄金集、自然 AI 重建、听感、长片/跨设备资源与干净机器发行仍按原路线推进，本契约不关闭这些需求。
