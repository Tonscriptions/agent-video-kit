## 1. 要解决的问题与验收范围

固定 V29 的分段 atempo 为每个短段重新建立 WSOLA 状态，随后补齐到累计采样边界。真实解码发现：2 秒、48 kHz、双声道恒定 DC 输入经过 1→2 速度曲线后，在 [0.2, 1.0) 秒内存在 82 个零采样帧，最长连续 53 帧。包络时钟正确不能证明声音内容正确；[原失败输出和机器记录](../assets/audio-buses-20261017/dc-diagnostic-verification.json)保留。

本轮让分段滤镜先处理同一作者选区内的前后上下文，再截取输出核心。末段取实际伸缩信号的最后一段，避免名义比例偏移丢掉真实尾部。功能仍属于明确告警的分段近似，不承诺连续相位、完整瞬态、任意输入音高、主观听感或剪映等价。正确的总时长和有声音不能取代实际内容核验。

## 2. 原生编译与采样定义

1. 音频先经原生 FFmpeg 重采样为 48 kHz、转换为 packed float32，再按 `round(source_in_seconds×48000)` 和 `round(source_out_seconds×48000)` 截出选区；该半开区间是变速上下文的唯一信号来源。编码解码及重采样本身的滤波支持范围另属原生媒体处理，不据此宣称任意压缩/采样率的边界质量。
2. 保留现有解析积分得出的每个输出累计锚点，四舍五入到 48 kHz 采样；核心输出长度由相邻累计边界相减。上下文不改变作者时钟、视频映射和音频总线的全局布局。
3. 对非单位速度 `s`，请求的前/后输入上下文分别为 `ceil(8192×max(1,s))` 个采样，并裁到选区范围内。四个 2048 采样窗口是当前资源/暖启动策略，不构成任意串联速度与内容的充分性证明。单位速度不请求上下文，保留 `anull` 恒等路径。
4. 每段先处理扩展后的本地选区。中间段从 `round((core_start−context_start)/s)` 截取原定核心采样数；非单位速度的末段通过 `areverse→atrim→areverse` 取实际伸缩输出的最后 N 个采样。最后一个累计边界按作者片段的全局半开采样区间对齐，避免四舍五入留下一个空采样；存在定格插入或不同作者窗口时，先按内容区间上取整，之后再执行原有定格/裁切规则。各段重新计时，按源顺序拼接；作者倒放在完整源顺序结果之后执行。末段截取的源内容局部偏移由原生 WSOLA 决定，未声称精确到采样的瞬态映射。
5. 仍使用同一多声道 atempo 实例处理一段，不拆左右声道，也不自动改成离线 R3。上下文不越过作者选区，不使用选区外语音、重复波形、边缘复制或音高修正来填充缺样。
6. 极短选区等导致真实核心输出不足时，现存 `apad` 补静音规则仍生效；manifest 和 `audio_speed_curve_piecewise` 告警明确保留此边界。末端截取不复制尾采样、不循环片段，也不保证原生引擎能从不足一个分析窗的信号恢复声音。采样总数一致不表示没有补静音。
7. 末端反向截取需要缓冲。规划时按 `(ceil(context_input_samples/speed)+8192)×channels×4` 估算单份末端 float32 PCM；超过 **64 MiB** 返回 `AUDIO_TEMPO_CONTEXT_LIMIT`、退出码 2，在执行之前拒绝。它是带预留量的规划限制，不是原生算法的严格输出长度上界，也不是总 RAM/长片性能验收；FFmpeg 内部状态、多个缓冲及其他轨道另占资源。恒定嵌套速度可走原有标量路径，本限制针对实际使用末端上下文的曲线路线。

[FFmpeg 8.1 atempo 源码](https://github.com/FFmpeg/FFmpeg/blob/n8.1/libavfilter/af_atempo.c)显示 48 kHz 分析窗选择为 2048 采样；[官方滤镜文档](https://ffmpeg.org/ffmpeg-filters.html#atempo)描述滤镜及运行时 tempo 指令。这里选择选区内上下文策略；连续指令探针虽然减少中间静音，但该探针输出短于积分目标，未作为产品替代实现。

## 3. Agent 与 manifest

无需增加 CLI 参数或修改持久工程格式。现有直接 `speed_curve` 和嵌套序列音频，在未显式登记 R3 时使用本策略。R3 的可执行文件、依赖、许可与缓存契约不变，见[离线音频伸缩](./离线音频伸缩与PCM输出契约_v0.1_2026-10-17.md)。

叶片音频 manifest 增加 `audio_tempo_context`：

- `engine=ffmpeg-atempo-source-context-v2`、`sample_rate=48000`；
- 作者选区的起止/总采样数、上下文策略数及 `context_outside_selection=false`；
- `core_sample_format=float32`、末段预估字节和 `terminal_context_pcm_budget_bytes=67108864`；
- 各段核心/上下文输入采样范围、tempo、名义截取范围和累计输出范围；`output_selection` 区分 `nominal-source-offset` 与 `last-retimed-samples`。末端模式的实际起点取决于原生输出长度，`retimed_trim_start/end_sample=null`，不能把名义范围冒充实际范围；
- `shortfall_policy=zero-pad-core`、`continuous_phase_accepted=false`、`pitch_and_listening_accepted=false`。

`local_content_sample_alignment_accepted=false` 明确区分累计锚点与实际声音局部定位。标量恒速和单位速度若沿用原路径，manifest 没有本上下文节点；这不是功能缺失，不能为通过审计而强行加滤镜。

嵌套输入的 `nested_time_mapping.audio_tempo` 为 `piecewise-source-context-integrated-boundaries`。该结构描述实际编译行为，不是声音质量证书。既有最多 16384 段、嵌套段至少一个 48 kHz 采样的限制继续适用；长片、总内存与实时性未验收。

## 4. 核验与保留的失败

[原生 PCM 回归](../../product/tests/test_audio_tempo_context.py)检查直接/嵌套/倒放/快慢曲线、选区外强信号、作者静音、反相立体声、静音右声道、真实终端标记和单位速度逐采样恒等。慢速/裁切增加完整有效区间检查，末尾标记检查实际最后 512 个采样帧及之后的作者留白。DC 幅度门槛为绝对差 0.001；它允许原生 WSOLA 窗函数的微小变化，不是位精确承诺。控制测试与完整套件分别标注，不能把它们相加。

[公开正式 CLI 脚本](../../scripts/smoke_audio_tempo_context.py)同时生成固定 V29 与当前成片，比较全部新旧视频像素，并解码 float32 PCM。DC 中间区间与完整有效区间分别计算偏差、零采样/最长零段；完整有效区间失败必须保留。其他声道/静音控制只验其明示条件，不推导通用音高或听感。AAC MP4 用于播放，float MKV/WAV 用于精度检查，波形 GIF 无声。

开发阶段“只有上下文、没有实际末端锚定”的版本仍出现慢速末尾 85 帧和裁切末尾 26 帧补静音；这些实际失败及其源码快照保留，不能算作最终版本通过。最终范围以当轮正式旧/新 PCM 实测和独立复核为准。

既有 R3 极短音高失败、apart 反相混合失败、默认 atempo 极短输入静音、任意材料的末端和相位/瞬态、自然语音音乐、3..8 声道质量、VFR/嵌套定格、HDR 和完整剪映等价继续开放。

正式核验：[11 组实际成片、完整有效区间和开发失败](../validation/分段音频上下文与完整尾部实测_2026-10-17.md)。完整 618/618 和明确通过范围不关闭第 4 节保留的通用质量边界。
