# Agent原生浮点帧包CLI

本页描述已实现的`agent-native-clock-float32-bundle-v1`数据接口。普通时间线render、preview和缓存尚未采用该核心。精度能力与发布状态见[规格](specs/浮点表面合成与高精度边界_实验_v0.1_2026-10-22.md)及[实际测试、原片和GIF](validation/浮点表面合成与高精度边界独立实测_2026-10-22.md)。

在已安装的原生Python/FFmpeg环境调用CLI。示例中`ai-ad-editor`可替换为离线安装目录的`python -I -S -B run.py`；不创建虚拟环境、不下载依赖。

```powershell
ai-ad-editor project init E:/video-project
ai-ad-editor media ingest --project E:/video-project --input E:/media/original.mkv --asset-id source
ai-ad-editor surface export --project E:/video-project --asset-id source --output renders/float-source --source-primaries bt709 --source-transfer bt709-oetf --working-primaries bt709 --working-transfer linear --dry-run
ai-ad-editor surface export --project E:/video-project --asset-id source --output renders/float-source --source-primaries bt709 --source-transfer bt709-oetf --working-primaries bt709 --working-transfer linear
ai-ad-editor surface inspect --project E:/video-project --input renders/float-source
```

原生YCbCr视频须再提供`--pixel-family yuv --yuv-matrix bt709 --yuv-range full --chroma-location center --scan progressive`。这里的矩阵/量程/色度位置和逐行参数都是调用方明确声明，命令不会证明文件实际是逐行扫描或自动检测正确色彩。原生RGB使用默认`--pixel-family rgb`，不能附带YUV参数。alpha表示通过`--alpha-association straight|premultiplied`明确。

| 参数 | 语义与边界 |
|---|---|
| `--source-primaries / --working-primaries` | bt709 / display-p3 / bt2020，共同相对D65白；工作默认bt709 |
| `--source-transfer / --working-transfer` | linear / srgb / bt709-oetf / gamma22 / gamma24；源参数必填，工作默认linear |
| `--start-frame / --stop-frame` | 源帧索引半开区间；stop省略为全源末尾，保持原始PTS，选择后部仍需解码前缀 |
| `--transform-json` | 工程内本地JSON：width、height、inverse（2×3逆仿射）；像素中心为整数，双线性预乘重采样，外部透明 |
| `--max-output-mib` | 1..2048，包含像素/时钟/清单的估算，再要求64MiB空余；不是RSS预算 |
| `--cancel-file` | 工程内取消标记；清理本命令所属临时产物和进程，不删除既有原片/输出 |
| `--dry-run` | 只生成计划，不建立帧索引或执行像素解码，源SHA仍会读取 |

输出目录必须是工程内尚不存在的新路径。三份产物由SHA绑定：

| 文件 | Agent读取方法 |
|---|---|
| `bundle.json` | 布局、尺寸、源SHA、源选区、原始time_base、依赖/转换/预算说明；最大128KiB |
| `frames.rgba-f32le` | little-endian Float32，frames×height×width×4，交错straight RGBA；RGB可负或超1，alpha独立0..1 |
| `clock.i64le` | little-endian int64，frames×3；列为原始源帧索引、PTS、原始duration，使用清单time_base |

```python
import json
from pathlib import Path
import numpy as np
p = Path('E:/video-project/renders/float-source')
m = json.loads((p/'bundle.json').read_bytes())
rgba = np.memmap(p/'frames.rgba-f32le', dtype='<f4', mode='r', shape=(m['frames'], m['height'], m['width'], 4))
clock = np.memmap(p/'clock.i64le', dtype='<i8', mode='r', shape=(m['frames'], 3))
```

先调用`surface inspect`核对派生字节与时钟；它不重新读取原片/实现或提供签名认证，明确返回`original_inputs_revalidated=false`。需要新的源核验时重新导出到新目录。导出保留作者工程和rights-ledger字节，操作日志单独记录。

不自动旋转、不输出音频、不做CFR重采样或编码影片。相对D65变换不做ICC、色适应、物理白/亮度匹配、PQ/HLG、色域映射或HDR元数据。独立媒体脚本用线性帧包合成，再施加明确输出传递函数和16-bit量化，才生成浏览MP4/GIF；这些编码步骤属于独立核心管线。
