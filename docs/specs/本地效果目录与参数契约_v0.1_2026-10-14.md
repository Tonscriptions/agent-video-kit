## 1. 目的与边界

本目录是 Agent 生成效果计划时的本地事实来源。它只登记当前 FFmpeg 可执行文件已经提供、并且渲染器使用安全参数映射的滤镜；不下载插件、不调用在线注册表、不启动 GUI，也不声明与剪映视觉逐像素相同。目录版本和每一项的 `backend`、参数范围、别名、许可证来源与关键帧限制都随 CLI JSON 返回。

调用：

```powershell
$env:PYTHONPATH = 'E:\dev\sandbox\AI广告剪辑\product\src'
python -X utf8 -m ai_ad_editor effects list
python -X utf8 -m ai_ad_editor effects list --query color
python -X utf8 -m ai_ad_editor effects inspect --name curves
```

成功 envelope 的 `data` 至少包含 `catalog_version`、`source=ffmpeg-local`、`network=disabled`、`count` 和 `effects[]`。`inspect` 在 `data.effect` 返回单项对象；未知名称返回 `ARGUMENT_INVALID`，不会尝试网络解析。

## 2. 单项对象

每项包含：

| 字段 | 约束 |
|---|---|
| `id` | 项目 JSON 使用的规范 ID，使用小写下划线 |
| `aliases` | CLI 查询可接受的兼容名称；渲染器仍会在写入报告中保留原始 `type` |
| `category` | `color`、`blur`、`repair`、`stylize`、`detail`、`temporal`、`distortion`、`overlay`、`keying`、`transform` 等本地分类 |
| `backend` | 形如 `ffmpeg:<filter>` 的本地 FFmpeg filter 名称 |
| `source` | 固定为 `ffmpeg-local` |
| `license` | 固定为 `inherit-local-ffmpeg-build`；发布时继续以实际 FFmpeg 构建的许可证和 notice 为准 |
| `keyframable` | 原七项表达式效果，以及 V58 的 `color_temperature/color_balance/color_wheel/exposure/color_levels` 为 `true`；不表示每个参数均可动画 |
| `keyframe_parameters` | V58 五类原生命令效果的精确数值属性白名单，共 19 通道 |
| `keyframe_engine` | 上述五类为 `native-color-command-cfr-v1`，按实际 CFR 帧采样 |
| `parameters` | 参数的类型、默认值、上下界或枚举说明 |
| `limits` | 路径、静态曲线、近似或本地构建差异等约束 |

当前目录版本 `0.5.0` 共 45 项，包含基础调色/模糊/变换/遮罩辅助效果，以及 `hsl`、`rgb_curves`、`color_wheel`、`exposure`、`color_levels`、`curves`、`hqdn3d`、`smartblur`、`avgblur`、`tmix`、`tblend`、`lens_correction`、`draw_box`、`color_contrast`、`solarize`、`threshold`、`deflicker`、`dctdnoiz` 和本地 `frame_interpolation` 光流补帧。V58 增加已有五类的数值动画，不增加效果项数量。

## 3. 安全参数规则

- 数值参数在渲染边界再次 clamp 到 FFmpeg 能力范围；未提供参数使用目录默认值。
- `curves.all`/`curves.master` 只接受空格分隔的 `x/y` 点，每个坐标必须在 `0..1`，字符白名单拒绝逗号、冒号、引号和滤镜分隔符。
- `rgb_curves` 的 `all`、`red`、`green`、`blue` 通道分别使用同一组 `0..1` `x/y` 点白名单；静态点字符串决定固定拓扑；V80 允许 `<通道>.<点号>.x/y` 数值关键帧，按曲线动画契约执行。
- `hsl` 使用本地 FFmpeg `hue` 滤镜，`hue` 范围为 `-360..360`、`saturation` 为 `0..4`、`lightness` 为 `-1..1`；明度映射为 FFmpeg `hue` 的 `brightness` 参数，动态表达式由 `hue` 滤镜逐帧计算（该滤镜没有 `eval` 选项）。
- `color_wheel` 使用 FFmpeg `colorbalance` 的 shadows/midtones/highlights 三向通道参数，范围均为 `-1..1`；九数值通道可逐帧执行，`preserve_luma` 布尔值仍静态。基础 `color_balance` 与色温仍沿用阴影通道映射，不等于全 RGB 增益或物理白平衡。
- `frame_interpolation` 使用 FFmpeg `minterpolate`，支持 `fps`、`mi_mode`、`mc_mode`、`me_mode`、`me`、`mb_size`、`search_param`、`vsbmc`、`scd` 和 `scd_threshold` 的受控范围；它可用于本地智能慢动作，但运动补偿可能带来明显 CPU 成本和场景切换伪影。
- `draw_box.color` 只接受字母、数字、`#`、`@`、`.`、`_`、`+`、`-` 组成的 FFmpeg 颜色 token；不接受任意 filtergraph 片段。
- `tblend.mode`、`deflicker.mode` 和 LUT 插值只能使用固定枚举；未知枚举返回 `EFFECT_PARAMETER_INVALID` 并回退到安全默认值。
- LUT 可以使用项目内路径或 `lut register` 生成的 `lut_id`；登记引用会在校验和渲染前复核 SHA-256，详细字段见 [本地 LUT 资产库与效果引用契约](./本地LUT资产库与效果引用契约_v0.1_2026-10-15.md)。
- 项目 JSON 中的 `effects[].type` 可以使用别名，但 Agent 应优先使用规范 `id`，以便转换报告和回归快照稳定。

## 4. 关键帧与降级

原七项动态效果使用 FFmpeg `eval=frame` 或等效帧表达式，其中 `hsl` 的色相、饱和度和明度都映射到本地 `hue` 帧表达式（`hue` 选项本身没有 `eval` 参数）。V58 的五类/19 数值通道使用本地运行时命令、唯一滤镜实例和完整作者时钟；未知动态通道、缺少原生命令、缓存摘要不符和递归配额超限明确拒绝，不能静态回退。布尔、枚举和未列出的其它目录参数仍保持原静态/告警行为；原未知效果及近似警告必须进入 manifest 和 Agent 回复。精确字段、局部区间时钟和配额见[逐帧调色参数自动化契约](逐帧调色参数自动化契约_v0.1_2026-10-19.md)，实际编码/失败/安装见[本轮实测](../validation/逐帧调色参数自动化实测_2026-10-19.md)。

`hsl` 的参数映射是本地可复现的：`hue` → `hue=h`、`saturation` → `hue=s`、`lightness` → `hue=b`。`rgb_curves` 无控制点动画时保持静态 `curves` filter；有动画时生成有界的整通道命令，执行固定拓扑、六位小数 x 采样格和共享预算校验；不向 Agent 开放任意原生命令。`color_wheel` 将 shadows、midtones、highlights 的 RGB 值映射到 `colorbalance` 的 `rs/gs/bs`、`rm/gm/bm`、`rh/gh/bh`，同时传递 `preserve_luma` 为 `pl`；这些映射与近似边界会写入能力清单和渲染计划。

## 5. 变更与验收

新增滤镜必须同时完成：

1. 在 `effects.py` 登记规范 ID、参数边界、别名、后端和限制；
2. 在 `render.py` 通过白名单参数构建 filtergraph，拒绝可注入字符串；
3. 增加 CLI 目录查询和至少一个真实 FFmpeg 输出回归；
4. 更新 `capabilities`、README、CLI/Project JSON 契约、能力矩阵、回归记录和 `video-cut-agent-editor` Skill；
5. 通过 `compileall`、完整 unittest、`git diff --check`、Skill 审计后提交到 `main` 并自动推送。
