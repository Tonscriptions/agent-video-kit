## 1. 作者数据与继承

序列可声明 `canvas: {"width": 1080, "height": 1920}`。只接受 width、height，均为 2..8192 的整数；拒绝布尔、浮点和额外字段。缺省或 null 继承工程 settings.canvas 的有效尺寸，**不继承直接父容器**。显式子画布独立于根输出变体；继承型序列沿用此前随工程输出尺寸变化的行为。

画布只声明像素宽高。工程 ticks、最终 display_fps 与当前颜色处理仍统一；这里不定义子级独立帧率、色域、SAR、线性光或 HDR。奇数尺寸允许作为内部 RGBA 画布；最终编码需遵守所选像素格式的对齐要求，420 要求宽高偶数，422 要求宽偶数。预检失败返回 `OUTPUT_CANVAS_ALIGNMENT_INVALID`，不能靠编码器偷偷改尺寸。

`timeline compose` 的 `add_sequence` 接受可选 canvas。`update_sequence` 用 sequence_id（或 id）指定序列，patch 只接受 name、duration_tick、canvas、markers，且不能为空。清除画布用 `"canvas": null`。普通变更受项目事务、Schema 和内置校验约束；缩短到片段范围以内等无效操作整体回滚。dry-run 不保存作者数据。

```json
{"operations": [
  {"op": "add_sequence", "id": "portrait", "duration_tick": 180000,
   "canvas": {"width": 1080, "height": 1920}},
  {"op": "update_sequence", "sequence_id": "portrait",
   "patch": {"name": "独立竖屏序列"}}
]}
```

## 2. 空间处理顺序

子序列的素材、文字、局部变换、蒙版、混合与轨道顺序先在自己的透明画布内合成。容器把该合成结果投影到包含它的序列画布，然后依次处理父级 opacity、effects、mask、fade；父容器保持在自己的轨道槽位。多级嵌套逐级进行，不能把全部子层提前变成根尺寸或把父蒙版下推给叶片。

容器 crop 的像素单位指子画布，normalized/relative 单位按子宽高换算。裁切窗宽高夹到 [2, 子宽高]，原点夹到画布内。fit 统一等比容纳，fill 等比覆盖，stretch 分别缩放横纵轴；默认 fit。

容器 transform.position 以父画布归一化；anchor 以裁切后的原生子画布矩形归一化。以父像素中心求源坐标：平移到 position，逆旋转，逆用户 scale 与 fit 系数，再加子裁切原点及 anchor。源裁切窗之外透明。父 mask 位于投影后的父画布坐标；子 mask 仍处于子画布坐标。不能拿根画布归一化点直接代替子局部坐标。

fill 的源内容不在旋转前永久裁掉：后续旋转可能把原先落在父画布外的源重新带入视野。crop 和 transform 的动画共享既有作者时钟，嵌套的 trim、speed、reverse 映射不改成局部从零重播。

## 3. 原生实现与数值边界

同画布、无 crop 的既有容器保留原仿射路径。不同画布或声明 crop 的容器保留完整原生源纹理，只透明填充到源/父宽高分别取最大值的工作栅格，再在预乘 Alpha 空间按原生子坐标进行一次 bilinear geq 逆采样，最后裁出父画布并恢复 straight RGBA。没有在旋转之前裁掉 fill 的不可见源，也不先把源伸缩到父画布。该路径仍**不是任意高频细节无损、全尺度抗锯齿或另一编辑器效果相等的承诺**；小尺寸输出配大源的工作栅格仍取大源尺寸，性能须另验。中间合成仍为现有 8-bit encoded RGB；不新增 GPU、外部渲染服务或有损中间影片。

源和父像素宽高及 `anchor_space: cropped-child-canvas` 写入 `sequence-composite` manifest；`raster_adaptation` 区分重采样与原同栅格路径。这些是规划记录，像素正确性需要独立解码参考及原素材另验。

## 4. 根导出、文字、绑定与音频

render/quality/golden/queue 等选中子序列时，以该序列有效画布作为根输出默认。显式 profile 或 width/height 可覆盖本次选中的根；不重写工程和其他显式子序列尺寸。直接渲染 API 同样遵守该规则。输出指纹继续包含作者数据与本次有效输出配置，不能通过修改作者 JSON 来模拟临时覆盖。

子级文字在子画布排版；有源片段引用的 tracking_binding 根据所在序列画布重编译，再随容器投影。该过程不执行新模型，也不把计划元数据当真实跟踪质量。源观测、模型与素材权利依赖继续保留。

画布只改变视觉空间，不改音频源区间、采样或分层总线。默认音频变速告警、本地 R3 接受边界均维持；画布通过不能关闭声音问题。

Agent JSON 和 package 保留多序列画布及引用。OTIO 首序列有效尺寸和原继承配置写入 ai_ad_editor metadata，本项目导入时恢复；外部播放器是否执行这些自定义字段仍为 Approximate。Kdenlive 首序列尺寸写入/读取 profile；明文草稿首序列尺寸写入 canvas_config。其他显式子画布未映射时必须有 Unsupported/既有多序列损失记录，不能把单一输出画幅的往返当完整嵌套等价。这里未启动任何闭源编辑器。

## 5. 验收与明确未接受部分

验收需分别检查横竖画布 fit/fill/stretch、原生像素/归一化/动态 crop、非中心锚点及动画、旋转后显露、父子蒙版、多级嵌套、文字和绑定、奇数内部尺寸、选中子级导出、临时根覆盖、继承控制、作者只读及无效操作回滚。提供自制可公开原素材、固定旧版实际输出、独立坐标参考、当前输出、逐帧统计和 GIF/短片。

未接受部分仍包括独立子级 FPS/色域/SAR、任意高频纹理质量、线性光/HDR、通用嵌套 freeze/VFR、自然 AI 特效/声音/听感、长片内存/性能以及完整剪映功能效果等价。测试通过不替代上述专项验收。
