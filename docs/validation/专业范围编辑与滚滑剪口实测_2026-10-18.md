## 3. 实际拒绝与事务检查

每组成功案例都先执行干跑并比较原工程原字节，再用计划指纹正式执行、相同幂等键重试、严格权利校验及 `render --publish`。六项当前产品拒绝均检查 `project.json` 原字节保持；另八次固定 V38 干跑对同一实际请求返回 `EDIT_REQUEST_INVALID`，用于表明旧版接口缺项，不计为新产品成功功能或新增测试方法。

| 编号 | 触发 | 实际错误/结果 |
|---|---|---|
| G01 | 插入需拆关联锁定音轨 | `EDIT_TRACK_LOCKED`，整体拒绝 |
| G02 | roll 没有此前保留的完整作者句柄 | `EDIT_RANGE_HANDLE_SHORTFALL`，没有补帧/重新估算曲线 |
| G03 | 编辑后使用原先项目指纹 | `EDIT_PROJECT_CHANGED`，重新规划才可执行 |
| G04 | compose 先执行 extract，再遇到未知操作 | `ARGUMENT_INVALID`，范围编辑整体回滚 |
| G05 | incoming 两片段同一 ID | `EDIT_RANGE_ID_CONFLICT`，新旧全局 ID 在裁切前校验 |
| G06 | incoming `link_id=[]` | `EDIT_RANGE_REQUEST_INVALID`，没有在哈希查找时崩溃 |

53 新增专项还覆盖负向滚动、共有 link ID 的剪口、关联音频各自连续剪口、同步 opt-out、锁轨、直接选空轨、背景床不截断、范围/ID/布尔严格类型、组内偏移和显式空尾、辅助轨新建/处理门禁、跟踪引用、整组源转场移动/删除、字幕文件时钟、嵌套总线、零操作及批量回滚。专项为完整回归子集，不能相加。
