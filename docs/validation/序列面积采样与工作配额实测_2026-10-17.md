## 1. 实际行为

子序列先在其原生画布隔离合成，再执行容器投影。`settings.sequence_sampling.method` 或本次 `--sequence-sampling area` 选择源轴可分离矩形面积核：按逆变换得到像素中心和源轴核宽/高，积分分段常量的预乘 RGBA 源像素；分数裁切边缘以格子实际重叠面积计算，crop 外透明仍计入完整核的分母。放大时各轴核宽至少 1 像素。默认 bilinear 不插入新的作者设置，所测九组默认像素与固定旧版一致；不承诺任意工程或编码文件字节相同。

FFmpeg `geq` 的整数前缀查询需要显式组成分数边界，不能把浮点 rsum 参数当作分数积分。实现使用原生 FFmpeg 的积分表，宿主产品保持标准库。参考程序独立遍历覆盖的像素单元及交叠面积，不使用积分表、产品导入或产品表达式。90°/轴对齐在此离散模型下核对面积；17° 只核对声明的源轴矩形核，不是精确旋转像素多边形、EWA、Lanczos、线性光或 HDR。

工作配额对所有可达执行容器统一计费，包括时间不重叠及重复引用的节点；未引用序列不计。源两份 RGBA、父四份 RGBA、工作三份 float RGBA 与两份 byte RGBA；area 另加四份 double 积分表。工作尺寸为源/父各维最大值，即使旧同尺寸路径可旁路也按统一保守模型收费。估计超过显式预算，在叶滤镜/文字探针、FFmpeg 执行、输出目录与任务创建前拒绝。精确等于配额可规划通过。

默认 1 GiB 的新配额也作用于 bilinear，因此此前能规划的超大工程可能被拒绝；可显式改尺寸或预算，不自动降质。这是规划配额，**不是进程 RSS 上界**，未包括解码/编码器、其他效果、线程、根合成及并发作业。不能用通过配额证明 4K 或长片内存已验收。

## 6. 复现与来源

[成片生成脚本](../../scripts/smoke_sequence_sampling.py)、[短标题预览脚本](../../scripts/make_sequence_sampling_preview.py)使用本机已有 NumPy/Pillow、FFmpeg 和显式本地字体；产品核心本身不增加这些 Python 依赖。以新的 output/work 路径执行，旧结果不能覆盖；默认实跑包括固定 V31 的 git archive 对照、全部实际 CLI 和参考输出：

```powershell
<本地NumPy-Pillow的python.exe> -I -B -X utf8 scripts/smoke_sequence_sampling.py --output <E盘新证据目录> --work <E盘新临时目录> --font <本地DejaVuSans.ttf> --font-license docs/assets/sequence-compositing-20261017/font-license.txt
<本地NumPy-Pillow的python.exe> -I -B -X utf8 scripts/make_sequence_sampling_preview.py --folder <刚生成的证据目录> --font <同一字体>
```

完整回归用宿主 Python、`PYTHONPATH=product/src`、`TEMP/TMP/TMPDIR` 指向 E 盘，显式 `AI_AD_EDITOR_TEST_RUBBERBAND` 指向已有原生 R3，再执行 `python -B -X utf8 -m unittest discover -s product/tests -v`。固定旧版从本地 Git 提交解包 product/src 与 Schema，使用相同当前新增测试；不切换主分支、下载依赖或改旧源码。

全部程序纹理自制 CC0，字体二进制不分发，许可文本公开；FFmpeg、字体、生成脚本、输入/输出 SHA-256、实际帧率/帧数/时长和 103 文件清单在[来源](../assets/sequence-sampling-20261017/fixture-provenance.json)与[机器汇总](evidence/sequence-sampling-20261017.json)。初始候选的像素虽通过，参数复核发现 D05 后已重新执行最终九组与完整回归；旧开发媒体不与最终 74 CLI/144 area 帧叠加。媒体独立解码与预览修订另计。
