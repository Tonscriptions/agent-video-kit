## 4. 像素、音频与视觉范围

四组 256×144、12fps、24 帧样例覆盖红橙色相、蓝色饱和度、洋红明度和八色最终强度动画。输入是自制 CC0 HSL 色带、灰阶、透明／半透明／不透明区域、棋盘和双声道合成正弦。独立参照使用标准库 `colorsys`、相邻权重和 source-over，未调用产品 HSL 或 FFmpeg 调色滤镜。

全帧 RGB、原透明区、灰阶、合成 Alpha、完整 96,000 帧立体声 PCM 和全部 PTS 分别检查；原生 ABI／geq 专项另外检查直接输入 Alpha、奇数尺寸、六插值、非线性时间／反转、并发实例、惰性求值和非法二进制。包导出／导入后解码逐字节重建，安装版使用 `-I -S` 且所有模块来自独立安装目录。

MP4／GIF 为有损预览；FFV1／PCM 用于精确断言。静态审查只覆盖收据列出的 PNG，未连续播放或听审。完整 CLI 的 1080p 输入另为实际移动的 FFmpeg testsrc2 与合成声音，所有成片帧 PTS 已核对；其速度测量不含自然素材质量或声音等价的验收。

## 5. 保留的限制与开发路径

当前 C 内核绑定 Windows amd64，本地 FFmpeg 需支持 frei0r；其他平台的默认回退仍可能很慢。最终 DLL 的滤镜吞吐超过 30fps，只接受该有限测试条件。**完整 CLI 的校验、编码和合成耗时必须另看；目前未接受实时编辑／实时预览。**

下一步先按实际工程分解编译、解码、合成与编码时间，再设计帧预览缓存、按需区间渲染、seek／取消／内存检查及可能的原生 GPU 后端。保持可迁移作者数据、本地替代、明确失败和原许可追踪。自然色彩、肤色、HDR、长片稳定性和全部剪映功能／效果差异继续按总验收矩阵推进。

## 6. 一次真实 CLI 的有界 Python 诊断

[profile-r1](evidence/native-hsl-20261020-v77/profile-r1/verification.json) 另外执行一次 60 帧强度动画渲染，保留原始 pstats、stdout／stderr、实际渲染清单与源冻结摘要。该次墙钟约 10.848 秒；`main` 之前的导入不在 profiler 内，Python profiler 会扰动计时，因此它**不参与前面的三次重复 fps 基准**。

该次 `compile_native` 累积约 1.794 秒，其中本地 FFmpeg `file_fingerprint` 约 1.617 秒；`build_filter_graph` 约 1.808 秒，`validate_project` 约 0.749 秒。`run_process`／`communicate` 等等待路径约 5.2 秒。线程和嵌套函数的累计时间相互重叠，不能相加或据此给出独立 CPU 百分比；FFmpeg 子进程在 Python profiler 内是黑箱，尚未分解其解码、滤镜、合成与编码。

这说明仍有可测的进程启动／校验／运行时指纹成本。后续评估同进程队列复用身份探测和局部渲染缓存时，必须保留内容完整性检查；不能用文件名／大小替代 SHA-256，或删掉校验来宣称性能目标已达成。涉及实际 FFmpeg 阶段的归因，另取原生测量后再决定。
