# VACE 本地权重读取与原生访问冲突约束 v0.1

2026-10-19 V66 扩图的两次实际执行在文本加载阶段发生 Windows `torch_cpu.dll / 0xc0000005`，偏移均为 `0x8e4a279`，没有生成帧；原事件、PID、报告 ID 和回滚收据分别保留。此约束于台北时间 2026-10-20 补充，在生产读取修改与新一轮实际模型执行之前发布。

上游有[相似问题报告](https://github.com/Comfy-Org/ComfyUI/issues/15424)，[safetensors 官方 API](https://huggingface.co/docs/safetensors/api/torch)提供 `backend="pread"`。它们只支持候选方案的来源，不能直接证明本机崩溃同因，也不能代替实际权重/模型验证。

| 编号 | 实现和验收约束 |
|---|---|
| VWR-01 | 保留原生 Windows Python、既有完整 17 文件约 19.04 GB 权重、模型 SHA、bfloat16/float32 精度、CUDA 分阶段准入及网络关闭。不更换权重、量化、降低分辨率/步数或停止别的任务来绕过失败 |
| VWR-02 | 在隔离 worker 的组件加载调用内，显式选择 safetensors 原生 `pread` 后端。只允许固定模型的文本 3 分片、transformer 2 分片及 VAE 1 文件；拒绝目录外、其它组件和非 PyTorch 格式。使用已验证的原生 reader 返回值，不自制张量反序列化器 |
| VWR-03 | Transformers 的局部 `safe_open` 引用和 safetensors.torch 的引用仅在该调用内替换，成功、原生 API 拒绝、组件加载异常均恢复；不编辑共享 D 盘依赖，不使用 sitecustomize、安装钩子、服务或虚拟环境。已有其它别名替换时拒绝，避免叠加未知包装 |
| VWR-04 | 不支持 `backend` 的旧依赖必须明确失败，不能静默重试 mmap、pickle、全文件 bytes 读取、云服务或其它模型。原 `local_files_only`、safetensors、dtype、device_map、max_memory 和严格权重加载信息完整保留 |
| VWR-05 | 正式模型响应增加三组件读取证据：后端、完整六文件清单、每文件打开次数；父进程验证组件唯一、后端确为 pread、完整且不重复的已知文件及整数计数。缺失、少片、冒用 mmap 等报告拒绝并回滚。读取次数不是张量数，也不代表实际峰值 RAM |
| VWR-06 | 已有完整性散列和 Windows 只读锁不减少；旧 adapter 的实现摘要不再匹配时须用新 ID 正式登记。不把新代码摘要写入旧登记记录冒充原环境。预先声明的扩图生成区 PSNR ≥30 dB 保持不变 |
| VWR-07 | 先做协议检查，再用原输入、提示词、seed、30 步、5/2 窗口、harmonic、256×160 画幅和整数放置完成实际 VACE 前向；独立核对全部原 RGBA、帧 PTS、立体声 PCM、包交换与片段组重绑定。协议模拟不计实际加载/推理 |
| VWR-08 | 源码修改后重新冻结、执行相关专项、完整回归及原生离线发行检查；历史 1454 项和失败模型执行绑定各自封存源码，不与新版本混计。开发与安装模型执行分别统计，安装版未实际执行 VACE 则明确未验收 |
| VWR-09 | 单次改后成功仅表明本机受控案例可交付；没有原生崩溃转储栈、重复压力与跨设备对照时，不能宣称底层根因已完全确认或永久解决。结构/纹理/时序、自然广告素材、长片、HDR 和完整剪映等价继续独立验收 |

现有 LaMa 与 VACE 的能力、失败、生成区画质和商业许可分别报告。候选代码/协议收据不升级为产品通过；执行版本和最终结果见[扩图约束](本地视频扩图与原画面保护契约_v0.1_2026-10-19.md)及其关联实测报告。
