## 1. 作者语义

`subtitle.style.fontcolor`、`bordercolor`、`shadowcolor`、`boxcolor` 的颜色与透明度分别生效。先画背景框，再画阴影、描边、字面；透明字面允许下面的描边、阴影和框透出。阴影使用原生描边后的字形，与已有 `borderw` 语义一致。透明度为 0 的组件保留几何约束但不产生可见覆盖；不会用不透明普通文字垫底后再叠加活动色。

`word_timing` 继续从两份相同完整排版选择普通/激活文字，`active_color` 可以有独立透明度。选择后才应用文字淡入、图层 opacity、已有变换、蒙版和混合路径。旧版高亮范围、原作者时钟和多行基线约束继续见[原生排版契约](./逐字高亮原生排版与颜色选择契约_v0.1_2026-10-16.md)和[字幕时钟契约](./嵌套字幕与文字动画时钟契约_v0.1_2026-10-16.md)。逐词与文字动画的联合调度尚未完整实现，不能忽略已有 warning。

示例：

```json
{
  "text": "LOCAL COLOR",
  "style": {
    "font_asset_id": "local_font",
    "fontsize": 48,
    "fontcolor": "0x4080c0@0.5",
    "borderw": 3,
    "bordercolor": "white@0.6",
    "shadowx": 8,
    "shadowy": 7,
    "shadowcolor": "black@0.5",
    "box": true,
    "boxcolor": "0x2040ff@0.35"
  },
  "animation": {"type": "fade_in", "duration": 1.0}
}
```

颜色 `@0.5` 通过本地 FFmpeg 解析为 8-bit alpha 127；显式 `@0x80` 或 `0xRRGGBB80` 为 128。这一量化差异保留，不把二者强行视为相同。文字颜色 alpha、淡入进度、图层 opacity 相乘，各应用一次。

## 2. 独立覆盖率与合成

每个启用的组件使用相同本地字体、相同文本和原生布局选项，在不透明黑底上以不透明白色测出覆盖率。其他组件只将颜色设为透明，仍保留 borderw、shadow 偏移、box 尺寸、对齐和 fix_bounds 等几何参数，避免改变实际字形位置或剪切范围。

令组件覆盖率为 `c`，作者颜色为 `C`，颜色 alpha 为 `A`，都归一化到 0–1。该组件的 alpha 为 `a=c*A`，与下面组件按 source-over 合成：

```text
P_out = C*a + P_under*(1-a)
alpha_out = a + alpha_under*(1-a)
straight_RGB = P_out/alpha_out       (alpha_out > 0)
```

产品组件输出使用 straight RGBA。独立/内嵌固定栅格文字不再依赖整张原生 drawtext 半透明结果的反预乘来猜测颜色。所有组件合并后，动画与图层透明度只缩放最终 alpha。背景视频仍通过现有 source-over 合成，不把文字样式的 alpha 写进底片的原始 alpha。

当前在 **8-bit 编码 RGB** 中合成，有组件级整数取整与最终 RGB/YUV 往返误差；没有宣称线性光、HDR、超低 alpha 的高精度富色或跨 FFmpeg 构建二进制一致。空间重采样仍遵循[透明重采样契约](./透明素材重采样与文字Alpha契约_v0.2_2026-10-16.md)。

绘制顺序和原生阴影形状可参照 [FFmpeg 官方 n8.0 drawtext 源码](https://github.com/FFmpeg/FFmpeg/blob/n8.0/libavfilter/vf_drawtext.c)以及[本地来源快照](../../sources/upstream/ffmpeg/libavfilter/vf_drawtext.c)。这些是原理参考；验收直接运行并指纹绑定本机 FFmpeg 8.1。

## 3. 本地颜色解析和证据

本地 FFmpeg 的颜色滤镜在 2×2 RGBA 探针上解析名称、`0xRRGGBB[AA]`、`#RRGGBB[AA]` 和可选 `@alpha`。输入限于短颜色字面量，不作为 shell 或任意滤镜片段执行，不联网查询颜色。颜色缓存位于项目 `cache/text-colors/`，键包含协议、实际执行器 SHA-256 和颜色原文；缓存写入采用原子 JSON。

manifest 的 `subtitle_time_mapping.text_paint` 记录：

- `engine=straight-component-source-over`；
- 每次整行/整段绘制的组件顺序、颜色原文、解析 RGBA、执行器指纹与缓存键；
- `coverage-times-color-alpha-once` 和 `working_color=encoded-rgb-8bit`；
- `linear_light_accepted=false`。

两份高亮画面使用独立内部图标签，同色普通/活动色仍可正确选择。该实现不更改作者 assets/settings/sequences 或原始 Rights Ledger；正常渲染产物登记另计。

## 4. 拒绝、降级和验收范围

| 情况 | 行为 |
|---|---|
| 非法颜色格式或本地 FFmpeg 不认识的颜色 | `SUBTITLE_COLOR_INVALID`，render 规划时拒绝 |
| `random` / `bikeshed` 随机颜色 | `SUBTITLE_COLOR_NONDETERMINISTIC`，要求明确颜色 |
| 颜色探针未给出一致 2×2 RGBA | `SUBTITLE_COLOR_PROBE_FAILED` |
| 动态尺寸片段内嵌文字 | 保留既有原生路径，显式 `subtitle_inline_dynamic_color` 近似 warning；颜色 alpha 未验收 |
| 动态内嵌动画 alpha / 逐词高亮 | 既有降级继续保留，不因新颜色路径自动转为通过 |
| 外部 ASS/SRT/libass 文字 | 使用原路径，颜色/透明度需独立验收；本契约不推进其状态 |
| 复杂字簇、RTL、逐词+动画、定格/VFR/群组 | 继续原限制，不因单项颜色修复关闭 |

没有新增顶层 CLI 参数，也不引入 GUI、模型、闭源服务或在线素材。真实成片需以普通不透明覆盖率对照、独立 source-over 数值、编码像素、原片/音频、来源许可与摘要分别核验。旧版本、开发失败、当前专项、完整回归和真实调用分别计数。

## 5. 位置表达式和当前实测入口

组件掩码会独立求值原生位置选项；随机/有状态位置组合没有完成本轮验收，不把固定及已有纯时间表达式样例推广到所有 x/y 表达式。逐词/多行仍执行原有位置表达式拒绝规则。当前受控颜色验收见[九组正式成片、15 项专项与完整 506 项回归](../validation/文字颜色透明度与实际合成实测_2026-10-16.md)，公开旧版失败及首轮回归失败全部保留。
