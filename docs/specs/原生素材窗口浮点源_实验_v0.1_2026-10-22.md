本契约约束 `float_native_pipe.NativePipe` 和 `float_native_source.NativeSurfaceSource`。它们把已登记本地视频或静态图片按原始时间戳提供给 Float32 时间线；不再要求先写出整片 Float32 帧包。当前为库层接入，标准 `render`、`preview`、`queue` 和缓存入口尚未接入，完整剪映功能及效果等价尚未达成。

| 编号 | 必须满足的行为 | 约束与拒绝条件 |
|---|---|---|
| NW01 | 原始资产绑定 | 只接受 video/image、本地路径及登记 SHA-256；远程引用按既有策略拒绝；实际源哈希不符拒绝打开 |
| NW02 | 生命周期读锁 | 原生 Windows 独立读句柄禁止写入和删除，覆盖源、工具、实现及持久化索引；两源关闭顺序互不影响 |
| NW03 | 原始帧时钟 | 复用既有 native-video-index-v1，严格递增 int64 PTS、原生 time_base、末帧 duration；索引上限 100 万帧 |
| NW04 | 容器起点 | 使用明确的解复用 start_time；未知须由调用者指定；已知起点不允许被矛盾覆盖 |
| NW05 | VFR 区间 | 按原生 PTS 持续到下一个 PTS，正向/反向半开边界延续 TimedSurfaceSource；不按平均 FPS 重建时钟 |
| NW06 | 末帧 EOF | 末帧原生 duration 未知时拒绝推测 EOF，不以平均 FPS 补帧 |
| NW07 | 显式颜色 | 原始/工作 ColorSignal 均须指定；视频 bt709 标签不自动决定 OETF/EOTF；不据此验收 HDR、ICC、PQ、HLG 或绝对亮度 |
| NW08 | 原生 RGB/灰度 | 使用既有纯像素适配器保持支持的 8–16 位及浮点值；禁止隐式降为 RGB8 |
| NW09 | 原生 YCbCr | 调用者明确矩阵、量程、色度位置及 progressive；读取原始字节后在浮点域转换，不先经过整数 RGB |
| NW10 | JPEG 字节布局 | yuvj 只作为等布局标签映射到对应 yuv 格式；仍要求调用者显式 full 量程；该分支未纳入本轮 JPEG 实片验收 |
| NW11 | 隔行源 | 额外关键帧探测读取 field_order；已知隔行拒绝；unknown 不是自动验证逐行，仍记录调用者假设 |
| NW12 | 显示几何 | 关闭自动旋转，保留原始 raster；记录原有 SAR/display matrix。上层标准渲染仍需正确应用显示几何或明确拒绝 |
| NW13 | 关键帧定位 | 额外 ffprobe 只保留 key_frame=1 的原生 PTS，须属于完整索引且递增；无已知可用关键帧时从头解码 |
| NW14 | Seek 精度 | 输入 seek 使用容器相对起点，向较早微秒取整；copyts、原生 PTS trim、passthrough 及 +原生格式保持边界；实际 B 帧跳读需与全片解码对照 |
| NW15 | 像素窗口 | 配置 1–256 帧、最多 256 MiB 缓存；根据实际 Float32 单帧字节数缩小窗口；不足一帧即拒绝 |
| NW16 | 拥有帧副本 | 每次返回独立连续 H×W×4 Float32；调用者修改或保留结果不污染缓存；独立 alpha 不参与 RGB 色彩转换 |
| NW17 | 原生管道 | stdout 队列最多 4×64 KiB，stderr 最多 2×64 KiB；逐帧读取，一次 raw 读取最多 512 MiB；这不是完整进程 RSS 上限 |
| NW18 | 输出完整性 | 局部窗口必须交付准确原生帧数及字节数，完整消费 EOF 并确认进程成功；不足、多余、非零退出拒绝该窗口 |
| NW19 | 取消和超时 | 每次原生操作 0–3600 秒内的显式预算；传播取消标记；真实阻塞读取和满队列退出均须回收自有进程/线程 |
| NW20 | 资源清理 | 正常、异常、取消均释放自身帧缓存、读锁和管道；不终止其他作业或浏览器进程 |
| NW21 | 元数据有界 | 最多保留最近 64 个窗口收据，同时记录累计次数和滚动 SHA；不无限保存整片命令列表 |
| NW22 | 索引复用 | 支持同工程/取消/持久化配置的 IndexContext；持久化沿用既有工程写锁约束；此类索引只有时钟，不存像素 |
| NW23 | 性能解释 | 记录前置关键帧逻辑距离，不冒充实际解码工作量；固定窗口反向跳读长 GOP 仍可能重复前滚，不承诺 O(N) 或实时 |
| NW24 | 证据 | 分别保留针对性测试、全新隔离安装、原片/实际 MP4/GIF/PCM、失败及全量收据；不合并计数，不用技术样例冒充自然广告验收 |
| NW25 | 下一步标准入口 | 经统一 validate/rights/manifest/queue/cache 路径构造来源与音频计划；补齐颜色输出、SAR/方向、全部作者效果及音频 stretch，之后才能逐项迁移默认渲染 |

本轮实际结果见[实测报告](../validation/原生素材窗口解码与浮点音画合成实测_2026-10-22.md)。该来源既不提供 AI 推理模型，也不复用任何闭源剪辑程序；离线依赖安装仍使用已有固定 SHA 的 8 个 wheel，禁止 Docker、WSL、容器或虚拟环境。

标准入口迁移还必须处理以下依赖，不能将本库完成当作默认渲染完成：

| 编号 | 接入工作 | 必须形成的验收结果 |
|---|---|---|
| NW26 | 明确项目色彩契约 | schema/CLI 明确每资产传递解释、工作基色、输出传递和越界策略；项目、续跑及队列指纹绑定这些设置；不从单一标签猜测 |
| NW27 | 共用执行入口 | 在现有 render_project/validate/rights/operations/manifest/queue 路径构造来源与音频计划；不允许外部任意音频filter graph绕开项目验证 |
| NW28 | 全作者操作迁移 | 转场、文字、字幕、蒙版羽化、变速、嵌套、全部效果与本地模型输出逐项支持；支持矩阵完整前明确拒绝不支持项，不能静默降精度 |
| NW29 | 编码及几何 | 除实验FFV1外，补齐正式8/10位输出、独立alpha、颜色标签/实际转换一致性；正确处理SAR、旋转/display matrix |
| NW30 | 长片及调度 | 既有素材导入仍有2GiB/2小时限制；需单独设计及验证。缓存预算、多个并行来源、索引、解码工作区及全部作业RSS分别限额；长GOP正向复用/倒放分块策略必须实测 |
| NW31 | 预览与一致性 | render、preview、queue、resume、manifest/cache使用相同内核和时钟；实际自然素材、长片、声音及HDR等专项验收不能由本轮程序生成样例代替 |
