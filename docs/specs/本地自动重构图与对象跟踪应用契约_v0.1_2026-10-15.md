# 本地自动重构图与对象跟踪应用契约 v0.1

| 项目 | 内容 |
|---|---|
| 文档编号 | SPEC-REFRAME-001 |
| 版本 | 0.1.0 |
| 日期 | 2026-10-15 |
| 状态 | 有效 |
| 关联命令 | `media adapter`、`media track`、`media reframe` |
| 运行边界 | 原生 Windows、FFmpeg、Pillow/numpy；网络关闭 |

## 1. 目标

`media reframe` 把本地模板跟踪，或已登记 `command-json-tracking-v1` 视觉 runner 返回的主体中心和尺寸，转换为目标画幅的动态归一化裁切。它是 Agent 可审计的自动重构图基础：先生成跟踪与裁切计划，再由 Agent 选择只报告或写入片段。它不调用云端视觉 API、私有剪辑运行时或在线素材服务。

当前实现使用目标画幅下可合法采样的最大裁切窗口，并跟随主体中心移动。主体框在目标窗口内无法完整容纳时，计划保留确定性窗口并写入 `tracked_subject_exceeds_target_crop_window`，要求人工复核；系统不会偷偷改变画幅或把越界采样当作成功。

## 2. CLI

```powershell
python -X utf8 -m ai_ad_editor media reframe `
  --project .\work\demo `
  --asset-id asset_video `
  --adapter-id tracker_local `
  --roi 0.20,0.20,0.20,0.35 `
  --clip-id talking_head `
  --track-id track_video_1 `
  --target-width 1080 `
  --target-height 1920 `
  --margin 0.12 `
  --dry-run
```

省略 `--target-width/--target-height` 时使用项目画布；也可以用 `--target-aspect` 显式覆盖目标宽高比。`--asset-id` 与 `--input` 必须二选一，`--clip-id` 和 `--track-id` 必须明确指定，避免把轨迹写入错误片段。

## 3. 计划字段

| 字段 | 语义 |
|---|---|
| `engine` | 模板轨迹使用 `local-reframe-from-template-track-v1`；视觉 runner 记录 `command-json-tracking-v1` |
| `source_aspect` / `target_aspect` | 源视频和目标画布的像素宽高比 |
| `crop` | 归一化 `x/y/width/height`、`fit` 和静态起始值 |
| `keyframes[]` | `crop.x`、`crop.y`、`crop.width`、`crop.height` 的片段局部 tick 关键帧 |
| `frames` | 可用跟踪帧数量 |
| `clipped_frame_count` | 主体安全框超出目标窗口的帧数 |
| `warnings[]` | 低置信度、主体越界或模板跟踪漂移边界 |
| `source_sha256` | 本地媒体输入哈希 |
| `adapter_id` | 可选的已登记视觉适配器；其模型/执行器哈希和协议见视觉适配器契约 |

计划中的时间均使用片段局部时钟。自动应用默认从片段 `source_in_tick/source_out_tick` 推导跟踪范围，并把关键帧写回片段的 `keyframes` 和 `crop` 对象。

## 4. 应用与拒绝

- `--dry-run` 只返回输入、目标画幅和执行计划，不创建快照或写回项目；
- `--apply` 在 `before-reframe` 快照后写入动态裁切，执行 schema/语义校验，保存操作 ID、报告和 provenance；
- 当前只接受直接媒体、常速、正向片段；嵌套序列、倒放、`speed_curve` 或无法解析的 speed 返回 `REFRAME_NESTED_UNSUPPORTED` 或 `REFRAME_TIME_MAPPING_UNSUPPORTED`；
- 源文件必须是项目内可读的本地视频资产；输出报告必须位于项目目录；
- 目标画幅、ROI、margin、fit 和所有裁切关键帧在保存前校验，禁止越出归一化范围；
- 跟踪置信度和主体裁切边界必须保留在报告中，不能把近似跟踪描述成模型级稳定跟踪。
- `--adapter-id` 只有在 `media adapter inspect` 返回 `verification.ok=true` 时才可执行；协议校验通过仍会返回 `TRACKING_EXTERNAL_REVIEW`。

## 5. Agent 交付门禁

1. 先执行 `--dry-run` 或生成报告，检查 `source_sha256`、目标画幅、`clipped_frame_count` 和 `warnings`；
2. 应用后检查 `before_snapshot`、`validation`、操作记录以及四条 `crop.*` 关键帧轨道；
3. 使用 `render --dry-run` 确认动态裁切滤镜图，再实际渲染目标画幅；
4. 使用 `quality check` 检查画布、时长、黑帧和音画同步，并人工抽样确认主体没有被切出画面；
5. 若主体发生遮挡、尺度突变或镜头切换，必须重新选择 ROI、缩短跟踪范围或改用已登记的本地模型适配器。
