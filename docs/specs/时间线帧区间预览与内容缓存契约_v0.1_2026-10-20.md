# 时间线帧区间预览与内容缓存契约 v0.1

V78 将 OpenFilm R12 的区间预览建议接到既有 Agent Project。执行器为新写的 Python `agent-timeline-preview-v1`，继续调用现有 `build_filter_graph`；没有复制 Studio、另建 HTML 工程格式或接入云 provider。研究来源和取舍见 [R12](../OpenFilm_0.2.3增量复用与开发成本评估_2026-10-20.md)。实际发布状态以 [核验报告](../validation/时间线帧区间预览与离线发行实测_2026-10-20.md) 为准。

## CLI 与产物

安装入口示例：`C:/Python313/python.exe -I -S -B -X utf8 <installed>/run.py <command>`。全部命令使用本地工程；`--sequence-id` 省略时沿用默认序列。

| 编号 | 命令 | 契约 |
|---|---|---|
| PV78-01 | `preview frame --project <dir> --frame 5` | 输出从 0 开始的第 5 个显示帧 PNG；不是原素材缩略图 |
| PV78-02 | `preview range --project <dir> --start-frame 3 --end-frame 15` | 输出半开区间 `[3,15)`；同时生成 `master.nut`、`preview.mp4`、`preview.json` |
| PV78-03 | 上述命令加 `--height 144 --budget-mib 512 --output previews/review-a` | 最大高度，合成后按比例缩小、不放大，尺寸向偶数取整；输出须为项目内缓存以外的新目录。绝对路径同样必须在项目内 |
| PV78-04 | 上述命令加 `--dry-run` | 验证工程、资源内容和缓存身份，返回计划；不编译作者图、不创建预览目录。SHA 检查仍会读磁盘 |
| PV78-05 | 上述命令加 `--cancel-file <project-local-marker>` | 已存在或执行中出现的 marker 取消本次请求；标记不能位于预览输出或缓存中 |
| PV78-06 | `preview cache-list --project <dir>` | 列出项目 `cache/timeline-previews` 内条目和字节量 |
| PV78-07 | `preview cache-prune --project <dir> --keep-mib 0 [--dry-run]` | 按目录时间淘汰至保留预算；先遍历核对所有待清理路径；保护当前工程明确引用的缓存素材 |

省略 `--output` 返回可淘汰缓存路径。需要长期保留的结果应显式导出到新目录。PNG 为 RGBA；NUT 为 FFV1 BGRA 与 48 kHz 立体声 float32 PCM。MP4 为 H.264/AAC、有损且不透明的观看副本；GIF 是另行制作的文档演示。透明参考只保留作者图实际具有的 Alpha：默认不透明工程不会因预览而自动恢复素材透明。

## 作者时钟与完整语义

先编译完整作者序列，在 `[vout]` 后按显示帧号截取，在 `[aout]` 后按 PCM 样本截取。因此保留原关键帧相位、嵌套、转场、调整区间、速度映射和作者音频上下文。没有以预览起点重建新序列，也没有在输入上提前 seek。

显示帧率为有理数 `f=num/den`，作者时长为 `D=duration_tick/ticks_per_second`。合法输出帧数为 `ceil(D*f)`。区间 `[s,e)` 的音频范围为 `[ceil(s*48000/f), min(ceil(e*48000/f),ceil(D*48000)))`，末帧可能不足完整一帧时长。视频 PTS 从 0 重置，音频按累计样本重新排布。真正解码检查所有视频帧、音频样本总数及每个 PTS，容差限为容器的一个对应 time-base tick。

先将完整图输出物化为与完整无损参考相同的 BGRA，再按需 Lanczos 缩小。尺寸相同则省略 scale。把 YUV→RGB 与缩放混在一起会改变色度插值；不能放宽像素阈值来掩盖差异。

## 内容身份与命中

- 工程身份复用现有作者规范化，排除 outputs、操作日志和更新时间；包含作者轨道、设置和序列 ID。请求的空间预算是操作参数，不作为画面身份。
- 对工程内可发现的文件、素材、内联字幕实际选用字体、LUT/登记表、权利账本、Python/FFmpeg/FFprobe/Pillow 运行资源、包内脚本/C/DLL计算完整 SHA-256，保留字节量与实际路径。当前身份较保守，未使用素材的变更也可能失效；不承诺最小依赖增量计算。
- 编译后补入实际输入、图元数据和当前验证锁观察到的派生依赖；记录命令、有效请求、警告和输出摘要。原生 HSL 后端设置也是身份的一部分。
- 直接 LUT 的 `path/file/lut` 三种兼容字段与派生元数据 `lut_uri` 均进入依赖收集；相同大小和 mtime 的 CUBE 内容替换必须重新渲染。发布前的真实像素测试曾复现遗漏 `lut` 的旧命中，修复及原失败均留存。
- 每次命中重新验证依赖、收据和所有输出字节；命中不再编译作者图或运行 FFmpeg。路径、大小和 mtime 相同但内容不同必须失效；上游 R12 的这类 key 不进入运行时。
- 外部 ASS/SRT 字体回退、不封闭媒体容器、随机表达式/噪声效果仍可经现有图渲染，但不复用缓存。损坏收据或产物明确拒绝，用户可显式清理后重建。
- 最终 key 是完整收据载荷 SHA，预览收据上限 8 MiB；源/运行时依赖和派生依赖分别最多 4096 个文件。缓存命中仍有全内容校验成本，不等于实时或零成本。

## 原子性、清理与空间边界

普通 CLI 持有现有工程写锁和事务；源码/运行资源在原生 Windows 验证作用域中持有禁止写入/删除的读取句柄。预览先写独立 `.tmp-preview_*` 目录，通过校验后原子发布；导出再写目标同级临时目录，复核后重命名。不覆盖任何现有输出目录。失败或取消清理本次临时目录。若完整缓存已经发布，而后续导出复制失败或取消，可保留完整缓存，但不发布不完整导出。

预览不更改 `project.json`，不登记最终 outputs、不改变权利或模型执行事实；成功操作可写既有操作记录。预览 manifest 的 `quality_accepted` 和 `model_inference_proven_by_preview` 均为 false。工程包传作者结构与资产，在目的工程重建预览，不把缓存命中冒充新的模型推理或正式交付。

高度参数为 64..2160 的偶数，预算 8..8192 MiB，单请求最多 3600 帧，缓存最多 256 条。空间准入使用 RGBA/PCM 的保守预留、磁盘剩余量和实际产物量，必要时先淘汰旧条目；受工程引用保护的缓存不足以释放空间时拒绝。此预算约束预览产物及副本，不是整个进程的硬内存/磁盘配额：完整作者图的 HTML、音频拉伸等衍生任务仍走各自已有预算。删除前检查未解析路径的所有分量，拒绝符号链接和 Windows junction；不跟随链接遍历或删除外部文件。

当前是软件离线预览；即使作者设置包含硬件偏好，本命令也不承诺执行 GPU 编解码。从作者起点累计解码，深处单帧可能很慢；没有播放 GUI、后台预览服务器、快速随机 seek、交互延迟保证或实时验收。前次中断留下的临时条目可用显式 prune 清理。

## 验收与来源

定向测试验证完整图参考的逐帧 RGBA、完整 PCM、NTSC 末端、透明、嵌套倒放、调整层、同大小/mtime 内容失效、损坏拒绝、取消/复制失败清理、引用保护和 Windows junction；真实 CLI、离线平台 wheel、包重放及完整回归单独计数。成片连续播放、声音听审、自然素材质量、HDR、实时性能和完整剪映等价仍需各自验收。

额外的两组上下文实测覆盖跨剪切点 xfade、显式登记的本地 Rubber Band R3 0.5 倍速及 100 ms 真实源上下文。完整参考实际先执行音频衍生任务，再独立渲染完整图；开发与同一隔离安装分别对比全部 RGBA、PCM、命中与工程包重放。这些额外 CLI 检查不新增 unittest 方法，也不把外部已登记 R3 程序误称为 wheel 内新附带的资源。

本实现没有移植 OpenFilm 缓存源码；借鉴研究中记录的任务形态和测试场景。任何将来复制的 MIT 源码须保留固定版本许可。组件参数 CP-01..06 和开放 NLE 交换适配器继续按原设计独立推进，不能由本次预览完成推断其已经实现。
