## 3. 已发现并修复的问题

### 3.1 移动后的链接失效

历史报告中的若干链接仍指向移动前的根目录，例如纯开源评估、video-recap 补充评估和本地 Skill 指南。已统一改为 `docs/` 下的绝对路径；研究目录和原始快照路径保持原样。

### 3.2 “有目标”但没有“机器契约”

原基线已经要求项目 JSON、错误码、任务状态、转换报告和 Rights Ledger，但缺少字段、状态、幂等、迁移和失败规则。新增规范分别落在：

- [Agent Project JSON 规范](./specs/AgentProjectJSON规范_v0.1_2026-10-13.md)
- [Agent Project JSON 机器 schema](./specs/agent-project.schema.json)
- [Agent CLI 契约](./specs/AgentCLI契约_v0.1_2026-10-13.md)
- [Rights Ledger 与素材模板登记规范](./specs/RightsLedger与素材模板登记规范_v0.1_2026-10-13.md)
- [项目转换报告规范](./specs/项目转换报告规范_v0.1_2026-10-13.md)

### 3.3 “质量门禁”缺少固定输入

原基线列出了黑帧、音画同步、字幕、响度和关键帧要求，但没有规定用什么样例、什么阈值、产出什么证据。新增 [P0 黄金样例与验收计划](./validation/P0黄金样例与验收计划_v0.1_2026-10-13.md)，把文档门禁转为可执行测试计划。

### 3.4 架构层级缺少依赖方向

原基线的七层架构能够说明职责，但没有规定 GUI、Agent、编排层、媒体引擎、适配器和权利模块之间谁可以调用谁。新增 [系统边界与模块契约](./architecture/系统边界与模块契约_v0.1_2026-10-13.md)，并明确 Concat 只是可替换的媒体/时间线后端候选。

### 3.5 版本和证据没有发布门禁

研究报告记录了仓库提交和 Star 快照，但没有形成统一的依赖锁定、许可证、SBOM、升级和回滚流程。新增 [版本、依赖与发布门禁](./ops/版本依赖与发布门禁_v0.1_2026-10-13.md)。
