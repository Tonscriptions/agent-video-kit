## 1. 目标与引擎选择

补足自动人脸局部锚点、肤部平滑、局部曝光、脸颊收缩和眼部放大的本地基础。
使用原生 Windows Python、CPU ONNX Runtime、OpenCV、NumPy 和现有 FFmpeg；
不使用剪映、Docker、WSL、摄像头、UDP、服务端、运行时安装或下载。

OpenSeeFace 固定源码 `50c09741897010faad721a218b2bbe14ecad6251`，
仅取作者的检测模型 `mnv3_detection_opt.onnx`、66 点模型 `lm_model3_opt.onnx`
及其预处理/热力图和偏移解码约定。保留 BSD-2-Clause LICENSE 和修改说明。
不执行作者的 GUI、摄像头、UDP、RetinaFace、视线或个体身份识别入口。
作者说明代码和模型采用 BSD-2-Clause；训练数据与地标用途限制另行记录，
不将 66 点拟合误称为精确皮肤分割、478 点网格、身份或真实三维几何。

已检查 MediaPipe 1.1.1 官方 Windows wheel，SHA-256
`a4b27829e808cd659e7cf481cbbbfc31917092a1ebcb7eafed2395dbabcd2499`。
其 DLL 包含 Clearcut 客户端和 `https://play.googleapis.com/log`，
此 SDK 未执行、不接入产品；Python socket 钩子不能证明原生 DLL 没有出网。

## 2. 登记、输入和扫描

`face adapter register/list/inspect` 登记两个现有本地 ONNX、原生 Python、
证据、线程上限和实现闭包哈希；权利登记默认未核验/仅内部用途。
不覆盖已有 ID。模型不允许外部张量、未知自定义 ONNX 算子、本地函数、pickle 或远程路径。
作者的优化模型使用 ORT 内置 `com.microsoft::FusedConv`，仅白名单允许该内置算子；
不登记或装载外部内核库，其它自定义域/算子仍拒绝。
只运行 CPUExecutionProvider，并关闭 ORT telemetry。模型、媒体和工具执行前后复核。

`face scan` 接收已登记图片或完整 CFR 视频及显式适配器、输出、最多帧数、
最多人脸、检测/地标阈值和切点。源需方形像素、零起始 PTS、零旋转；
不静默旋转、缩放、丢帧、插帧或回退到其它模型。视频不超过 60 fps/600 秒，
扫描不超过 1800 帧/4 张脸、单帧不超过 2073600 像素，报告上限 32 MiB。
只接受已支持的 8 bit SDR 像素格式；HDR/高位深拒绝，不静默压成 8 bit。
曝光分别按 sRGB、BT.709、gamma 2.2/2.8 传递函数计算并记录输出标签；
源未声明传递函数时明确警告并记录假设 sRGB，不能称已识别真实色彩空间。
计划在执行前计入报告/数组预算；超限要求显式分段。

逐帧执行检测和每个候选的地标推理，保留实际 forward 次数、原始帧号、
独立 ffprobe 核实的 PTS、检测分数、66 个 (x,y,confidence) 和检测缺失。
置信度不是校准的准确率。缺失帧不复制前帧地标。传入切点清空关联；
关联只表示短时几何接近，不表示同一人。跨切点不继承人脸 ID。
原始检测每帧执行，不把手工锚点或复用结果计入模型推理数。

## 3. 局部修饰

`face retouch` 使用已核验且来源未变的完整逐帧报告，显式选择检测到的所有脸
或指定轨迹 ID；默认不美颜。四项强度全部为零时，输出全部解码 RGBA 必须逐样本相同。

| 控制 | 取值 | 方法与范围 |
| --- | --- | --- |
| skin-smooth | 0..1 | 7 像素双边滤波，在地标皮肤候选内混合；排除眼、眉、嘴、鼻孔附近 |
| exposure-ev | -1..1 | 依显式来源传递函数转线性后的局部曝光，使用同一候选软蒙版 |
| face-slim | 0..1 | 两侧脸颊的有界、紧支撑反向位移，不是身体塑形 |
| eye-enlarge | 0..1 | 两眼周围紧支撑反向径向采样，最大局部放大约 20% |

这些是明确的几何/滤波基础，不包含生成式美妆、美肤模型、磨皮质量验收、
身体塑形、发型、换脸、真实补光或全部剪映美颜预设。
局部几何作用范围外 RGB 必须与原输入逐样本相同；任何修饰都逐样本保留原 Alpha。
几何蒙版由地标近似，不能承诺遮挡、镜片、头发、胡须或眼睑边界自然正确。
无人脸帧不修改。相邻/重叠脸按稳定 ID 顺序执行并明确报告，不静默挑选主角。

输出使用 FFV1 RGBA 无损中间件，保留全部视频帧/PTS 和原音频 PCM；
任何预览 MP4 的有损差异不替代中间件逐样本检查。
源音频、色彩标签、帧时基和有向旋转等不支持的情况必须显式拒绝或说明，
不能用一张 PNG 或零音轨样例证明视频/音频功能已经通过。

## 4. 保存、事务和重放

输出保存标准资产、源/模型权利父链、完整已用地标、控制参数、来源 SHA 和实现版本。
地标报告是可编辑的确定性数据，不能改写后继续沿用旧签名或旧推理证据。
保存配方可以在原始来源 SHA 相同且权利完整时显式重放，不重新下载或运行模型。
历史 source ID 是来源记录；片段复用不会据此自动复制原片或权重。

所有命令沿用项目锁、幂等键、dry-run、JSON 信封、快照和元数据事务；
失败、取消或超时不登记半成品。仅回收本次所有的原生子进程，保留实际错误。
执行超时通过拥有的 Job Object 结束本次进程树，不能假设 Python 级检查会中断原生算子。

## 5. 验收

1. 坐标/偏移解码以固定作者源码和真实模型输出对照；检验 RGB/BGR、x/y、边界裁剪。
2. 实际 CPU 模型推理须有已许可输入、实际 forward 数、原始输出和完整来源哈希。
3. 逐帧验证原 Alpha、作用范围外 RGB、零强度 RGBA、CFR/PTS、原音轨 PCM。
4. 负例包括坏输出、缺失脸、切点、多脸、源变更、模型/实现变更、超限、取消和超时。
5. 开发态和隔离安装态分别运行；单元协议测试、真实推理、静态抽帧、连续播放与声音检查分开。
6. README 编号表、实际 MP4/GIF、源/输出/模型哈希和失败边界随发布同步；
   只有完成的项可标通过，不能用通过数或一个人像推导剪映等价。
