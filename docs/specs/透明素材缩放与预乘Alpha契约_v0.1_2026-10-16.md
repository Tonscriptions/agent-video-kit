# 透明素材缩放与预乘 Alpha 契约

| 字段 | 内容 |
|---|---|
| 文档版本 | v0.1 |
| 状态 | 有效 |
| 日期 | 2026-10-16 |
| 范围 | 本地 FFmpeg 媒体适配、图层缩放和独立文字标量缩放 |

## 1. 问题和结果

透明 PNG/MOV 的透明像素仍可含任意 RGB。直接对 straight RGBA 四通道分别插值，会把不可见颜色混入可见边缘，产生黑边、绿边和细线发暗。该缺陷能改变最终编码标签的可检测范围，即使轨迹和 bbox 坐标完全正确。

本地渲染器对具有 alpha 的素材，在每次普通 `scale` 前转换 `gbrapf32le`，执行 `premultiply=inplace=1`；缩放后执行 `unpremultiply=inplace=1`，返回 straight `rgba` 再进入后续效果和合成。保持浮点中间值，减少低 alpha 在整数乘除中的损失。不存在新增云端服务、下载、GUI 或模型调用。

## 2. 应用边界

| 编号 | 路径 | 当前行为 |
|---|---|---|
| A01 | PNG、RGBA/BGRA/ARGB/ABGR、YUVA、GBRAP、YA、pal8 | 根据已登记探测的像素格式保守识别 alpha；不要求新增用户参数 |
| A02 | 普通 `crop.fit=fit/fill/stretch` 的素材适配 | 对缩放操作预乘/反预乘；fit 的补边继续透明，opaque 素材原有黑色补边不变 |
| A03 | 图层静态/关键帧标量 scale | 非仿射路径的 scale 使用相同处理；时间线、位置表达式和锚点不变 |
| A04 | 独立文字图层标量 scale | 透明文字画布使用同一处理；旋转或持久绑定触发的仿射路径另行验收 |
| A05 | 输出和效果 | 缩放返回 straight RGBA，继续由既有蒙版、opacity、转场、效果和编码器消费 |

`geq` 仿射旋转/重采样、动态尺寸 crop 的逆采样、扭曲和一般效果滤镜未在此增量中统一为预乘采样。不得将 A02/A03 的结果推及这些路径。静态 crop 本身不插值，其后的普通适配在范围内。

## 3. 核验要求

1. 构造 alpha 完全相同、非零 alpha 处 RGB 完全相同、仅零 alpha 隐藏 RGB 不同的两份素材。
2. 通过正式 CLI 渲染同一项目、同一参数，独立解码所有帧比较 RGB。受控 PNG 三种适配、动态 scale、QTRLE/ARGB MOV 和调色板 PNG 必须无隐藏 RGB 可见影响。
3. 独立检查真实编码标签位置，沿用原 3 px 门槛，不因渲染成功或中心观测正确而免除画面检查。
4. 保留基线原实现的实际输出、失败日志、源码摘要及修复后的输出，不用当前程序绘制或伪造“旧效果”。公开素材具备原输入、SHA-256、时钟、来源和复现脚本。

## 4. 质量和性能限制

浮点 RGB 运算仍沿用输入编码域，没有转换为线性光；不构成完整色彩管理、HDR 或光学正确缩放。小标签细线会受输出 4:2:0 采样、压缩和背景影响，单一阈值也不能证明整体视觉质量。每个浮点中间画面为四个 32-bit 通道，缓冲开销高于 8-bit RGBA；没有据此声明 1080p/4K 性能达标，FFmpeg 总内存和长期吞吐需要独立测量。

自然蒙版的漏选、跟踪身份和遮挡质量不由此修复。模型/人物素材许可和发布门禁继续按原台账执行。见[真实实测](../validation/透明素材缩放边缘与标签精度实测_2026-10-16.md)和[蒙版锚定契约](./本地分割蒙版轨迹与锚定契约_v0.1_2026-10-16.md)。
