# OpenFilm 新增提交与复用结论更新

**结论：继续按模块复用 OpenFilm；这次新增内容不会显著降低当前 CLI 的开发量。** 高价值字幕、HTML 动效、字段编辑、缓存、诊断和编码器探测已有适配。还可按需求拆取开放工程交换模块，或在建设自有 Agent 宿主时拆图片上下文预算函数。

本页是 R15 增量研究，承接 [R14 完整模块与成本清单](OpenFilm可拆模块与现有内核降本清单_2026-10-21.md)。不将既有适配重复列为新功能，不以源码阅读或历史测试宣称剪映等价。

| 优先级 | 拆用对象 | 当前收益与预算 |
|---|---|---|
| 1 | 已有 HTML / 字幕 / 模板字段 / 缓存 / 诊断 / 编码器适配 | 继续利用原实现与上游失败夹具；不重复移植和计费 |
| 2 | `studio/server/nle.mjs` 的轨道、素材和烘焙规划，以及对应 XML writer | 明确新增开放交换目标后实施；限定生产化 **8–15 人日**，含作者 tick / 混合帧率 / 效果损失报告和目标程序实际验证。已有 OTIO / MLT 的缺口优先在原适配器修复 |
| 3 | `apps/desktop/src/pi-config.mjs` 的 `fitImages` | 仅自有可控 Agent 消息管线有收益；限定生产化 **2–4 人日**。不能直接裁减外部 Codex 的会话历史，完整宿主开发另计 |
| 不纳入 | Studio / Electron、云 provider、上述新增 GUI 修复 | 不补齐离线 AI 算法，也不能代替抠像、人像、光流、修复、HDR 和自然素材效果验收 |

预算是规划估计，承接 R14，未增加这次 3 个 GUI 提交的“节省工时”。MIT 复制仍须保留归属；字体、模板、模型和资源单独核权。主线继续为 Agent → 本地 CLI → Agent Project → FFmpeg / 已登记离线模型 / 受控 HTML。
