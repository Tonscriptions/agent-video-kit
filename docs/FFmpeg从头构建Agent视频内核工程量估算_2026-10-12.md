# 基于 FFmpeg 从头构建 Agent 视频编辑内核：工程量估算


| 文档编号 | EST-2026-10-001 |
|---|---|
| 状态 | 评审中 |
| 本次审计复核 | 2026-10-13 |
| 证据性质 | 工程量估算；需按真实拆分任务校准 |
核查日期：2026-10-12。目标是原生 Windows、无 GUI、仅通过 CLI/JSON 供 Agent 调用，使用 FFmpeg 作为媒体编解码与渲染基础，禁止剪映、剪映 SDK、Docker 和 WSL。

这里的“人月”指 1 名全职工程师约 1 个月的有效开发量。下面是架构评估用的区间，不是报价或交付承诺；并行开发不能简单把人月除以人数，集成、回归素材、模型兼容和发布仍会形成关键路径。

## 先给结论

如果“所有功能内核”指常见剪映式广告制作能力，但排除 GUI、账号、云协作、素材商城和移动端，建议按 **200–350 人月** 规划。一个 10–14 人团队的现实日历周期约为 **18–30 个月**，前提是使用现成的开源 AI 模型和第三方库，并持续做 Windows 渲染回归。

如果把剪映当前的 AI 生成视频、数字人/口型、换脸、模板和素材生态也算进去，首期会扩大到 **300–500+ 人月**，而且需要持续的模型、模板、编码器和素材维护，不能给出一个“一次做完”的终点。

如果只要一个可执行的 Agent CLI 剪辑内核，第一阶段可以控制在 **25–45 人月**；但它只能覆盖剪辑、合成、关键帧、字幕、音频和导出，不能称为完整剪映替代品。

## FFmpeg 已经提供什么

FFmpeg 官方组件覆盖编解码、封装/解封装、协议、缩放、音频重采样、滤镜和 `ffprobe`；`libavcodec`、`libavformat`、`libavfilter`、`libswscale`、`libswresample` 可作为程序内核使用。官方滤镜文档也覆盖裁切、缩放、叠加、混合、遮罩、`drawtext`、字幕、调色、速度、音量、混音、降噪和响度等基础操作。

这些能力相当于“渲染积木”。FFmpeg 本身没有剪映式的非破坏工程模型、素材库、时间线编辑语义、撤销/修订、模板参数系统、Agent 计划协议、视觉质量验收或完整的 AI 创作产品层。不能把一条复杂 `filter_complex` 命令当成可长期编辑的工程格式。

依据：[FFmpeg 官方文档](https://ffmpeg.org/documentation.html)、[FFmpeg 滤镜文档](https://ffmpeg.org/ffmpeg-filters.html)、[FFmpeg 许可说明](https://ffmpeg.org/legal.html)。具体发行版的许可取决于启用的组件和外部库，需要固定构建选项并保存 SBOM/许可证记录。

## 目标分层

| 级别 | 覆盖范围 | 估算人月 | 建议团队与日历周期 | 能否称为剪映替代 |
|---|---|---:|---|---|
| P0 验证原型 | 探测、裁切、拼接、叠加、字幕、单次导出、JSON 输入 | 8–15 | 2–3 人，2–4 个月 | 不能，只能证明技术路线 |
| P1 Agent CLI 核心 | 多轨时间线、可编辑 JSON、关键帧、转场、基础效果、音频、字幕、预览、渲染、QC | 25–45 | 3–5 人，5–8 个月 | 只能覆盖基础剪辑 |
| P2 广告生产版 | P1 + 本地 ASR/TTS/VLM、抠像、追踪、模板、品牌预设、批量版本、缓存和回滚 | 70–120 | 6–8 人，10–16 个月 | 可覆盖常见广告流程，但不是全功能 |
| P3 开源“剪映式”功能内核 | P2 + 高覆盖效果/转场/文字动画、速度曲线、蒙版、跟踪、调色、混音、资产系统、插件系统、稳定 Windows 发布 | 200–350 | 10–14 人，18–30 个月 | 接近常见本地制作能力，仍需样片证明 |
| P4 当前剪映功能面 | P3 + 生成视频/图像、数字人、口型、换脸、更多模型路由、模板/素材生态 | 300–500+ | 长期产品团队 | 不能把“完成”定义为一次性交付 |

P3 是本项目最有意义的目标：保留 CLI/Agent 形态，完成本地可编辑、可批量、可复现的广告制作核心，同时不承担 GUI、云协作、账号体系、支付和在线素材商城。

## P3 的模块拆解

下面的区间已经包含工程设计、实现、接口文档和基本回归；视觉模板的持续创作与模型训练不完全包含在内。

| 模块 | 主要工作 | 人月区间 |
|---|---|---:|
| 项目模型与 Agent 契约 | 版本化 `project.json`、资源引用、帧/时间基、事务、撤销/重做、幂等 CLI、JSONL/JSON-RPC、错误码 | 15–25 |
| 媒体接入与渲染运行时 | `ffprobe` 索引、VFR/CFR、代理文件、缓存、临时文件、filtergraph 编译、预览/最终渲染、硬件编码、崩溃恢复 | 20–35 |
| 时间线与编辑语义 | 多轨、链接音视频、切分、ripple、嵌套/组合、转场重叠、冻结帧、变速、源区间映射 | 25–45 |
| 关键帧与效果系统 | 位置、缩放、旋转、透明度、裁切、混合、蒙版、速度曲线、参数插值、效果注册表、预设版本 | 30–50 |
| 字幕、文字与模板 | SRT/ASS、逐字/逐词动画、字体 fallback、中文排版、花字、品牌模板、变量绑定、透明层导出 | 18–32 |
| 音频内核 | 多轨混音、BGM ducking、响度、降噪、变调、音频关键帧、对白保护、波形/静音分析 | 12–22 |
| 本地 AI 能力 | Whisper/ASR、VLM 选段、镜头检测、TTS、抠像、物体/人脸追踪、自动重构图、质量检测和模型适配器 | 35–65 |
| 资产、批量和模板运行 | 素材清单、哈希、代理、字体/音乐许可记录、批量变量、队列、失败重试、结果归档、可重建工程 | 18–30 |
| Windows 发布与质量工程 | 原生安装/升级、FFmpeg 构建、GPU/CPU 矩阵、长视频回归、音画同步、黑帧/冻结帧、字幕截图差异、安全沙箱 | 20–35 |
| **合计** | 集成时要留出跨模块联调和返工 | **193–339** |

因此将 P3 规划成 200–350 人月，而不是把表格下限当成承诺。

## CLI 不需要 GUI，但必须保留这些 Agent 反馈

无 GUI 并不等于只接受一条命令后输出 MP4。Agent 需要可检查、可重复的反馈面：

```text
video-engine probe   --input raw/clip.mp4 --json
video-engine ingest  --project project.json --input raw/clip.mp4
video-engine plan    --project project.json --out plan.json
video-engine apply   --project project.json --patch edit.patch.json
video-engine preview --project project.json --frames 0,30,60 --contact-sheet out.png
video-engine render  --project project.json --preset vertical-1080p --out final.mp4
video-engine qc      --project project.json --media final.mp4 --report qc.json
video-engine revert  --project project.json --revision 17
```

每一步都要能输出结构化 JSON：工程修订、输入素材哈希、实际时间线、生成的 filtergraph 摘要、渲染日志、模型版本、字幕文件、音量指标和 QC 结果。Agent 通过联系表、关键帧截图、波形摘要和错误定位做下一轮修改；不需要 GUI，但不能没有可审查的视觉证据。

## 推荐技术结构

```text
Agent
  ↓ JSON/JSONL CLI（后续可包一层 MCP）
Canonical Project IR（帧准确时间线、轨道、关键帧、模板变量、资源哈希）
  ↓ 验证器 + filtergraph/compiler
FFmpeg/libavformat + libavcodec + libavfilter + swscale/swresample
  ↓
预览/缓存/最终渲染/QC/可重建产物
  ↘ ASR/VLM/TTS/抠像/追踪模型适配器
```

建议使用独立的 Canonical Project IR；OpenTimelineIO 可以作为交换格式，但不应把 OTIO 或 FFmpeg filtergraph 当成全部产品状态。Agent 编辑、模板变量和渲染计划必须保留项目自己的稳定版本。

核心实现建议以 Rust 或 C++ 调用 FFmpeg 库，CLI 层可以提供 PowerShell/JSONL 友好的入口。直接为每个请求拼接一次 FFmpeg 子进程适合 P0/P1 原型；P2 以后需要统一时间基、图编译、缓存和可恢复作业，否则复杂转场、变速和多次修改会快速失控。

## 最容易低估的部分

1. **时间线不是拼接命令。** VFR、音频采样、转场重叠、变速后的源区间、字幕时间和不同时间基会同时影响结果。
2. **关键帧不是只有位置和缩放。** 剪映式效果还要有曲线、蒙版、文字动画、速度、音频和效果参数的统一插值协议。
3. **AI 不是调用模型就结束。** 每个模型都需要帧坐标映射、置信度、失败回退、缓存、显存/CPU 路由、许可证记录和结果 QC。
4. **模板是产品工程。** 真正可用的广告模板要定义安全区、字体、商品变量、画幅变换、镜头约束、默认音量和 CTA 规则。
5. **CLI 仍需要预览。** Agent 没有 GUI 时，contact sheet、关键帧图、波形、字幕截图和 QC 报告就是审片界面。
6. **Windows 发布会成为持续工作。** 编码器、字体、GPU 驱动、路径、长文件名、进程取消和临时文件都需要持续回归。

## 关键范围边界

以下内容不应混入“P3 已完成”的承诺：

- CapCut 的在线账号、云协作、模板商城、素材库、推荐系统和商业服务；
- 专有闭源生成模型、专有数字人/换脸模型和未知授权的声音/素材；
- 移动端实时预览、手机硬件适配和所有平台编码器矩阵；
- 通过 FFmpeg 能调用某个滤镜，就宣称已经具有剪映同等级的交互或 AI 效果；
- 只生成 MP4、无法重开和修改的“一次性脚本”。

CapCut 官方当前功能页面把自动字幕、文本转语音、背景移除、运动追踪、脚本转视频、模板和 AI 视频生成都列为产品能力，因此“所有功能”的范围远大于裁切、拼接和几个滤镜。[CapCut AI 工具](https://www.capcut.com/tools/ai-tools)、[视频编辑能力](https://www.capcut.com/tools/video-editing-software)、[运动追踪](https://www.capcut.com/tools/motion-tracking)、[文本转视频](https://www.capcut.com/tools/text-to-video-ai)。

## 建议的实施顺序

第一阶段先做 P1：稳定的 JSON 项目模型、探测/素材哈希、两条视频轨和两条音频轨、裁切/拼接/转场、6 个运动预设、字幕、基础混音、预览联系表、MP4 渲染和 QC。这个阶段的目标是验证时间线和 Agent 契约，而不是堆 AI 功能。

第二阶段做 P2：接 Whisper、开源 TTS、镜头检测、抠像、追踪和模板变量，建立 15 秒竖屏电商广告与 30 秒中文解说广告回归集。

第三阶段做 P3：扩展效果/转场/文字动画、批量变量、资产许可、GPU/CPU 路由、模型注册表、可恢复队列、工程重建和 Windows 发布。

只有 P1/P2 样片和工程重开稳定后，才值得继续投入 P3；否则最后会得到很多滤镜适配，却没有一个可被 Agent 可靠修改的编辑内核。

## 本项目的实际建议

如果目标是尽快验证业务，先采用现有 Shotcut-MCP 或 Kdenlive-MCP 作为参照，不要立刻投入完整 P3。从 FFmpeg 自研的价值在于拥有统一的 Agent Project IR、确定性渲染、跨后端适配和长期可控的模板系统；它不是因为 FFmpeg 本身缺少滤镜，而是因为需要把滤镜编排成一个可编辑、可验证、可批量的产品内核。

这份估算没有安装候选程序、没有启动虚拟化环境，也没有把 GUI 工作量混入核心估算。
