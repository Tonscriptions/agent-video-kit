# VACE 前窗生成上下文与连续输出契约 v0.1

状态：V68 CLI、协议及发行完成限定核验；真实 VACE 条件画质和自然质量未验收。完整目标继续是无 GUI、原生本地、面向 Agent 的剪映功能与效果对标；本契约只约束其中的跨窗口生成连续性，不能代替自然结构和画质验收。

## 已确认的问题与来源

当前 `vace_frames.py` 给每个联合窗口重新抹除选区 RGB，再独立推理，最后按重叠权重混合。它没有把前窗生成内容交给后窗模型。V66 的 8 帧扩画布案例以两个 5 帧窗口执行，生成区 19.227695 dB，低于事先 30 dB 门槛；桌沿变形及时间差异仍存在。V67 的诊断改善了故障留证，没有改善这份画质。

2026-10-20 查阅 [VACE 作者指南](https://github.com/ali-vilab/VACE/blob/main/UserGuide.md)：保留条件对应黑色 mask，缺失内容为 RGB 127、白色 mask；作者对长片建议分段并用先前 clip 作为延续条件。此处借用条件语义，使用已经登记的本地 Diffusers VACE，保持现有权重、运行环境和网络阻断；不运行作者 GUI 或线上服务。

## 生成与输出语义

| 编号 | 约束 |
|---|---|
| VTC-01 | `media inpaint` 和 `media outpaint` 新增显式 `--temporal-context previous`；默认及显式 `none` 保持旧独立窗口参数、采样和输出。LaMa 拒绝该 VACE 专属参数。 |
| VTC-02 | previous 要求窗口重叠大于零。沿用现有帧范围、4k+1 尾帧填充、窗口 seed、原文提示词、步数、guidance、conditioning、flow shift 和输入倍率，不自动修改它们。 |
| VTC-03 | 后窗重叠前缀使用同源、同一场景、同一全局帧上已经实际输出的 RGBA。只以该帧原选区内的生成 RGB 替换被抹除内容，将这些已知条件的 mask 改成黑色；选区外继续使用原源 RGB。未来帧及新场景不能提供条件。 |
| VTC-04 | 新生成帧仍在缩放前和缩放后擦除原选区 RGB，防止待移除对象颜色通过重采样泄漏。前窗生成内容是预测条件，不是真值、独立观测或新拍摄素材。 |
| VTC-05 | previous 按窗口实际新增的帧连续输出一次。已经输出的重叠前缀保留原结果，后窗重新解码出的前缀不覆盖它；不把逐窗混合称为全片联合注意力。 |
| VTC-06 | 输出仍完整保留输入 Alpha、选区外 RGB、作者 PTS 和原音频。harmonic/feather 在新帧正式输出时执行；后窗条件来自这份实际合成并量化后的结果。扩图的完整原矩形保护继续适用。 |
| VTC-07 | 场景切点清空前窗上下文。全空选区旁路模型；如果窗口仅有已知前缀、所有新增帧都无选区，也无需启动推理。取消、超时、坏输出或异常继续回滚，并按 V67 留证。 |

## 存储、身份与协议

| 编号 | 约束 |
|---|---|
| VTC-08 | 只保留供下一窗口使用的已输出重叠帧，最多 `window_overlap` 帧 RGBA uint8。规划时在旧 owned-array 上界之外增加 `width × height × 4 × window_overlap` 字节；这不是 Torch/模型/RSS 或显存保证。预算不足在读取帧或载入模型前拒绝。 |
| VTC-09 | 报告模式、实际使用的上下文帧/选区像素、窗口数、上下文峰值帧数/字节、场景清空及输入摘要。原源 SHA 与生成条件身份分别保存，固定长度摘要绑定所有实际模型调用，明细最多保留首 16 窗。 |
| VTC-10 | 控制器构造的最终模型 RGB/mask 身份应与模型调用侧实际收到的数组身份一致；缺失或不符不能登记资产。协议模拟不能冒充真模型执行，摘要相同也不证明画质。 |
| VTC-11 | 配方、工程包和片段组保留该模式及全部生成参数，权利依赖继续包括原媒体、mask、模型；不能把模型生成条件登记成独立可用的真实素材来源。实现改变必须重新登记 adapter。 |

扩图沿用完整的 `source.outpainting` 配方。修复的已编码资产新增 `source.vace_generation`，保存 canonical generation 并按输出帧范围校验；工程包和片段组保留参数，原 source/mask 仍由 `source.derived_from` 记录历史来源 ID。修复的历史 ID 不是新工程中的可执行引用；跨项目复用按现有片段组规则重新绑定权利依赖，不因此复制原 source/mask 或模型权重。它是已执行采样的可追溯记录；再次推理需要显式提供源、mask 和当前有效 adapter，不在导入、复用或播放时自动启动模型。

## 预先声明的验收

| 编号 | 检查 | 判定边界 |
|---|---|---|
| VTC-T01 | 两窗、极高重叠、移动选区、部分 Alpha、尾帧填充 | 逐帧身份无重复/遗漏；已输出前缀不变；实际条件为前窗正式输出，未来帧不可见。 |
| VTC-T02 | 被移除内容颜色负对照、缩放及倍率 | 原待移除 RGB 不泄漏；只允许明确的生成上下文进入已知条件；坐标回映射及原区域保护独立检查。 |
| VTC-T03 | 切点、空窗口、无新选区、预算、无效参数、取消和坏报告 | 不跨场景、不多调用模型、不读超预算帧、不登记半成品；保留原错误与诊断。 |
| VTC-T04 | none 默认兼容 | 同一个受控输入和模型回调下，旧实现与新 none 的完整输出字节一致；通过数不代替这种内容对照。 |
| VTC-T05 | 当前 V66 扩画布输入的真实模型对照 | 固定同一 source、prompt、seed、30 steps、window/overlap、输入倍率及 blend，仅改变模式；全部原 RGBA/PTS/PCM 精确保留。生成区沿用 ≥30 dB，时间残差独立报告；失败继续保留。 |
| VTC-T06 | 原有自然素材的私有对照或有公开权利的新素材 | 检查对象残影、结构、接缝与运动；未确认发布许可的原画面和输出仅留本地。自然效果不得用程序化 PSNR 替代。 |
| VTC-T07 | 发行与 Agent 调用 | 专项与完整回归、当前源码冻结、原生离线安装、CLI、配方往返及 Skills 同步；README 给编号表、原视频/GIF及失败限制。 |

结构误生成可能在前窗上下文中继续传播；减少跨窗重生成不等于重建正确结构。不会降低 V66 的门槛、替换失败真值、自动换引擎或停止其它 GPU 任务来获得通过。
