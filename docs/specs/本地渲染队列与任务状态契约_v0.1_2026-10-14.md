## 1. 目的和边界

渲染队列为 Agent 提供项目内、可重启、可审计的多版本本地渲染入口。队列使用 `operations/render-queue.json` 保存作业状态，执行时顺序调用既有 FFmpeg 渲染器；不启动服务、守护进程、数据库、Docker、WSL、容器或网络任务。它解决的是批量成片、失败后显式重试和取消请求的状态持久化，不宣称分布式调度或多机并发。

队列作业与项目时间线解耦：作业只引用序列 ID、输出规格和项目内输出路径；素材、权利和效果能力仍由项目校验、Rights Ledger、效果目录和 `render` 统一约束。

## 2. 文件和作业结构

项目创建后，队列文件按需生成：

```text
<project>/
├─ operations/
│  ├─ render-queue.json
│  ├─ project-write.lock
│  └─ queue-cancel/<job_id>.cancel
└─ renders/
   └─ queue_<job_id>.<container>
```

队列顶层字段为 `queue_version`、`project_id`、`created_at`、`updated_at` 和 `jobs[]`。每个作业至少包含：

| 字段 | 约束 |
|---|---|
| `job_id` | 字母、数字、下划线或连字符；队列内唯一 |
| `sequence_id` | 可选；省略时使用主序列 |
| `output` | 项目根目录内相对路径；省略时按作业 ID生成 `renders/queue_<id>.<ext>` |
| `container` | `mp4`、`webm` 或 `mkv` |
| `profile` | `vertical`、`square`、`landscape`、`vertical_720`、`landscape_720` 或 `custom` |
| `width`/`height` | 成对出现；`custom` 必填，且必须为合法偶数画布 |
| 编码字段 | 可选的 `video_codec`、`audio_codec`、`crf`、`video_bitrate`、`audio_bitrate`、`pixel_format`，沿用 `render` 白名单；WebM 未指定时默认 VP9 + Opus |
| `publish` | 为 `true` 时执行严格 Rights Ledger 门禁 |
| 运行字段 | `status`、`attempts`、`operation_id`、`cancel_requested`、`errors[]`、`warnings[]` 由 CLI 管理 |

输入可以是单个作业对象，也可以是 `{ "jobs": [ ... ] }`。未知字段不会拼接到 shell 命令；所有路径和编码参数都经过现有项目/FFmpeg 校验。

## 3. 状态机

```text
pending ──queue.run──> running ──成功──> succeeded
   │                       │
   └─queue.cancel──> cancelled  └─取消标记/FFmpeg──> cancelled
                           └─错误──> failed
failed/cancelled ──指定 --job-id 重试──> running
```

- `queue run` 无 `--job-id` 时只取 `pending` 作业，可用 `--max-jobs` 限制本次数量。
- pending 作业上的取消标记优先于启动请求；`failed` 和 `cancelled` 只能通过显式 `queue run --job-id ID` 重试，重试会清理旧取消标记，避免 Agent 无意中重复发布成片，同时保留新到达的取消请求。
- 项目写入命令（包括 `queue run`）持有 `operations/project-write.lock`，覆盖完整的队列读改写和渲染状态提交；冲突返回 `PROJECT_WRITE_LOCKED`、退出码 6、`retryable=true`。
- `queue cancel` 不等待该锁：pending 且锁空闲时立即提交 `cancelled`；锁被运行器占用或作业已 running 时原子写入项目内 `.cancel` 标记，并返回 `acknowledged=true, confirmed=false`。`queue list/inspect` 会从标记反映 `cancel_requested=true`，渲染器确认后写入 `cancelled`。
- `succeeded`、`failed`、`cancelled` 均保留错误、警告、尝试次数和对应 render 操作 ID；队列文件使用原子替换写入。

## 4. CLI 语义

```powershell
$env:PYTHONPATH = 'E:\dev\sandbox\AI广告剪辑\product\src'
python -m ai_ad_editor queue enqueue --project .\work\demo --input .\queue.json
python -m ai_ad_editor queue list --project .\work\demo
python -m ai_ad_editor queue inspect --project .\work\demo --job-id vertical-a
python -m ai_ad_editor queue run --project .\work\demo --max-jobs 2 --continue-on-error --progress jsonl
python -m ai_ad_editor queue cancel --project .\work\demo --job-id square-a
```

每个命令返回标准 JSON envelope。`queue.run` 的 `data.summary` 至少包含 `selected`、`succeeded`、`failed`、`cancelled` 和 `skipped`；单作业的 `operation_id` 指向现有 `render` 操作记录，队列批次另有一个 `queue.run` 操作记录。`--dry-run` 只解析输入、列出候选作业和输出路径，不创建队列、取消标记、媒体或操作记录。

## 5. 失败和恢复

渲染前会重新执行项目 schema、引用、效果和 Rights 校验；校验失败进入 `failed`，不创建最终媒体。FFmpeg 失败、取消和质量门禁结果沿用 `render` 的错误码和临时目录清理策略。Agent 应先用 `queue inspect` 读取状态，再决定是否显式重试；重新入队使用新 `job_id` 适合保留独立版本。

当前执行器为同一项目内的顺序单进程模型，适合本地 Agent 和 Windows 工作站。项目内合作 CLI 已使用原生 Windows 文件锁串行化写入；跨机器调度、优先级、公平性和远程 artifact 存储不属于本契约。跨文件断电恢复和孤立 running 作业恢复仍需独立故障契约；若后续增加并发 worker，必须先扩展锁与状态 CAS，并保持现有作业 JSON 向后兼容。
