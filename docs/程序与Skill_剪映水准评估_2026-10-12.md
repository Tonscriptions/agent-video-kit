评估日期：2026-10-12，Asia/Taipei。沿用 2026-10-11 的源码快照与 Star 核查，补查当前官方说明、问题区及本机剪映登记版本。目标是广告、混剪、关键帧与运镜预设；运行环境为原生 Windows。

**当前优先方案：剪映专业版 + JyWrapper 内嵌 pyJianYingDraft + 已安装的 `$video-cut-jianying-editor`，按需求加入 HyperFrames 动效素材。** 对能够正确写入草稿、资源可用且被客户端支持的操作，最终使用剪映原生渲染，具备达到剪映同类成片效果的直接路径。此判断是基于架构与源码；本机端到端效果尚未实测。

**若要求完整替代剪映，当前核查的开源程序 + 现成 Skill 尚无足够证据证明功能、效果库、AI 能力和稳定性全面相当。** Concat 是独立内核研发候选；HyperFrames/Remotion 可承担特定广告形式的独立制作；Lumen 更贴合命名运镜与 MCP 编辑，但需要独立验证。

## 怎样理解“剪映的水准”

| 目标 | 本次判断 |
|---|---|
| 做出视觉、字幕、节奏和音频合格的广告成片 | 剪映原生渲染方案最直接；HyperFrames/Remotion 也有实现定制广告动效的工具基础，效果取决于设计、素材与验收 |
| Agent 自动执行常用时间线编辑、推拉平移、字幕、特效 | JyWrapper 或 VectCutAPI 有实际接口；命名运镜配方、参数约定、错误恢复与视觉检查仍需组织 |
| 自动调用剪映完整特效、模板、AI 按钮并稳定无人值守导出 | 尚未核验到完整覆盖；新版草稿、资源与 UI 自动导出是实质限制 |
| 全开源、独立预览渲染并替代剪映完整编辑器 | 尚未验证达标；不能用 README 的定位或 Star 数量代替实机证明 |

分辨率、效果枚举数量和能写出 MP4，都不足以单独证明达到剪映水准。对本广告项目，中文文字质量、9:16 构图、预览与导出一致性、关键帧时间、混音和可修改项目同样影响交付。

## 候选体系比较

| 体系 | 实际程序与 Skill | 可实现的能力 | 当前关键缺口 | 选型判断 |
|---|---|---|---|---|
| 剪映原生制作 | 剪映专业版 + JyWrapper 内嵌 SDK + `$video-cut-jianying-editor` | 草稿多轨、字幕、已知特效/转场、位置缩放关键帧、Bezier 缓动；客户端预览与导出 | 本机 10.7 未测兼容；自动导出受版本影响；模板槽位替换有未实现方法；部分高级能力未被 API 覆盖 | **当前主生产路线的优先验证对象** |
| 剪映服务化制作 | 剪映专业版 + VectCutAPI + `vectcut-api` Skill | HTTP/MCP 调用，生成和保存草稿，批量素材/文本/关键帧参数 | 公开版本的云渲染和完整 Agent 应用未开源；最终原生效果仍依赖客户端；本地 Skill 尚未安装 | **需要多个 Agent 或服务接口时再增加** |
| 独立广告动效 | HyperFrames + 已装 `$video-cut-hyperframes` 系列；或 Remotion + 已装 `$video-cut-remotion-*` | 程序化动画、字幕排版、产品展示、转场、批量变量、独立渲染；有配套创作 Skills | 剪映草稿、专有素材与 AI 能力不是这些框架的原生格式；复杂影像处理需组件或外部工具 | **广告动效与模板化制作可用；优先作为主路线的素材组件** |
| 独立编辑内核 | Concat + 官方 `run-concat`；创作 Skill 待补 | 实际 CLI/JSON-RPC、可选 gRPC；时间线、关键帧、效果、模板、自身渲染 | 官方 Skill 主要负责开发运行；Windows 发布包存在维护者确认的问题；成熟度仍需验收 | **研发候选，暂不选作本机主要交付工具** |
| Agent 运镜编辑 | Lumen + 内置短视频/动效指导 + MCP | 已核验 `clip_animate`、音乐卡点、命令编辑和运镜指导；有独立项目与渲染路径 | 尚未注册本地 `$video-cut-` Skill；部分指导为内部 Markdown；长片、中文与复杂效果的交付质量未实测 | **命名运镜/MCP 专项验证候选** |

以上为选型判断，不是已经通过的渲染测试结果。JyWrapper 内嵌 SDK 有本地修改，和官方 PyPI 0.3.0 并非可无条件替换的同一个运行时；初次验证应固定一种实现。

## 优先方案的依据与边界

### 剪映 + JyWrapper + 现有 Skill

已装 `video-cut-jianying-editor` 为 1.7.0，来源 luoluoluo22，安装 commit 为 `32c56928ded4f9e2c2b80e099dc7abb793d2c30b`。它包含包装器与内嵌 SDK；不是只有自然语言提示词的空入口。

其 `auto_exporter.py` 实际调用 `JianyingController.export_draft`，依赖 Windows UI Automation。文档中的“headless”描述不能解释成独立、无需桌面剪映的渲染内核。README 说明 5.9 或更早版本最稳；官方 SDK 的导出矩阵对剪映 7+ 标记不支持。生成草稿成功不能据此推导 MP4 自动导出成功。

本机只读检查发现登记版本 **10.7.0.14076**，安装目录也有对应版本。官方 SDK 的新版矩阵自报 10.8 支持多项草稿操作，10.8 蒙版仍标记不支持；这份矩阵不能直接当作本机 10.7、现有内嵌 SDK 或全部 AI 功能的通过记录。

关键帧方面，底层接口与缓动扩展具备组织推近、拉远、横移和 Ken Burns 配方的基础。前次核查已发现 `rules/keyframes.md` 将绝对时间线时间传给片内相对时间 API；项目配方必须纠正此时间约定。当前存在接口和示例，不等于已拥有经过视觉验证的完整运镜预设库。

模板方面，`rules/core.md` 明确将语义槽位替换方法标为尚未实现。可以生成新草稿或克隆模板，但不能保证“任意剪映模板 → 智能换料 → 全保留效果”已开箱实现。

**判断：支持的操作正确进入草稿后，客户端原生渲染是与剪映效果一致的直接基础。自动化覆盖不足的地方，仍须通过客户端完成、添加适配或使用外部素材；Skill 不会自动增加内核没有暴露的能力。**

### VectCutAPI 增加的是接口编排能力

源码有实际 MCP 服务，关键帧、素材、字幕和草稿保存可以通过工具调用。它与 JyWrapper 的差别主要在服务接口和工作流，不能据此判断同一个剪映效果会自动变得更好。

中文 README 明确说明完整 MCP 剪辑 Agent、Web 客户端、云渲染模块尚未开源；这里不否定公开 `mcp_server.py` 的存在。本地开源部分应按“工具服务 + 草稿生成”评估，不把线上产品的全部能力算入本机交付。

初期使用一个草稿写入实现更容易定位版本、时间和资源问题。等主路线通过验收，再按服务化需求增加 VectCutAPI。

[公开接口与交付边界](https://github.com/sun-guannan/VectCutAPI/blob/main/README-zh.md)、[实际 MCP 服务](https://github.com/sun-guannan/VectCutAPI/blob/main/mcp_server.py)

### HyperFrames / Remotion 的适用范围

HyperFrames 使用 HTML/CSS/JavaScript 构建视频，具备逐帧渲染、音频混合、Studio 和动画组件。官方渲染说明提供本地运行路径，Docker 是可选路线；本项目只考虑原生本地渲染。现有 `$video-cut-hyperframes` 系列来自已下载的 OpenMontage 集成包，其文档与当前 HyperFrames CLI 仍需按版本匹配。

Remotion 提供 React 视频组合、动画、音频、字幕与渲染，官方提供 Agent Skills。两者都有制作定制广告动效的基础；达到什么视觉水平需要设计和样片检查，不能由框架名称保证。

建议先用其中一套制作片头、片尾或产品卖点动效，输出素材后加入剪映时间线。动效源码保持可修改，但预渲染成视频的内部文字、形状和动画不会自动成为剪映原生可编辑轨道。透明叠加还要验证目标编码与客户端支持。

HyperFrames 核心为 Apache-2.0；Remotion 程序的商业使用条件与 Skills 仓库许可不是同一个问题，具体见其官方条款。

[HyperFrames 程序](https://github.com/heygen-com/hyperframes)、[原生本地渲染与输出](https://github.com/heygen-com/hyperframes/blob/main/docs/guides/rendering.mdx)、[OpenMontage 集成](https://github.com/calesthio/OpenMontage)、[Remotion 与 Agent Skills](https://www.remotion.dev/docs)、[Remotion 条款入口](https://www.remotion.dev/docs/license)

## Concat：有真实内核，现阶段仍有交付障碍

Concat README 将其定位为 CapCut 替代品，并说明仍是 Beta。已读源码具备多轨、关键帧、效果包、项目编辑 API 和渲染模块；官方 `run-concat` Skill 是编译、启动与验证开发变更的说明，不是广告创作与运镜预设 Skill。

此次增加的问题区核查提供了具体依据：

| 官方记录 | 当前信息 | 对本项目的影响 |
|---|---|---|
| [#303：Windows x86_64 0.2.6 发布包](https://github.com/jub0t/concat/issues/303) | 维护者 10 月 11 日确认该版本发行二进制存在问题；页面仍开放 | 有 Windows 下载包不能推导本机可顺利启动；应验证修正后的发行包或原生构建 |
| [#278：Windows 文字质量](https://github.com/jub0t/concat/issues/278) | 主分支有修补，维护者仍要求在 Windows 100% 缩放下观察 | 主要是桌面文字渲染报告，不直接证明成片字幕有问题；仍需检查本机显示与最终输出 |
| [#255：非 16:9 导出](https://github.com/jub0t/concat/issues/255) | 原始报告是 0.2.5 的 4:3 导出；维护者称最新导出窗口已调整，尚无本次复现结论 | 不应声称当前版本一律无法竖屏导出；9:16 成片应列为验收项 |

这些是维护者与社区记录，本次未复现。判断依据是具体交付问题和缺少创作适配，不能简化为“开源程序不可能做出好视频”。MCP 的产品宣传与此前开发状态存在差异；此次重读 CLI 仍以 JSON-RPC/可选 gRPC 为已见接口，独立 MCP 接入仍需核验。

## Lumen 与其他方案的取舍

Lumen 对用户确认的“关键帧与运镜预设”很贴近：源码与内置指导涉及 `clip_animate`，README 列出 Ken Burns、推近、平移、弹入、滑入和卡点 punch；另有 MCP 与独立渲染路径。命名预设这一项值得优先做专项样片。

它当前约 7 Star，但 Star 少本身不能证明质量差；本次已有源码接口证据，仍缺本机输出、复杂项目和批量稳定性证明。内部短视频/动效指导不是已安装的本地 `$video-cut-` Skill，后续若引入需要按此命名规范整理。

Frontstage、FFmpeg/MCP 小型工作流和解说 Skills 可以满足专项需求；本次证据不足以把它们提升为完整剪映替代方案。macOS 原生专项项目与需要 Docker/WSL 的集成不符合本机运行范围，具体来源与许可见之前的检查报告。

[Lumen 程序与能力说明](https://github.com/Mas-inx/lumen-ai-video-editor)、[本地内置动效指导](E:/dev/sandbox/AI广告剪辑/research/agent-video-kernels/sources/Mas-inx__lumen-ai-video-editor/code/src/integrations/skills/motion-design-craft.md)

## AI 特效需要分别核验

| 能力 | 当前可据以评估的实现 | 尚不能承诺的内容 |
|---|---|---|
| 滤镜、转场、花字、发光等 | 草稿接口写入已知资源和参数，或 HyperFrames/Remotion 自定义视觉组件 | 草稿中有 ID 不保证本机资源已可用；不能推定完整剪映效果库均可自动调用 |
| 智能抠像、物体跟踪、蒙版跟随 | 独立模型、跟踪实现或客户端操作；Concat/Lumen 有部分相关代码 | 普通位置/缩放关键帧不等于自动识别或跟踪；SDK 色度抠图也不等于 AI 智能抠像 |
| 生成式画面、变形、补帧等 | 生成服务或本地模型产出素材，再进入时间线 | 未核验到上述 Skill 能开放调用剪映所有专有 AI 按钮；时序一致性与质量需另验 |

## 推荐的最小体系与验收门槛

主路线固定为 **剪映专业版 + 现有 JyWrapper + `$video-cut-jianying-editor`**；需要定制动效时加入 **HyperFrames + `$video-cut-hyperframes` 系列**。脚本、素材、参数配方、测试项目和成片均置于 `AI广告剪辑/`，客户端导入与导出按已验证流程完成。API 服务化作为主流程稳定后的扩展。

建议用相同素材和目标规格比较手工剪映基准与候选方案：

1. **基础广告**：30 秒 9:16，至少三段素材、中文标题/字幕、Logo、旁白与配乐；检查字幕清晰度、同步、裁切、声量和最终尺寸。
2. **运镜**：推近、拉远、横移和一次带缓动的强调；检查片内关键帧时间、起止位置、裁切边界、预览与 MP4 一致性。
3. **特效与修改**：一个转场、一个实际可用特效，保存后重新打开项目再改文案；检查素材、效果和可编辑性。
4. **批量与导出**：重复生成多条版本，确认时长、资源、导出结果与失败记录；仅在本机目标客户端通过后，才评定为可无人值守交付。

通过基础、运镜与特效样片，可以判定覆盖本项目的常用广告制作目标；通过批量与导出，才能判定自动化交付。高级 AI、复杂跟踪和完整模板生态须继续单项测试。上述门槛是建议，本次没有执行这些样片。
