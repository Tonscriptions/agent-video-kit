# 硬件编解码探测与显式回退契约 v0.1

本增量把 OpenFilm 固定 `f6a65ae54fa1c10ec482eeb84dc9ffa6ef33c4d8` 的 `packages/openfilm/src/encoders.mjs` 参数与短样本探测思路适配到现有 Python/FFmpeg 渲染、队列和 manifest，不引入上游 GUI、服务商、网络、Node 或新安装依赖。MIT 原文继续随包。软件默认链保持原样；这不是全平台硬件认证、画质等价或剪映等价验收。

| 编号 | 约束 |
|---|---|
| HA01 | `settings.acceleration` 为严格对象，可缺省/null；`encode`、`decode` 各为 `off/prefer/require`，默认 off。`encoder` 为 auto/nvenc/qsv/amf/mf，`decoder` 为 auto/d3d11va/cuda。仅原生 Windows 列出本轮候选，其他平台按 prefer 回退或 require 拒绝 |
| HA02 | `probe_max_bytes` 为 1 MiB..1 GiB 整数，默认 512 MiB，约束四帧未压缩像素工作量估计，**不声称约束驱动全部显存**。不停止其他 GPU 进程，不自动安装、下载、创建虚拟环境 |
| HA03 | 编码启用必须显式给 `settings.output.video.bitrate`（CLI `--video-bitrate`）；仍声明逻辑软件 codec，硬件参数由后端推导。不能把 CRF 跨厂商视为同质量。首版候选 H.264/HEVC/AV1/VP9 受实际后端支持限制；透明输出不进入硬件链，require 拒绝、prefer 留在既有软件路径 |
| HA04 | 编译列表不等于可用性。每次真实渲染用实际画布、帧率、目标像素格式、码率和色彩标签编码四帧，再 ffprobe 验证 codec/尺寸/像素格式/显式色彩标签；自动降位深/色度不得算成功。dry-run 不分配硬件、不启动探测 |
| HA05 | 只对实际视频文件输入探测解码；图片、音频、内联表面跳过。原始 YUV420 8/10-bit 的 H.264/HEVC/VP9/AV1/MPEG2 可尝试；其他格式、透明输入按模式拒绝/回退。不以 RGBA8 中转核验 10-bit |
| HA06 | CPU 四帧 framemd5 与强制硬件帧→hwdownload→原像素格式的四帧 MD5/字节数/时间戳对照；非空且相同才选用。正式图也强制硬件帧及 hwdownload，不允许 FFmpeg 悄悄用 CPU 却仍记为 GPU。首四帧一致不证明任意源文件整片一致 |
| HA07 | `prefer` 允许有限降级：硬编+硬解→同编码/软件解码→软件编码；`require` 对应轴永不降级。运行时只对明确的硬件/驱动/硬件滤镜错误重新尝试；取消、超时、进程启动失败、输入变化、IO/空间错误及输出质量失败终止。R3 音频只执行一次。每次失败和实际命令均留档，不覆盖旧输出 |
| HA08 | 源输入和项目依赖指纹在探测后、尝试前和发布前重验。成功后保留作者时钟、现有滤镜、结构质量与权利门禁，并额外验证编码 codec/尺寸/像素格式/显式色彩标签；质量错误不触发降级 |
| HA09 | 每操作 `renders/diagnostics/acceleration_<operation_id>/` 保存报告、完整已结束命令 stdout/stderr、SHA 和状态；该目录属于渲染副产物，不受作者元数据事务回滚，也不进入后续事务备份。取消/超时只能保留执行器提供的 stderr 尾部，明确标为 partial。manifest/失败 operation 引用此报告；实际后端与请求分别记录，设备为驱动默认、未认证 UUID |
| HA10 | CLI `--hardware-encode`、`--hardware-decode`、`--hardware-encoder`、`--hardware-decoder`、`--hardware-probe-mib` 覆盖当前渲染，不修改作者设置；队列接受对应下划线字段，resume 保留原设置并重新探测当前硬件，不复用可用性缓存 |
| HA11 | 编码器通过 NV12/P010 接受 4:2:0 的 8/10-bit 数据；这是输入内存布局，不是把声明的 yuv420p/yuv420p10le 输出降精度。最终帧使用 setparams 写色彩标签，H.264/HEVC 另写 H.273 码流标签，再核对流及解码帧；标签正确不等于视觉调色验收 |
| HA12 | manifest 的 `filter_complex` 保留逻辑合成图；实际 `command`/逐次执行日志还包含硬件解码、hwdownload 包装。`filter_graph_transport` 的 SHA 对应实际执行图，应从命令内联参数或引用的图文件核验；不能误用逻辑图去校验实际图的 hash。软件 off 时没有硬件包装 |

探测不是完整预览，硬件编码依然有损。本增量不迁移 CPU 滤镜到 GPU，不承诺固定提速、所有驱动与色彩配置可用，也不把单机合成视频的通过扩展为自然广告内容或完整剪映质量验收。后端不支持所要求的位深、色度、色彩标签时，应保留失败证据并按策略处理。
