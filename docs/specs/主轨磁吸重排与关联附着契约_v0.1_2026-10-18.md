# 主轨磁吸重排与关联附着契约

2026-10-18，V53；执行与实测前声明。引擎 `agent-main-track-reorder-v1`。继续采用原生 Windows、Python 标准库、整数 tick 与现有本地 FFmpeg，产品执行不访问网络，不调用 GUI、Node、模型、Docker 或 WSL。

本增量实现主轨整片段插入式重排与自动紧邻排列，保持完整作者内容。持久磁吸开关、屏幕距离吸附、任意拖拽手势及跨剪口同步内容的自动拆分仍属于完整目标中的其他工作，不用本增量取代全功能验收。

## 请求与确定性

```json
{"action":"reorder","clip_ids":["shot_c"],"before_clip_id":"shot_a","options":{"linked":true,"linkage":true}}
```

使用现有 `timeline edit --project <工程> --input <请求JSON> --dry-run`；正式执行省略 dry-run，并可使用 `--expected-project-sha256` 绑定计划。`timeline compose` 的 `linked_edit` 可以将请求放进同一原子批次。

| 编号 | 要求与预声明验收 |
|---|---|
| MR01 | `clip_ids` 是非空、无重复的主轨片段 ID；原主轨按开始 tick/ID 排序。多选保持原相对顺序，形成一个插入块。请求数组的顺序不重新定义源次序。 |
| MR02 | `before_clip_id` 必须显式给出：有效的剩余主轨 ID，或 `null` 表示末尾。目标落入关联扩展后的选择中则拒绝，不猜手势。未知字段、布尔/浮点 tick、无效 ID 和副轨目标均拒绝。 |
| MR03 | 主轨沿用 `sequence.editing.main_track_id`，否则选 order 最小的 video。重排后所有主轨片段从 0 开始紧邻排列；原开头/内部空隙移除，不裁切或覆盖镜头。原主轨有重叠则拒绝。所有加减使用整数，不量化为毫秒或显示帧。 |
| MR04 | 默认 `linked=true`，sync/linkage 沿用序列配置。选择扩展包含同 link_id 的主轨成员。所有被挤动主轨镜头的关联成员也跟随，不能仅移动显式选中的音轨。一个关联组要求相同位移；多个主轨成员所需位移冲突时明确拒绝，可先显式解除关联。 |
| MR05 | `linkage=true` 时，副轨短片段按原主轨宿主与原相对偏移移动；跨过多个剪口的长配乐、原主轨间隙中的片段保持锚定。非关联的锁定副轨保持不动；有实际位移的锁定关联成员导致整体拒绝。显式关联优先于推断的宿主。 |
| MR06 | `sync=true` 优先于 linkage，参与所有未锁且 sync_lock 未退出的副轨。整片段只在其覆盖的主镜头区间有同一位移时跟随；跨越不同位移或跨间隙的片段拒绝，不裁掉、伸缩或重排声音。主轨外尾部随末镜头，前置/无宿主片段保持锚定；显式关联不受 sync_lock 退出影响。 |
| MR07 | 负时间、主轨锁定、实际位移的锁定关联组均整体拒绝。冲突副轨沿用兼容处理轨道选择；普通音量复制，效果/闪避总线自动换轨仍拒绝，避免把不同总线声音称为保真。 |
| MR08 | 源 in/out、输出窗口、倒放/曲线/定格、关键帧、子序列、效果、模型/素材/字体权利引用保留。序列基准外置字幕的 offset 只按实际位移补偿；clip 基准与已保存作者窗口保持原作者时钟。重复重排不能重复漂移字幕。 |
| MR09 | 跟踪引用按现有轨道重新绑定；无法更新锁定依赖则拒绝。markers 保持绝对 tick。存活片段内容的允许差异只有位置、必要的字幕 offset、轨道引用和明确请求的转场移除，输出计划列出全部差异。 |
| MR10 | `transition_policy` 缺省 `preserve`，可显式为 `drop_broken`。真实源声明的画面/关联音频剪口和源句柄重新分析；保留的转场维持原端点。被拆开的声明默认拒绝；显式移除时列出 ID/原因，未受影响的声明保留。 |
| MR11 | 旧式跨片段 transition_in/out 不能悄悄换邻居或改变原邻居相对间距。默认拒绝；drop_broken 仅移除实际受影响字段并记录。普通单片段 fade 保留。锁定片段不能因转场策略而被改写。 |
| MR12 | dry-run、旧计划拒绝、幂等、快照、操作记录失败回滚、compose 批量失败回滚沿用现有事务；纯规划不修改输入对象。重排后的序列时长是全部轨道最大结束点，至少 1 tick；长配乐可保留尾部。 |
| MR13 | 原生 JSON、项目包和片段组保留结果与作者图。未新增持久 Schema 字段；外部格式沿用既有 link/editing/window/转场 Unsupported 报告，不把旁车当目标软件执行证据。 |
| MR14 | 规划对最多 20000 个片段准入；超过返回明确资源错误。排序/宿主查询使用整数有序索引；此准入不是总进程 RSS、长片吞吐或 4K 性能验收。 |

## 实际媒体核验

| 编号 | 必须执行的证据与不变门槛 |
|---|---|
| MR15 | 使用可公开的原创逐帧身份源、独立音频数组，实际 CLI 重排单选/多选/空隙/末尾/关联配音/短字幕/长配乐/sync opt-out。原片、实际无损成片、MP4/GIF、生成源码、摘要、帧数、PTS 与采样数公开；无损纯切画面全像素/Alpha 精确，独立 float32 PCM 最大误差 ≤2e-6。 |
| MR16 | 曲线/倒放/输出窗口/子序列/父动画的整镜头内容按重排前实际作者片段选区比较，声明同渲染器参考；真实转场保留以完整邻接块比较，独立原 PCM 与转场参考分计。显式移除转场后另验原始硬切真值。 |
| MR17 | 必须验证锁定/链接冲突/负时钟/sync 跨剪口/副轨效果总线/断开转场/旧摘要/事务/幂等与包交换，保留开发失败。相同最终测试对固定 V52 运行，控制与缺项失败分计，不把报告新字段差异称为多个算法。 |
| MR18 | 最终完整回归冻结产品/测试/发行输入；发行包和原生独立安装实际重建同一编辑结果；更新 README 编号表、进度、能力矩阵和 video-cut- Skills。静帧、连续播放、听审分别记录；自然质量、全手势与完整剪映等价未被本增量证明。 |

本契约依赖既有[整片段关联规则](./关联片段与主轨联动规划契约_v0.1_2026-10-17.md)、[作者输出窗口](./片段输出窗口裁切与波纹编辑契约_v0.1_2026-10-18.md)、[真实源转场](./真实源句柄转场与可逆编辑契约_v0.1_2026-10-17.md)与[交付端点](./透明视频交付与音画端点契约_v0.1_2026-10-18.md)。新重排算法由本项目实现，不新增一份 OpenFilm 原码采用量或节省百分比。

媒体执行前细化：独立纯切 RGB 使用二值灰阶身份源，避免将 RGB/YUV 色彩转换误差混入重排结果；Alpha 另以完整 0–255 渐变核验。字幕字形与复杂作者块采用重排前同渲染器输出参考，精确门槛仍为 0，独立音频数组另计；此参考不能证明字体排版、运镜或曲线算法本身正确。MP4 是供查看的有损预览，不进入无损门槛。
