# 本地视频防抖与稳定化派生素材契约 v0.1

| 项目 | 内容 |
|---|---|
| 文档编号 | SPEC-MEDIA-STABILIZE-001 |
| 状态 | 有效 |
| 日期 | 2026-10-15 |
| 运行边界 | 原生 Windows、Python、带 `libvidstab` 的本地 FFmpeg；网络关闭 |
| 关联入口 | `media stabilize`、`capabilities.media.stabilize_vidstab_two_pass` |

## 1. 目标和边界

本契约为 Agent 提供可复现的本地视频防抖底座。`media stabilize` 不修改原始媒体，也不直接改写时间线，而是运行 FFmpeg `vidstabdetect` 与 `vidstabtransform` 两遍处理，生成项目内可继续参与时间线编排的派生视频资产。该流程不调用剪映运行时、云端视频服务、在线模型或远程素材。

当前能力面向手持抖动的全局运动补偿。它不承诺主体级跟踪、滚动快门修复、物体遮挡修复、GPU 加速或剪映中的一键智能防抖质量；这些情况必须由质量检查和人工复核决定是否发布。

## 2. CLI 契约

```text
media stabilize --project PATH (--asset-id ID | --input FILE)
  [--derived-asset-id ID] [--output PROJECT_FILE]
  [--shakiness 1..10] [--accuracy SHAKINESS..15] [--stepsize 1..32]
  [--mincontrast 0..1] [--smoothing 0..1000]
  [--maxshift -1..500] [--maxangle -1..3.14]
  [--crop keep|black] [--optzoom 0|1|2] [--zoom -100..100]
  [--interpol no|linear|bilinear|bicubic]
  [--dry-run] [--progress jsonl] [--idempotency-key KEY]
```

`--asset-id` 与 `--input` 必须二选一。项目资产路径必须解析到项目内的本地文件；外部输入只能是本地文件，URL、云存储 URI 和服务商标记在执行前拒绝。输出默认为 `assets/derived/stabilized_<derived-asset-id>.mp4`，禁止覆盖已存在文件，并且必须位于项目目录内。

`--dry-run` 只返回输入、派生资产 ID、输出、变换文件目录、参数和 `ffmpeg-local:vidstabdetect+vidstabtransform` 引擎标识，不创建快照、变换文件、媒体或 Rights Ledger 记录。

## 3. 两遍处理和证据

正式执行按以下顺序进行：

1. 检查输入视频流、目标参数和本机 FFmpeg 是否同时提供 `vidstabdetect`、`vidstabtransform`；缺少 `libvidstab` 返回结构化依赖错误。
2. 在项目 `cache/stabilization/<derived-asset-id>/` 下生成 `transforms.trf`，第一遍使用 `vidstabdetect` 分析运动轨迹。
3. 检查变换文件存在且非空；第二遍使用 `vidstabtransform` 生成 H.264/AAC 派生 MP4，保留可用音频并使用 faststart。
4. 对输出执行 FFprobe 探测和 SHA-256 计算，写入 `validation/stabilization_<operation-id>.json`。报告必须包含输入/输出探测、输入/输出哈希、引擎、完整参数、变换文件路径、操作 ID 和快照 ID。

写入前创建 `before-stabilize` 项目快照，运行过程通过 `--progress jsonl` 报告 detect、transform、completed 阶段，并写入 `operations/<operation-id>.json` 与 provenance change log。失败时删除未完成输出；项目元数据事务仍由通用项目写锁和事务日志保护。

## 4. 派生资产与权利

从项目资产生成时，派生资产必须写入 `assets`，`source.derived_from` 指向父资产，`rights_ref` 指向新记录，Rights Ledger 的 `derived_from` 指向父权利记录。许可证、允许用途、渠道、限制、验证状态、撤下状态、作者、证据和归因从当前有效父记录继承；父记录缺失或无法解析时返回 `RIGHTS_RECORD_MISSING`，不得生成可发布的孤立资产。

从外部本地输入生成时，调用方必须提供与 `media ingest` 相同的本地来源、许可证、允许用途、验证状态和证据字段。未验证素材仍可以作为内部派生文件存在，但 `validate --strict-rights` 和发布渲染必须继续阻断。

防抖结果不会自动插入任何轨道。Agent 应在检查报告、哈希、Rights Ledger 和质量结果后，显式把派生资产放入时间线；这保证原始素材、稳定化素材和历史快照都可追溯。

## 5. 参数与质量限制

| 参数 | 默认值 | 约束和影响 |
|---|---:|---|
| `shakiness` | 5 | 1–10；越高越敏感，可能放大噪声 |
| `accuracy` | 15 | `shakiness`–15；越高 CPU 成本越高 |
| `stepsize` | 6 | 1–32；步长越小分析越细但更慢 |
| `mincontrast` | 0.25 | 0–1；低对比区域可能无法稳定 |
| `smoothing` | 15 | 0–1000；窗口越大越平滑，也可能削弱真实运镜 |
| `maxshift` | -1 | -1 或 0–500；限制最大平移 |
| `maxangle` | -1 | -1 或 0–3.14 弧度；限制最大旋转 |
| `crop` | `keep` | 保留边缘或填充黑边；裁切质量需人工确认 |
| `optzoom` | 1 | `vidstabtransform` 的自动缩放策略 0–2 |
| `zoom` | 0 | -100–100；与自动缩放共同决定画面边缘 |
| `interpol` | `bilinear` | `no`、`linear`、`bilinear`、`bicubic` |

输出质量受输入分辨率、快门/滚动快门、运动模糊、场景切换、遮挡、边缘裁切和本机 FFmpeg 编码器影响。`media stabilize` 不等同于主体级智能防抖；质量报告应检查黑边、画面裁切、残余抖动、变形、音画时长和编码完整性。

## 6. 验收证据

- `product/tests/test_cli.py::P0CliTests::test_media_stabilize_creates_derived_asset_with_inherited_rights` 覆盖 dry-run、两遍本地处理、输出探测、报告、`before-stabilize` 快照、父权利继承和严格权利校验。
- `capabilities` 必须公开 `stabilize_vidstab_two_pass`、稳定化契约和 `libvidstab`/质量边界。
- 真实部署前应在固定的手持抖动、场景切换和快速运镜素材上补充质量 golden；静态或程序生成样例只能证明流程可执行，不能证明主观稳定化质量。
