V77 把既有八色 HSL 的逐像素运算移入本地 C11 内核，作者模型和颜色定义沿用 [V76 契约](八色分区HSL与关键帧契约_v0.1_2026-10-20.md)。效果目录更新为 **0.8.1／46 项**；25 个 HSL 表达式通道与既有 10 类／34 个运行时命令通道分别发现。不增加效果数，不把性能探针等同于完整剪映验收。

## 1. 本地执行与后端选择

`render`、`render --dry-run`、工程包及片段导入继续使用普通 `selective_hsl` 效果和原作者轨道，无需新项目字段。`capabilities.effects.selective_hsl` 和 `effects inspect selective_hsl` 公布内核、回退和配额。

| 编号 | `AI_AD_EDITOR_HSL_BACKEND` | 实际行为 |
|---|---|---|
| N77-01 | `auto`，默认 | Windows amd64、随包清单和 DLL 完整且本地 FFmpeg 支持 frei0r 时，选择原生内核 |
| N77-02 | `native` | 要求原生模块及 FFmpeg frei0r；不可用时返回 `SELECTIVE_HSL_NATIVE_UNAVAILABLE` |
| N77-03 | `expression` | 明确执行既有 geq 参考后端，不加载原生模块 |
| N77-04 | 其他值 | 返回 `SELECTIVE_HSL_BACKEND_INVALID` |

`auto` 在不适用平台、模块清单未安装或 FFmpeg 缺少 frei0r 时回退，并在元数据记录原因。已安装清单中的文件丢失、来源 C／DLL 哈希变化、非法字段／文件名属于完整性错误，返回 `SELECTIVE_HSL_NATIVE_INTEGRITY`，不静默回退。完全中性或零强度旁路沿用原契约，不触发原生加载。

校验后的目录写入**当前进程及其子进程**的 `FREI0R_PATH`；不修改系统环境变量。模块文件名包含 DLL 摘要前 16 位，防止命中同名普通插件。没有在线安装、运行时编译、外部模型、Python 视频帧工作进程或 GUI。

使用 FFmpeg 公开的 [frei0r 滤镜接口](https://ffmpeg.org/ffmpeg-filters.html#frei0r)。最小 ABI 声明依据 [上游公开头文件](https://github.com/dyne/frei0r/blob/master/include/frei0r.h) 编写，未复制上游效果实现或编译其头文件；本项目原始 C 源码及通知为 MIT。随包 FFmpeg、Python、Windows SDK／CRT 和其他依赖仍各自遵循原许可。

## 2. 颜色定义与等价边界

内核输入为 8 位编码 RGBA。保持标准 HSL、原始色相的相邻双区线性权重、八个不等距中心、正负饱和度／明度映射、最终 RGB 强度混合和最近整数舍入。逐像素只计算有效的相邻两区；灰阶精确旁路，输入 Alpha 精确复制。它没有改用 HSI、近似三维 LUT 或闭源厂商算法。

`engine=encoded-rgb-eight-band-hsl-v1` 保持不变；执行元数据新增 `backend=ffmpeg:frei0r`、选择策略、DLL／C／FFmpeg 摘要、参考 geq 内核摘要，以及原生内核和程序摘要。独立 colorsys 参照和原生／geq 对照分别检查量化差，允许 8 位浮点运算次序产生的有限舍入误差；不声称与所有平台逐字节相同。

输入 Alpha 的保证只适用于 HSL 本阶段。后续合成、像素格式转换和有损编码有自己的边界。自然肤色、线性光、HDR、感知一致性及厂商色彩科学仍需要独立素材和质量评审。

## 3. 作者时钟与有界 DAG

`hsl_program.py` 编译既有作者时钟生成器的表达式，保留已有格式化数值、窗口映射、反转／速度变换和 32 段 Bezier 近似。没有第二套插值算法。C 接收的时间是 FFmpeg 实际传入的帧 PTS，每帧清空节点 memo，一次求出 25 个通道；像素循环复用该帧参数。

白名单仅接受数值常量、`t/T`、加减乘除、正负号及 `clip/lt/pow/exp/log/if`。不使用 `eval`；拒绝属性、导入、未知变量、未知函数、关键字参数和其他语法。`if` 只求值选中的分支，未选中分支的除零不会污染有效曲线。

| 编号 | `AVKHSL01` 二进制结构 | 限制 |
|---|---|---|
| N77-05 | 8 字节魔数、1 个 uint32 节点数、25 个 uint32 根索引 | 固定 112 字节头；小端 |
| N77-06 | 每节点 4 个 uint32：操作符和三个字段 | 每节点 16 字节；双精度常量占其中两字段 |
| N77-07 | 相同节点按原始字节共享 | 所有孩子索引必须早于当前节点，无环 |
| N77-08 | Python 编译后程序 | 最多 32,256 字节；深度最多 128；恰好 25 个根 |
| N77-09 | C ABI 防御校验 | 有界十六进制、精确长度、有限常量、已知操作、有效索引和深度；最多 4,096 节点 |

生成程序实际受更小的 Python 配额和完整 64 KiB 滤镜串限制，不能把 C 解码器的 4,096 节点上限当作作者配额。节点求值结果若非有限值，直接 ABI 调用输出原输入；非法或未设置程序也为原输入。这是内核防御行为，**不是 Agent 产品接受非法作者数据**：产品先做作者校验、参考 geq 预算检查和有界程序编译。

原来的单内核 64 KiB、根表达式 16 MiB、递归共享 1,024 效果实例和 2,000,000 状态样本等限制继续有效。中性／零强度旁路不新增执行配额；原生程序再紧凑，也不能绕过原作者表达式配额。

## 4. 线程、尺寸与生命周期

Windows 内核使用共享线程池，最多 **3 个后台工作线程＋当前调用线程**。每次以 32,768 像素块领取不重叠输出区间。小于 16,384 像素或无法创建池／工作对象时使用串行路径；像素定义相同。参数在派发前固定，`update` 返回前等待本实例全部回调完成；`destruct` 等待并关闭本实例工作对象，最后一次 `deinit` 关闭共享池。

不同实例持有独立 DAG、memo、参数和帧地址。当前并发实测覆盖三个实例共享池和重复时间输入；没有承诺单实例同时执行多个 `update`／修改参数的未定义 ABI 用法。

本内核显式接受宽高 1..8192，按总 RGBA 像素数处理。实际 FFmpeg 对 17×13、257×131 的奇数尺寸和步幅进行了像素对照。frei0r 旧接口中对其他插件的尺寸／对齐建议不能直接推为本内核已验证的限制；本次结果也不接受其他任意插件或整个渲染图的全部尺寸组合。

`-filter_threads 1` 不会关闭 C 内核自己的工作线程，因此性能报告必须同时写出 FFmpeg 滤镜线程和原生线程策略。

## 5. 构建、发行和完整性

`scripts/build_native_hsl.py` 使用本机已安装的 MSVC 19.29 x64 和 Windows SDK，在 E 盘临时目录编译；`/O2 /W4 /WX /std:c11 /MT /fp:precise /Brepro`，SDK 头文件的 C5105 仅在包含该头文件时屏蔽。保留完整命令、编译器摘要、原始 stdout／stderr、执行时 C 源码和 DLL。`/Brepro` 是构建选项，不是跨任意编译器逐字节可重现的验收结论。

当前包只保留一个摘要命名的 DLL；清单绑定格式、平台、程序格式、DLL／C 摘要、许可通知及编译器配置。旧 DLL 仅存历史证据目录。发布 wheel 为 **`py3-none-win_amd64`、Root-Is-Purelib=false**：C DLL 不依赖 CPython C ABI，平台却受 Windows x64 限制。原生 CPython 3.13 离线安装器精确接受该标签，仍拒绝 ARM、Linux、32 位 Windows 和错误 CPython ABI。

发行仍使用现有 7 个本地 wheels，不新增 NumPy、模型或下载。153 项源／wheel／安装资源逐字节核对；完整回归冻结源码、测试、C、DLL、清单、配置、`setup.py` 和离线脚本。完整结果与失败记录见 [实测报告](../validation/八色HSL原生提速与离线发行实测_2026-10-20.md)。

## 6. 性能验收层次与下一步

保留四种证据，禁止合并成一个“实时剪辑”结论：

1. 同机旧 geq／初版原生的滤镜探针，保留实际帧数、启动成本和不同长度。
2. 最终 DLL 的 1080p、60 帧、三次重复、输出 null 探针，含原生线程策略。
3. 真实工程的完整 CLI：校验、解码、HSL、合成、H.264/AAC 编码及清单，逐帧检查 PTS，并披露并发回归负载。
4. 未来持续交互预览：seek 延迟、缓存、取消、长时间内存和自然素材；本轮未实现或验收。

下一步以实际工程渲染瓶颈与长片质量为依据设计预览缓存、颜色管理和 GPU 后端；保持本地运行、完整性、作者数据可迁移和明确回退。完整剪映功能与效果等价仍须按总能力矩阵逐项补齐。
