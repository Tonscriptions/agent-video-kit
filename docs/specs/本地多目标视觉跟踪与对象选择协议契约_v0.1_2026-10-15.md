# 本地多目标视觉跟踪与对象选择协议契约 v0.1

| 项目 | 内容 |
|---|---|
| 状态 | 有效 |
| 关联 CLI | `media adapter`、`media track`、`media track-bind`、`media reframe` |
| registry | 项目内 `models/visual-adapters.json` |
| 协议 | `agent-video-object-tracking-v2` |
| engine | `command-json-tracking-multi-v1` |
| output contract | `tracking_objects_v1` |
| 更新日期 | 2026-10-15 |

## 1. 目标与边界

本契约把一个已经登记、哈希仍匹配的本地多目标视觉 runner 接入 Agent Project。runner 可以在同一段视频中返回多个带稳定 `object_id` 的归一化框轨迹；CLI 负责协议、范围、身份唯一性和关键帧边界校验，然后由 Agent 决定是否把一个对象应用到时间线。

模型、runner、媒体和响应证据都留在本机。CLI 不下载权重、不访问网络、不启动 Docker/WSL/容器/虚拟机、不调用 GUI，也不把协议接通解释成模型质量已经达到剪映。

`agent-video-object-tracking-v1` 的单目标契约继续有效；v2 是独立的 `output_contract`，不会把 v1 的 `frames` 响应静默解释成多目标结果。

## 2. registry 与执行门禁

`media adapter register` 对 v2 写入以下关键字段：

| 字段 | 要求 |
|---|---|
| `engine` | 固定为 `command-json-tracking-multi-v1` |
| `protocol` | 固定为 `agent-video-object-tracking-v2` |
| `output_contract` | 固定为 `tracking_objects_v1` |
| `capabilities` | 至少包含 `multi_object_bbox` |
| `model_path` / `model_sha256` | 已存在的本地文件或目录及确定性哈希 |
| `executable` / `executable_sha256` | 已存在的 argv-only 本地 runner 及哈希 |
| `network` | 固定为 `disabled` |
| `verification_status` | `unverified`、`verified` 或 `restricted` |

执行 `media track`、`track-bind` 或 `reframe` 前重新计算模型和 runner 哈希。路径缺失、哈希变化、未知 engine、shell wrapper、超时或非零退出都会结构化失败；不会退回 v1、模板匹配或线上服务。

## 3. 请求

runner 从 stdin 读取一条 JSON，请求结构的核心字段如下：

```json
{
  "protocol": "agent-video-object-tracking-v2",
  "status": "request",
  "engine": "command-json-tracking-multi-v1",
  "network": "disabled",
  "source": {"path": "...", "sha256": "sha256:..."},
  "model": {"path": "...", "sha256": "sha256:..."},
  "runner": {"path": "...", "sha256": "sha256:..."},
  "roi": {"x": 0.1, "y": 0.2, "width": 0.4, "height": 0.5},
  "selection": {"object_id": "person_2", "all_objects": false},
  "range": {"start_seconds": 0.0, "end_seconds": 1.0, "step_frames": 4},
  "limits": {"max_width": 640, "max_samples": 600, "max_objects": 64},
  "ticks_per_second": 90000,
  "output_contract": "tracking_objects_v1"
}
```

`selection.object_id` 为单对象应用或查看目标；`all_objects=true` 只表示希望收到完整对象列表。CLI 不要求 runner 只返回被选对象，因为它需要保留对象计数和候选证据。

## 4. 响应校验

响应必须是单个 JSON 对象，且满足：

```json
{
  "protocol": "agent-video-object-tracking-v2",
  "status": "ok",
  "engine": "local-multi-tracker",
  "objects": [
    {
      "object_id": "person_2",
      "label": "person",
      "frames": [
        {"at_seconds": 0.0, "x": 0.60, "y": 0.40, "width": 0.18, "height": 0.28, "confidence": 0.94, "rotation_degrees": 0.0}
      ],
      "metadata": {}
    }
  ],
  "metadata": {}
}
```

CLI 强制检查：

1. `protocol=agent-video-object-tracking-v2`、`status=ok`、`objects` 非空且不超过请求的 `max_objects`；
2. 每个 `object_id` 非空、长度不超过 128 且全局唯一；
3. 每个对象的 `frames` 非空且不超过 `max_samples`；
4. `at_seconds` 位于请求范围内，`at_tick` 非负、单调递增；
5. `x/y` 位于 `0..1`，`width/height` 位于 `(0,1]`，`confidence` 位于 `0..1`；
6. 可选 `rotation_degrees` 为有限的 `-180..180` 数值；非法字段、过大 stdout、非 JSON 或 runner 错误均拒绝。

通过校验后，每个对象保留 `frames`、`confidence_mean`、`metadata` 和位置/旋转关键帧。指定 `object_id` 时，报告额外提供该对象的顶层 `frames` 与 `keyframes`，供三条应用路径复用；`--all-objects` 报告保留完整 `objects`，不生成可直接应用的顶层关键帧。

## 5. CLI 语义

### 5.1 `media track`

```powershell
python -X utf8 -m ai_ad_editor media track `
  --project .\work\demo --asset-id source `
  --adapter-id tracker_multi --roi 0.1,0.2,0.4,0.5 `
  --object-id person_2 --clip-id talking_head --track-id track_video_1
```

`--object-id` 选择一个对象并允许 `--clip-id` 应用位置/旋转关键帧。`--all-objects` 用于只写多目标报告；它与 `--clip-id` 互斥。v2 适配器没有选择参数会返回 `TRACK_OBJECT_SELECTION_REQUIRED`。

### 5.2 `media track-bind` 与 `media reframe`

这两条命令只接受一个目标对象：

```powershell
python -X utf8 -m ai_ad_editor media track-bind `
  --project .\work\demo --asset-id source --adapter-id tracker_multi `
  --object-id person_2 --roi 0.1,0.2,0.4,0.5 `
  --target-clip-id product_label --target-track-id track_titles --dry-run

python -X utf8 -m ai_ad_editor media reframe `
  --project .\work\demo --asset-id source --adapter-id tracker_multi `
  --object-id person_2 --roi 0.1,0.2,0.4,0.5 `
  --clip-id talking_head --track-id track_video_1 --dry-run
```

两条命令缺少 `--object-id` 时拒绝应用，避免把多个对象轨迹混入一个文字层或一个裁切窗口。应用仍遵守各自的 `before-track-bind`/`before-reframe` 快照、项目校验、报告和操作记录。

## 6. 错误与 warning

| 代码 | 语义 |
|---|---|
| `TRACK_OBJECT_SELECTION_REQUIRED` | v2 runner 缺少应用目标对象 |
| `TRACK_OBJECT_SELECTION_UNSUPPORTED` | 对 v1/模板 runner 使用了对象选择参数 |
| `TRACK_MULTI_APPLY_SELECTION_REQUIRED` | `--all-objects` 与 `--clip-id` 同时出现 |
| `TRACK_OBJECT_NOT_FOUND` | runner 没有返回请求的 `object_id` |
| `TRACKING_RUNNER_OUTPUT_INVALID` | 对象、帧、范围、框或 confidence 不符合契约 |
| `TRACKING_MULTI_OBJECT_REVIEW` | 多目标身份连续性、遮挡、镜头切换和模型质量仍需复核 |
| `multi_object_identity_requires_quality_review` | 报告中的机器可读限制标记 |

## 7. 质量边界与验收

协议只证明“runner 返回了可解析且边界合法的多目标轨迹”。它不证明身份在遮挡、交叉、出画、镜头切换或相似目标之间保持正确，也不提供分割 mask、姿态点、透视角点、运动模糊修复或语义目标识别。每个真实模型必须提供固定素材、遮挡/交叉样例、身份切换指标、许可证证据和本地 golden；在此之前只能保持 `TRACKING_MULTI_OBJECT_REVIEW`，不能写成剪映级质量或发布门禁通过。

当前回归覆盖注册、hash 验证、v2 request/response、唯一对象、选定对象应用、`--all-objects` 报告、`track-bind`、`reframe` 和项目校验；真实模型质量 golden 仍待补。
