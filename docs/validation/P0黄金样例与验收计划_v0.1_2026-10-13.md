# P0 黄金样例与验收计划 v0.1

| 项目 | 内容 |
|---|---|
| 文档编号 | VALIDATION-P0-001 |
| 状态 | 评审中 |
| 版本 | 0.1.0 |
| 日期 | 2026-10-14 |
| 关联需求 | PRD-001、PRD-003、PRD-004、PRD-008 |
| 目标 | 在原生 Windows 上验证无头 Agent 剪辑核心，而不是验证 GUI 体验 |

本计划定义 P0 的固定输入、预期输出、质量阈值和证据要求。没有实际样例媒体、命令日志和报告，P0 只能算“文档通过”，不能算“工程通过”。

## 1. 样例集原则

- 样例素材优先使用程序生成、CC0 或项目明确拥有授权的短文件，所有文件都有 Rights Ledger 记录。
- 每个样例保存输入哈希、生成脚本/来源、分辨率、帧率、色彩、音频采样率和预期时长。
- 样例目录建议为 `validation/fixtures/p0/<fixture-id>/`；媒体、项目 JSON、命令和期望报告分开保存。
- 测试不能只用一条 H.264 CFR 视频；必须覆盖 VFR、长 GOP、透明素材、CJK 字幕、坏文件和多轨边界。

## 3. 必须生成的证据

每个样例必须保存：

1. 输入资产清单与 SHA-256；
2. Agent Project JSON、schema 校验结果和项目锁文件；
3. 完整 CLI 命令、工具版本、环境摘要和 JSONL 进度日志；
4. 渲染清单、输出媒体哈希、`ffprobe` 摘要和质量报告；
5. 失败时的退出码、错误路径、临时文件清理结果和重试记录；
6. 人工目视检查记录：画面、关键帧、字幕、转场、音画同步和颜色；
7. Rights Ledger 快照与目标渠道检查结果。

## 4. 默认阈值

阈值可按渠道覆盖，但项目必须记录实际使用值：

| 指标 | 默认阈值 |
|---|---|
| 总时长 | 与期望值相差不超过 1 帧 |
| 音画同步 | 关键对白与画面偏差不超过 1 帧；无法自动测量时必须人工确认 |
| 黑帧/冻结帧 | 不允许非预期黑帧或连续冻结帧 |
| 输出流 | 至少一个有效视频流；有声样例必须有有效音频流 |
| 字幕 | 不越界、不重叠、不为空；每个 cue 落在序列范围内 |
| 响度 | 通过 `--target-lufs` 和 `--lufs-tolerance` 显式启用；广告默认建议 -14 LUFS ± 1.5 LU，真峰值不高于 -1 dBTP，渠道可覆盖 |
| 文件完整性 | 输出可读、容器索引完整、哈希可记录 |
| 可复现 | 同锁文件重跑的项目/清单差异必须可解释 |

`quality check` 的 CLI 默认 `--max-av-sync-ms` 为 80 ms，作为通用媒体流时长安全线；P0 黄金样例可以按帧率把该参数收紧到 1 帧以内。两者不能混写成同一个阈值，实际命令参数必须写入样例证据。

## 5. 验收流程

当前 `product` CLI 已支持下列步骤的 P0 子集；本计划中尚未实现的 `--stage media` 聚合编排、其他长任务的全量进度 JSONL 必须在对应模块完成后再启用，不能把计划项当成现有命令参数。`quality check`、`quality golden --mode capture|verify`、`render --cancel-file` 和带输入指纹校验的 `render --resume` 已有本地实现；golden 命令已经能捕获/验证本地媒体和 settings 哈希，仍需把经过版权登记的固定素材集纳入正式样例。

1. `doctor` 检查工具链和本地路径；
2. `project init` 创建样例项目并固定 schema；
3. `media ingest` 写入资产哈希和 Rights Ledger 引用；
4. `timeline compose` 或固定变更集生成时间线；
5. `policy audit --project <path>` 审计项目 JSON/JSONL，发现远程协议、URL、云存储或服务商标记时立即失败；
6. `validate --project <path> [--strict-rights]` 先校验结构、引用、时间和权利，再执行渲染；
7. `render` 写入临时目录并生成渲染清单；需要多个输出规格时，先 `queue enqueue`，再 `queue list/inspect/run`，取消使用 `queue cancel`；
8. 使用 `ffprobe` 检查流和时长；`quality check` 自动检查画布、视频/音频时长差，配合 `--expensive` 检查黑帧和 `ebur128` 响度；通过后用 `quality golden --mode capture` 固定输出哈希、settings 哈希和稳定指标，再用 `--mode verify` 检查后续漂移；字幕视觉和跨设备真峰值仍需人工/专门样例；
9. `rights check` 验证发布资格；
10. 保存证据并按样例 ID 更新回归状态。

任何 P0 样例失败都不能用“肉眼看起来可以”关闭；必须记录是实现缺陷、样例问题、工具限制还是预期降级，并更新基线/ADR（如影响承诺）。
