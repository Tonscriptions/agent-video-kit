# 本地视觉模型适配器与对象跟踪协议契约 v0.1

| 项目 | 内容 |
|---|---|
| 状态 | 有效 |
| 关联 CLI | `media adapter`、`media track`、`media track-bind`、`media reframe` |
| registry | 项目内 `models/visual-adapters.json` |
| 协议 | `agent-video-object-tracking-v1`（单目标） |
| 更新日期 | 2026-10-15 |

## 1. 目标与边界

本契约把已经登记的本地视觉模型接入 Agent Project 的对象跟踪链路。模型、执行器和结果都必须留在本机；CLI 不下载权重、不访问网络、不启动 shell wrapper，也不把“已登记”解释成“模型质量已经达到剪映”。

当前实现支持 `command-json-tracking-v1` 单目标 runner；多目标已由独立的 `command-json-tracking-multi-v1` / `agent-video-object-tracking-v2` 契约覆盖，详见[本地多目标视觉跟踪与对象选择协议契约](./本地多目标视觉跟踪与对象选择协议契约_v0.1_2026-10-15.md)。v1 是一个受限的本地 runner 协议：CLI 通过 argv 启动一个已登记的 `.py` 或原生可执行文件，把一条 JSON 请求写入 stdin，读取一条 JSON 响应，再把经过校验的归一化框和 confidence 转成位置关键帧。原生 YOLO ONNX 跟踪见其专用契约；人物软 alpha 已通过独立的 [RVM 抠像契约](./本地RVM人物视频抠像与透明素材契约_v0.1_2026-10-16.md)接入同一视觉 registry，不能替用跟踪协议。通用物体分割、姿态、旋转框和遮挡恢复仍需新的输出契约与独立验收。

## 2. 注册、哈希与权利门禁

注册表记录以下字段：

| 字段 | 要求 |
|---|---|
| `adapter_id` | 项目内唯一 ID |
| `kind` | 固定为 `object-tracking` |
| `engine` | 当前只能为 `command-json-tracking-v1` |
| `model_path` / `model_sha256` | 已存在的本地模型文件或目录及确定性哈希 |
| `executable` / `executable_sha256` | 已存在的本地 runner 及哈希 |
| `output_contract` | 固定为 `tracking_frames_v1` |
| `protocol` | 固定为 `agent-video-object-tracking-v1` |
| `network` | 固定为 `disabled` |
| `verification_status` | `unverified`、`verified` 或 `restricted` |

`media adapter register` 会创建 `before-media-adapter-register` 快照，并在 Rights Ledger 写入 `kind=model-adapter`、`asset_id=adapter:<adapter_id>` 的记录。正式执行前，`media track`、`media track-bind` 和 `media reframe` 重新计算模型和执行器哈希；路径不存在或哈希变化时返回 `MODEL_ADAPTER_HASH_INVALID`，不会执行 runner。

注册前建议先执行：

```powershell
python -X utf8 -m ai_ad_editor media adapter register `
  --project .\work\demo --adapter-id tracker_local `
  --engine command-json-tracking-v1 `
  --model-path D:\models\tracker.bin `
  --executable D:\models\tracker_runner.py `
  --license-spdx Apache-2.0 --verification-status verified `
  --evidence local://tracker-evidence --dry-run
```

执行 `media adapter list` 或 `media adapter inspect --adapter-id tracker_local` 检查 `verification.ok` 后，再允许进入跟踪计划。

`.cmd`、`.bat`、`.ps1`、`.psm1`、`.vbs`、`.wsf`、`.sh`、`.bash` 和 `.zsh` wrapper 在注册阶段直接返回 `MODEL_EXECUTABLE_UNSAFE`。这是 argv-only、无 shell 的执行约束，不是对模型本身质量的判断。

## 3. JSON 请求

runner 从 stdin 读取一个对象。路径是本机绝对路径，哈希用于 runner 自己的审计；runner 不得根据请求访问网络。

```json
{
  "protocol": "agent-video-object-tracking-v1",
  "status": "request",
  "adapter_id": "tracker_local",
  "engine": "command-json-tracking-v1",
  "network": "disabled",
  "source": {"path": "D:/media/shot.mp4", "sha256": "sha256:..."},
  "model": {"path": "D:/models/tracker.bin", "sha256": "sha256:..."},
  "runner": {"path": "D:/models/tracker_runner.py", "sha256": "sha256:..."},
  "roi": {"x": 0.1, "y": 0.2, "width": 0.25, "height": 0.3},
  "range": {"start_seconds": 0.0, "end_seconds": 2.0, "step_frames": 4},
  "limits": {"max_width": 640, "max_samples": 600},
  "ticks_per_second": 90000,
  "output_contract": "tracking_frames_v1"
}
```

`roi` 是 `[0,1]` 归一化源画面框；`end_seconds` 可以为 `null`。CLI 会把 `max_samples` 限制在 1..20000，把时间基准固定为项目 `ticks_per_second`。

## 4. JSON 响应与 Agent 校验

成功响应必须是单个 JSON 对象，`protocol` 与 `status=ok` 必须精确匹配：

```json
{
  "protocol": "agent-video-object-tracking-v1",
  "status": "ok",
  "engine": "my-local-tracker",
  "frames": [
    {"at_seconds": 0.0, "x": 0.25, "y": 0.5, "width": 0.2, "height": 0.3, "confidence": 0.97},
    {"at_seconds": 0.5, "x": 0.27, "y": 0.5, "width": 0.2, "height": 0.3, "confidence": 0.91}
  ],
  "metadata": {"model_variant": "local-v1"}
}
```

CLI 在写报告或项目之前执行以下门禁：

1. `frames` 必须是非空数组，数量不得超过请求的 `max_samples`。
2. `at_seconds` 必须是有限数字，并位于请求范围；`at_tick` 缺省时由项目时间基准计算。
3. `at_tick` 必须非负、单调递增。
4. `x`、`y`、`width`、`height` 必须是归一化有限数字，宽高必须大于 0；`confidence` 必须位于 0..1。
5. stdout 超过 10 MiB、JSON 无法解析、协议不匹配、非零退出、超时或响应失败时，返回结构化错误且不写入关键帧。

报告 `engine` 为 `command-json-tracking-v1`，`method` 为 `command-json`，保留源/模型/执行器哈希、协议、runner metadata、逐帧框、confidence 和位置关键帧。报告会附加 `external_local_runner_requires_quality_review` 与 `runner_output_validated_by_agent`；协议校验通过不等于视觉质量验证通过。

## 5. 三条应用链路

```powershell
# 只生成可审计报告
python -X utf8 -m ai_ad_editor media track --project .\work\demo \
  --asset-id asset_video --adapter-id tracker_local --roi 0.1,0.2,0.25,0.3 --dry-run

# 把位置关键帧写入直接媒体片段
python -X utf8 -m ai_ad_editor media track --project .\work\demo \
  --asset-id asset_video --adapter-id tracker_local --roi 0.1,0.2,0.25,0.3 \
  --clip-id clip_video --apply

# 复用同一轨迹驱动文字/贴纸/效果
python -X utf8 -m ai_ad_editor media track-bind --project .\work\demo \
  --asset-id asset_video --adapter-id tracker_local --roi 0.1,0.2,0.25,0.3 \
  --target-clip-id label --target-track-id track_titles --apply

# 用同一轨迹生成目标画幅动态 crop
python -X utf8 -m ai_ad_editor media reframe --project .\work\demo \
  --asset-id asset_video --adapter-id tracker_local --roi 0.1,0.2,0.25,0.3 \
  --clip-id clip_video --track-id track_video_1 --apply
```

三条命令仍遵守各自的 `before-*` 快照、项目校验、provenance 和操作记录。`track-bind` 会把源时钟归一化到目标片段时长；`reframe` 只接受常速、正向、直接媒体片段。runner 输出的旋转、姿态、遮罩或多目标字段不会被静默解释成当前项目属性。

## 6. 当前质量边界与后续扩展

该协议解决的是“Agent 可以安全调用一个已登记的本地视觉 runner，并获得可验证轨迹”的工程缺口，不能单独解决剪映级跟踪质量。遮挡恢复、镜头切换重初始化、旋转框、分割 mask、姿态点、多人关联、光流稳定和视觉 golden 仍需单独契约。任何新增输出字段都必须提升 `output_contract` 版本，补充固定素材、质量指标、许可证和回归测试后才能进入 `verified`。
