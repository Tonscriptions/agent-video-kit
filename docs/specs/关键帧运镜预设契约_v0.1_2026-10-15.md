## 1. 目的和边界

运镜预设把常用的缩放、平移、旋转、透明度和 Ken Burns 组合动作表达为 Agent Project 的普通关键帧。它为 Agent 提供稳定的发现、参数验证、局部应用、快照和操作记录入口，避免把一个内部时间线操作误当成不可审计的模板系统。

运行时只使用项目 JSON、Python 和本地 FFmpeg 渲染器，不访问网络、不下载模板、不启动 GUI，也不依赖剪映/Jianying。预设目录不声明与任何商业编辑器逐像素或逐参数等效。

## 2. 目录版本和对象

目录版本为 `0.1.0`，`motion list` 的成功 envelope 返回：

```json
{
  "catalog_version": "0.1.0",
  "source": "local-catalog",
  "engine": "timeline-keyframes",
  "network": "disabled",
  "count": 12,
  "presets": []
}
```

单项对象包含：

| 字段 | 约束 |
|---|---|
| `id` | 项目和操作记录使用的小写下划线规范 ID |
| `aliases` | 只用于 CLI 查询和兼容旧变更集；写入结果保留规范 ID |
| `category` | `scale`、`position`、`rotation`、`opacity` 或 `compound` |
| `engine` | 固定为 `timeline-keyframes` |
| `source` | 固定为 `local-catalog` |
| `properties` | 该预设可能写入的关键帧属性 |
| `parameters` | 参数类型、默认值和边界 |
| `limits` | 近似、渲染器或应用边界 |

当前 12 个规范 ID 为：

`zoom_in`、`zoom_out`、`pan_left`、`pan_right`、`pan_up`、`pan_down`、`ken_burns`、`rotate_in`、`rotate_out`、`fade_in`、`fade_out`、`shake`。

兼容别名为：`push_in`、`pull_out`、`slide_left`、`slide_right`、`slide_up`、`slide_down`、`kenburns`、`rotate_left`、`rotate_right`、`opacity_in`、`opacity_out`。

## 3. 应用契约

```powershell
python -m ai_ad_editor motion list --query position
python -m ai_ad_editor motion inspect --name push-in
python -m ai_ad_editor motion apply --project .\work\demo --clip-id clip_001 --preset ken_burns --amount 0.2
```

`motion apply` 的必需字段是项目、片段 ID 和预设名称；`--track-id` 用于消除跨轨道重复片段 ID，`--sequence-id` 默认为主序列。`--start-tick` 和 `--end-tick` 使用片段内时间，缺省分别为 `0` 和片段时长。`--amount`、`--degrees`、`--points` 缺省使用目录值：

| 参数 | 适用预设 | 范围 |
|---|---|---:|
| `amount` | 缩放、平移、Ken Burns、shake | `0..1` |
| `degrees` | rotate_in、rotate_out | `-360..360` |
| `points` | shake | `2..64` 整数 |

未知预设、未知别名、非有限数、越界参数或空时间范围均返回 `ARGUMENT_INVALID`，不写入项目。写入前执行项目 Schema 和语义校验；校验失败不会留下半成品变更。

成功写入会：

1. 创建 `history/` 中的 `before-motion-apply` 自包含快照；
2. 在片段 `keyframes[]` 中写入普通 `transform.*` 关键帧；
3. 更新 `provenance.change_log`；
4. 写入 `operations/<operation_id>.json`，其中包含规范预设、目录版本、目标片段和快照 ID；
5. 通过统一 JSON envelope 返回 `clip`、`motion`、`validation` 和 `before_snapshot`。

`--dry-run` 会在深拷贝项目上执行同样的规范化和校验，只返回 `status=planned`，不写项目、快照或操作记录。

## 4. 关键帧映射

| 预设 | 写入属性 | 时间点语义 |
|---|---|---|
| `zoom_in` / `zoom_out` | `transform.scale` | 从当前 scale 到相对增量，或反向回到当前 scale |
| `pan_left/right` | `transform.position.x` | 以当前位置为中心的对称归一化位移 |
| `pan_up/down` | `transform.position.y` | 以当前位置为中心的对称归一化位移 |
| `ken_burns` | scale、position.x、position.y | 缩放与二维平移同步执行 |
| `rotate_in/out` | `transform.rotation` | 指定角度与零度之间的平滑过渡 |
| `fade_in/out` | `transform.opacity` | `0↔1` 透明度过渡 |
| `shake` | `transform.position.x` | 在区间内生成确定数量的交替线性点 |

预设只负责生成关键帧；插值由项目关键帧执行器处理，当前使用 `ease_in_out` 或 `linear`。渲染效果、边界裁切和坐标空间仍以本地 FFmpeg renderer 的 manifest 与 warning 为准。

## 5. 已知限制和验收

- 目录不包含商业编辑器的 GUI 模板、自动构图、主体跟踪、光流补帧、镜头语言识别、GPU 特效或素材推荐。
- 平移和 Ken Burns 的位置值可能在大强度下越过画布，最终画面是否出现留边或裁切由渲染画布和 clip transform 约束决定。
- `shake` 使用固定点数和线性插值，不等同于物理抖动或真实手持相机轨迹。
- 预设没有独立媒体副作用；操作事务、项目写锁和失败恢复由 CLI 公共层负责。

必须通过：

1. `motion list`、`motion inspect` 的本地目录和未知名称拒绝测试；
2. `motion apply` 的别名规范化、快照、操作记录、dry-run 和参数范围测试；
3. 完整 `unittest`、`compileall`、`git diff --check`；
4. `capabilities` 中的目录版本、来源、功能和限制与本契约一致。
