# 本地对象跟踪与关键帧规范 v0.1

| 项目 | 内容 |
|---|---|
| 文档编号 | SPEC-TRACK-001 |
| 状态 | 评审中 |
| 版本 | 0.1.0 |
| 日期 | 2026-10-13 |
| 运行边界 | 原生 Windows、Python、FFmpeg、Pillow、numpy；默认无网络 |
| 关联命令 | `media track` |

## 1. 目标与边界

对象跟踪是 Agent 的可编排能力：给定本地视频和归一化感兴趣区域（ROI），输出带源哈希的逐采样帧位置、置信度和可直接写入 Agent Project 的位置关键帧。当前实现采用可解释的模板匹配，优先保证离线、可复现和失败可诊断；它不能被描述为剪映级的模型跟踪。

跟踪器不得访问网络、下载模型、启动 Docker/WSL 或依赖 GUI。遮挡、显著尺度变化、镜头切换、运动模糊和目标形状改变可能造成漂移，报告必须保留这一风险，而不是静默平滑成“准确”轨迹。

## 2. CLI 契约

```text
python -m ai_ad_editor media track \
  --project <project> \
  (--asset-id <asset_id> | --input <local_video>) \
  --roi <x,y,width,height> \
  [--start-seconds <float>] [--end-seconds <float>] \
  [--step-frames <int>] [--search-radius <int>] [--max-width <int>] \
  [--output <project_relative_report.json>] \
  [--clip-id <clip_id>] [--track-id <track_id>] [--sequence-id <sequence_id>]
```

输入规则：

- `--asset-id` 与 `--input` 必须且只能提供一个；`--asset-id` 的 URI 必须解析到项目内的本地文件。
- `--roi` 使用 `x,y,width,height`，四项都是 0 到 1 的归一化值，宽高必须为正且不能越界。
- 时间范围以源媒体秒为单位；未提供结束时间时使用 FFprobe 的媒体时长。
- `step_frames`、`search_radius` 和 `max_width` 会被限制在本地可控范围内，避免 Agent 传入不受控的资源消耗。
- `--dry-run` 只返回输入、ROI、序列和写回目标，不读帧、不修改项目。

## 3. 报告格式

报告写入项目 `validation/`，至少包含：

```json
{
  "report_version": "0.1.0",
  "project_id": "...",
  "asset_id": "asset_...",
  "source": "...",
  "source_sha256": "sha256:...",
  "engine": "local-template-matching",
  "range": {"start_seconds": 0, "end_seconds": 1, "sample_fps": 3, "step_frames": 4},
  "roi": {"x": 0.05, "y": 0.25, "width": 0.2, "height": 0.3},
  "frames": [
    {"at_seconds": 0, "at_tick": 0, "x": 0.15, "y": 0.4, "width": 0.2, "height": 0.3, "confidence": 0.98}
  ],
  "keyframes": [
    {"property": "transform.position.x", "keyframes": [{"at_tick": 0, "value": 0.15, "interpolation": "linear"}]},
    {"property": "transform.position.y", "keyframes": [{"at_tick": 0, "value": 0.4, "interpolation": "linear"}]}
  ],
  "warnings": ["template_matching_can_drift_on_occlusion_or_large_scale_change"]
}
```

`x/y` 是目标中心的归一化坐标；`width/height` 是跟踪框的归一化尺寸。`at_tick` 相对于本次跟踪范围的起点，使用项目默认 90,000 ticks/s 的时间基准写回片段时必须经过项目校验。`confidence` 是模板误差映射出的可比较分数，不是概率，也不能作为发布质量的单独证明。

## 4. 写回语义

没有 `--clip-id` 时命令只生成报告。指定 `--clip-id` 时：

1. 先解析序列和片段，并在修改前创建 `before-track-apply` 项目快照；
2. 用报告中的 `transform.position.x`、`transform.position.y` 关键帧替换同名片段关键帧轨道；
3. 将时间点裁剪到片段时长，按项目语义校验和 JSON Schema 校验；
4. 校验失败时不保存项目，返回 `TRACK_APPLY_INVALID`；成功时写入项目变更日志和操作记录；
5. 报告和操作记录必须保留源哈希、片段 ID、应用属性和快照 ID，便于恢复与重放。

跟踪位置不会自动改变片段裁切、缩放、遮罩或旋转。Agent 如果要把框尺寸映射为缩放或裁切，必须生成独立的变更集并在能力清单允许时执行。

## 5. 失败与降级

| 错误/警告 | 含义 | Agent 行为 |
|---|---|---|
| `TRACK_SOURCE_MISSING` | 输入文件不存在 | 修复本地路径后重试 |
| `TRACK_VIDEO_MISSING` | 输入没有视频流 | 拒绝跟踪，选择视频资产 |
| `TRACK_ROI_INVALID` | ROI 越界或尺寸无效 | 修正归一化 ROI |
| `TRACK_FRAME_EXTRACTION_FAILED` | FFmpeg 未能抽取采样帧 | 保留诊断，检查编码/范围后重试 |
| `DEPENDENCY_UNAVAILABLE` | Pillow 或 numpy 缺失 | 安装已批准的本地依赖，不自动联网 |
| `TRACKING_APPROXIMATE` | 模板匹配可能漂移 | 要求人工复核或升级模型适配器 |
| `TRACK_APPLY_INVALID` | 关键帧写回后项目不合法 | 不发布，读取快照或修正片段 |

## 6. 验收与已知缺口

当前代码证据是 `test_local_object_tracking_report_and_keyframe_apply`：程序生成的移动方块视频可被抽帧、生成报告、写回位置关键帧并通过项目验证。发布前还必须增加：

- 遮挡、镜头切换、尺度变化和运动模糊样例，记录漂移率和低置信度阈值；
- 与本地可许可模型适配器的统一报告格式，明确模型权重哈希和许可证；
- 框尺寸、旋转框、姿态点、遮罩路径和自动重构图的独立 schema；
- 固定 golden 轨迹与人工视觉验收，不能用单一置信度数字替代；
- 大分辨率、长视频、批量素材的时间、峰值内存和临时文件清理基线。

这些缺口关闭前，能力清单把它标为本地模板跟踪并报告漂移风险；不能把它标记为剪映级运动跟踪等效。
