# 本地跟踪绑定与对象锚定契约 v0.1

| 项目 | 内容 |
|---|---|
| 文档编号 | SPEC-TRACK-BIND-001 |
| 状态 | 有效 |
| 生效日期 | 2026-10-15 |
| 关联命令 | `media track-bind` |
| 运行后端 | 本地 FFmpeg 帧抽取 + Pillow/numpy 模板匹配 |
| 网络 | 禁用；不调用云端视觉 API、在线素材库或剪映运行时 |

## 1. 目标与边界

`media track` 只把模板匹配结果写回跟踪源片段自身，无法让独立文字、贴纸或效果随主体移动。本契约增加一条可由 Agent 审阅和重放的绑定链：在本地视频上计算跟踪帧，把位置关键帧和可选的 ROI 相对缩放写入另一个视觉片段。

绑定结果是普通 `transform.*` 关键帧，不创建隐藏的运行时依赖，也不修改源媒体。它适合产品标签、价格牌、贴纸、遮罩占位层和效果片段等需要跟随主体的对象。模板匹配仍是可解释的近似算法，不等同于模型级、多目标或亚像素跟踪。

## 2. CLI 契约

```powershell
python -X utf8 -m ai_ad_editor media track-bind `
  --project .\work\demo `
  --asset-id <asset_id> `
  --roi 0.20,0.20,0.20,0.35 `
  --target-clip-id product_label `
  --target-track-id track_text_1 `
  --scale-mode roi `
  --offset-x 0.0 `
  --offset-y -0.05 `
  --dry-run
```

也可以用项目外的本地视频作为源：

```powershell
python -X utf8 -m ai_ad_editor media track-bind `
  --project .\work\demo `
  --input .\media\source.mp4 `
  --roi 0.20,0.20,0.20,0.35 `
  --target-clip-id sticker_01 `
  --target-track-id track_overlay_1 `
  --apply
```

`--asset-id` 与 `--input` 必须二选一；远程 URI 会在本地输入校验阶段拒绝。`--dry-run` 返回 `status=planned`、源哈希、目标片段、采样参数、缩放模式和网络关闭声明，不写项目。只有显式 `--apply` 才创建快照并写回目标片段。

| 参数 | 语义 |
|---|---|
| `--roi X,Y,W,H` | 源帧归一化模板区域；必须由 Agent 或人工先确认 |
| `--target-clip-id` / `--target-track-id` | 接收绑定关键帧的独立视觉片段和轨道 |
| `--sequence-id` | 目标序列；省略时使用主序列 |
| `--step-frames` / `--search-radius` / `--max-width` / `--max-samples` | 本地模板匹配的采样和搜索上限 |
| `--offset-x` / `--offset-y` | 叠加对象相对跟踪中心的归一化偏移，范围为 `-1..1` |
| `--scale-mode none` | 只绑定 `transform.position.x/y` |
| `--scale-mode roi` | 额外绑定 `transform.scale`，按 ROI 宽度相对首帧缩放 |
| `--scale-multiplier` | 在 ROI 缩放基础上的正数乘数，范围为 `(0,20]` |
| `--output` | 项目内 JSON 报告路径，默认写入 `validation/track_bind_<target>.json` |

## 3. 时钟和关键帧映射

跟踪器输出的 `frames[].at_tick` 使用源视频的局部时钟。为了让短文字或贴纸片段也能复用一段较长的跟踪证据，绑定按以下确定性公式把源局部时钟映射到目标片段：

```text
source_span = max(frames[].at_tick, 1)
target_tick = clamp(round(frame.at_tick / source_span * target_duration), 0, target_duration)
```

位置取跟踪中心加偏移后裁切到 `[0,1]`。`scale-mode=roi` 使用：

```text
target_scale = base_scale * scale_multiplier * frame.width / first_frame.width
```

同一目标属性的关键帧按 `linear` 插值写入，并由项目校验器检查时钟范围和属性结构。该映射是可复现的时长归一化，不声称解决源片段与目标片段之间的语义时间对应问题；需要精确对齐时，Agent 应先裁切或重建目标片段再绑定。

## 4. 应用事务和证据

显式 `--apply` 的顺序固定为：

1. 解析项目、源资产、目标序列、目标轨道和目标视觉片段；
2. 运行本地跟踪并生成位置/缩放计划；
3. 创建 `before-track-bind` 项目快照；
4. 写入目标片段的 `transform.position.x/y`，以及可选的 `transform.scale`；
5. 运行项目结构校验；
6. 写入报告、`provenance.change_log` 和操作记录；
7. 原子保存项目。

报告至少包含 `source_sha256`、`asset_id`、`sequence_id`、`target_track_id`、`target_clip_id`、ROI、采样帧、每项关键帧、`scale_mode`、偏移、校验结果、快照 ID、操作 ID 和 warnings。项目写锁、元数据事务和失败恢复遵循通用 [跨文件项目事务恢复契约](./跨文件项目事务恢复契约_v0.1_2026-10-15.md)。

## 5. 目标限制和错误码

目标必须是当前序列中的视觉片段，并且能接受普通 `transform` 属性。以下情况必须结构化失败，不得静默写入：

| 错误码 | 触发条件 | Agent 处理 |
|---|---|---|
| `TRACK_BIND_TARGET_AUDIO` | 目标轨道是音频轨道 | 改用文字/贴纸/效果视觉轨道 |
| `TRACK_BIND_NESTED_UNSUPPORTED` | 目标片段属于嵌套序列 | 先展开或在叶片视觉片段上绑定 |
| `TRACK_BIND_EMPTY` | 跟踪没有可用帧或关键帧 | 调整 ROI/采样参数并人工复核 |
| `TRACK_BIND_APPLY_INVALID` | 写入后项目校验失败 | 使用快照恢复，不发布该项目 |
| `ARGUMENT_INVALID` | 输入、ROI、偏移或缩放范围非法 | 修正参数后重试 |

## 6. 质量边界

- 模板匹配可能在遮挡、主体快速缩放、低纹理、镜头切换和相似背景中漂移；报告始终保留逐帧 `confidence`，Agent 必须在发布前抽查绑定对象。
- `scale-mode=roi` 只按模板宽度变化估计整体缩放，不估计旋转、透视、姿态或非均匀缩放。
- 当前绑定只写位置和整体缩放，不生成旋转、透视、路径变形、运动模糊或多目标关联。
- 源时钟到目标时长的归一化会把起止状态映射到目标边界；源素材发生剪辑、变速或倒放时，必须先使用直接可解释的源范围或另建绑定计划。
- 本地实现不下载模型、不启动 Docker/WSL、不访问网络，也不把绑定结果描述为剪映或模型级跟踪等效。
