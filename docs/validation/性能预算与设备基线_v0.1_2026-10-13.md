| 目标 | 为原生 Windows 的 Agent 剪辑核心定义可测量的资源预算 |

本文件是预算和测量协议，不是对任何机器性能的承诺。第一次真实基准测试后，应把“目标”更新为“已测 P50/P95”，并在设备变化或后端升级时重跑。

## 1. 参考设备档案

至少登记两个原生 Windows 档案：

| 档案 | 用途 | 必须记录 |
|---|---|---|
| `dev-cpu` | 无独立显卡的开发/回归机 | CPU、RAM、磁盘、Windows、FFmpeg、线程数 |
| `prod-gpu` | 目标广告生产机 | CPU、RAM、GPU/驱动、显存、磁盘、Windows、编解码支持 |

设备档案保存为 JSON，引用工具版本和测试素材哈希。禁止把“有 GPU”当作可复现配置；必须记录具体型号和驱动。

## 2. P0 初始预算

目标样例为 1080×1920、30 fps、30 秒、多轨、字幕和一条 BGM。以下数值是首轮预算，超过后必须进入性能风险，而不是静默忽略：

| 指标 | 初始预算 | 测量方式 |
|---|---:|---|
| `doctor` 冷启动 | ≤ 5 秒 | 连续 10 次，记录 P50/P95 |
| `project inspect` | ≤ 2 秒 | 1000 个片段以内项目 |
| `media ingest` | 不低于磁盘顺序读取 0.5× | 1 GB 混合素材，含哈希和探测 |
| 1080×1920 P0 渲染 | ≤ 2.0× 实时（目标） | 30 秒样例，CPU/GPU 分开记录 |
| 项目结构验证 | ≤ 0.1× 媒体时长 | 不含模型推理 |
| 峰值内存 | `dev-cpu` ≤ 4 GB；`prod-gpu` ≤ 8 GB | 操作全过程峰值 |
| 并发渲染 | 默认 1；显式配置后才增加 | 不能因并发产生非确定性或 OOM |
| 临时空间 | 输入总大小 × 3 以内，或提前失败 | 包含代理、中间文件和回滚空间 |

如果输入是 VFR、HDR、透明序列、复杂跟踪或模型推理，必须把实际 profile 标记为 `extended`，不能拿 P0 普通样例阈值掩盖差异。

## 3. 资源策略

- 任务开始前估算磁盘、显存和内存；不足时返回退出码 10，并给出可降低代理规格或并发的建议。
- 代理、缓存和模型权重按内容哈希隔离；清理缓存不得删除项目锁定输入或诊断证据。
- 后端只在声明支持且用户显式选择时切换，并记录 provenance；本地登记的 LaMa/VACE/SAM2 等遵守各自设备契约，不因 GPU 不可用自动回退或换模型。
- 长任务按照操作 ID 写入心跳和阶段进度；超过预算不自动杀死任务，由策略决定取消、降级或继续。
- 每次渲染记录解码、滤镜、编码、I/O 和等待时间，便于区分引擎慢与磁盘慢。

## 4. 压力样例

除 P0 黄金样例外，性能回归应加入：1000 个片段、20 条视频轨、8 条音频轨、1000 个关键帧、CJK 动态字幕、4K 输入下采样、透明图像序列、VFR 和 10 个并发待处理任务。压力样例只用于测量和失败恢复，不自动改变 P0 通过标准。

## 5. 通过条件

性能基线需要同时满足：

1. P50/P95、峰值内存、临时空间和失败原因都有机器可读记录；
2. 同一设备、同一输入哈希和同一锁文件重跑结果在允许误差内；
3. 超预算任务仍生成完整操作报告，不留下可误发布的半成品；
4. 任何改变后端、线程、缓存或模型的变更都触发性能回归并更新版本记录。

| VACE harmonic 本轮 | 8 帧 192×128@8、30 步、5/2；包装 2065.228 秒，pipeline 1154.010 秒，worker 1147.349 秒，加载 597.205 秒，融合 0.128 秒 | 单次扩展 profile；363 项回归并行；非 P50/P95/独占速度基准，详见[正式证据](./evidence/repair-blend-smoke-20261016.json) |

上述均属于扩展模型 profile。当前宿主、父进程和 worker 的完整性读取、模型加载、推理与成片开销必须分开记录；特别是约 19 GB 的 VACE 模型，每个新命令的首次完整 SHA-256 读取仍可能占据主要时间。同一命令持有禁止写/删除共享的读锁期间可复用摘要，下一命令重新读取；不能为了速度退回跨命令 stat 缓存或跳过权重验证。

本轮共享融合声明的是自有数组保守上界，另记 Torch CUDA 峰值分配；二者均不是总进程 RAM/VRAM 的实际峰值。未采集重复样例分布、长输入、4K/HDR 与跨设备基准，性能验收不关闭。最新完整结果、源码冻结、音频与质量边界见[实测](./本地区域色差融合实测_2026-10-16.md)；VACE 历史数字见[正式参数证据](./evidence/vace-profiles-20261016.json)。

现有模型扩展按失败层级返回错误：规划参数/数组上限通常为 2，worker 数值/模型执行失败为 6，取消/超时为 8，完整性为 10，未核验权利发布门禁为 7；不能把上文 P0 资源预检的目标退出码 10 当作所有模型异常的统一现状。读取具体 error code、cause 和失败报告。

后续可评估一次命令内的有限模型批次、分阶段读取进度与显式资源会话，摊薄摘要和模型加载开销；这些当前未实现，须先补命令边界、持续读锁、每任务源/蒙版权利、取消/资源释放和失败隔离契约。不能把这种性能方向描述为已经解决结构或时序画质。

## 光流背景传播研究资源记录（非产品预算验收）

本轮既有原生 OpenCV 5.0.0、CPU 4 线程，无新增模型。10 项独立研究检查及 12/32/32 帧三组诊断完整耗时 113.597 秒，含解码、计算和 NPZ/联系表输出，不代表长期视频或 P50/P95。数组保守估算 WH×(128N+1024)，32×512×288 对应 720 MiB，预算 1024 MiB；排除输入、OpenCV 内部与总进程 RAM，并非实际峰值。研究暂为有限批次，尚无长窗口/重叠、总内存监测或性能验收；未接入产品。见[实测](./本地光流背景传播与遮挡真值实测_2026-10-16.md)与[证据](./evidence/temporal-background-flow-20261016.json)。

## 多运动参考选择研究资源记录（非产品性能验收）

既有原生 OpenCV 5.0.0、CPU 4 线程，无新模型运行。22 项研究检查、两组合成前序对照及四组新方法任务共 183.785 秒；墙面/床单同源新内核 85.060 秒，自然新内核 81.395 秒，均非 P50/P95。WH×(192N+1536) 自有数组估算在 32×512×288 为 1080 MiB，默认预算 1536 MiB；不含输入、OpenCV 内部及总进程 RAM。原生 GetProcessMemoryInfo 记录该 Python 进程峰值工作集约 830.277 MiB、PeakPagefileUsage 约 1197.055 MiB；后者表示提交内存指标，不是磁盘交换量，均不含研究测试/FFmpeg 子进程。与前序任务数量/流程不同，不以两次总耗时计算加速比；长输入、跨设备和正式产品资源验收继续待办。见[实测](./本地多运动参考选择与双表面真值实测_2026-10-16.md)和[证据](./evidence/temporal-reference-selection-20261016.json)。
