# OpenFilm 三套创作流程的本地 CLI 适配设计

**适合复用的是创作步骤和验收问题。三份 Skill 本身不包含自动理解、录屏追焦或视频生成算法。** 先在现有 Agent Project/FFmpeg 主链串联这些步骤，可以减少重新设计 Agent 工作流的成本；完整成片质量仍需独立验收。

## 最小适配与验收路径

1. 每套先定义本地输入计划：输入 SHA、源 tick 区间、画布/FPS、已核对文字、明确锚点及所用模型/声音 ID。它是拟新增工作流计划，不伪装成当前已支持的独立公共 Schema。
2. 把计划转为现有 CLI 的 dry-run；审核影响及摘要，再应用已有事务。模型或输出门禁失败时保留诊断，不补成功状态，不静默换云服务、换设备或降低质量。
3. 每套至少制作一部有使用权的独立实片，保留原输入、可编辑工程、实际编码输出、原命令和失败。分别核对源区间/PTS、音频、字幕、构图及该任务的内容条件。
4. 完成静帧核验后仍需全片播放/听审；若使用 HTML 浏览器路径，沿用现有关闭页面和自建进程回收门禁。保持原生 Windows、本地已有运行时，不启动 Docker/WSL/虚拟环境。
5. 端到端通过后再创建/验证/注册上述三个 `video-cut-` Skill，更新 README 和 Skills 清单并推送 main。创建说明文件不能替代模型、语义或自然质量验收。

R05 所列 **单套 1–2 人日、三套 3–6 人日**，适用于已具备输入计划和人工核对的基础工作流适配（每人日六小时有效工作），不包含开发 OCR/VLM、自动点击识别、跨应用录屏、说话人识别、完整参考片重建或修复字词定位质量。若要求这些自动化能力，应分别设计与估算；现有证据不能给出整套项目的降本百分比。
