# 源音频硬缺口与重叠缓存独立实验

**这是独立实验，尚未发布 V91。** 当前已发布父版为 V90 / `7545d747dffd196434e9591d57d4702850faa94d`，实际完整回归 **2084项 /3875.245s /0跳过**。本实验从其263产品输入出发，当前267输入、163包内资源；新增61个方法。下一次完整门禁预计2145项，尚未以专项、安装或媒体通过代替完整回归和主线发布。

目标和15条约束见[契约](../specs/源音频内部时钟与硬缺口缓存_实验_v0.1_2026-10-21.md)。只使用原生Windows和已有离线工具；没有Docker、WSL、容器或虚拟环境，没有打开交互浏览器tab。

## 1. 缺口与修复

| 编号 | 实际行为与边界 |
|---|---|
| ANC-R01 | 解码帧PTS、nb_samples、原生采样率、声道和time_base构成有界整数索引。内部正缺口补零；后解码帧覆盖重叠区早先样本。原始资产ID、URI、SHA和作者选区保留 |
| ANC-R02 | 只在不连续源需要时写原生采样率float32派生PCM。连续源保留原输入；渲染前float上采样，关闭软async漂移补偿 |
| ANC-R03 | 每个粗PTS有半tick舍入不确定性；与段首相减时合计可达一个粗tick。这个相对容限防止把真实AAC连续1024样本包误拆。精确原生采样格继续使用半采样阈值，真实1采样缺口独立通过。粗容器不能恢复已丢失的亚tick跳变 |
| ANC-R04 | 已选作者窗口的EOF静音在倒放前保留。R3只允许实际原生视频覆盖内的音频EOF静音；超出实际音/视频源末端拒绝，不能相信伪造的探测时长补出源上下文 |
| ANC-R05 | scalar、reverse、曲线、嵌套、R3输入和多机位分析共用源时钟。多机位只读缺失缓存时用E盘临时目录，完成后清理；保留原始来源身份 |
| ANC-R06 | 缓存绑定源、FFmpeg/ffprobe及实现SHA和全部派生字节；上限200万帧、64MiB索引、8GiB PCM、单帧512KiB及256条缓存。此限额不等于已测进程RSS或长片时延 |
| ANC-R07 | CLI `cache list/prune --kind native-audio-clock` 提供盘点和显式清理。作者工程仍登记的源SHA保护对应条目，清理仅已知文件；盘点明确不是字节完整性认证。读取损坏缓存会拒绝，不静默覆盖 |

原生核验实际 **32次CLI＋22条其他原生命令 /37检查通过**。同一原创片有130帧/5.2秒视频，音频是20包×9600样本的原始4秒双声道PCM；包5后增加0.5秒缺口，包10后重叠0.1秒，作者选择前4.8秒。源的所有原始视频帧RGBA及解码顺序PCM均核对；输入帧PTS先核对生成真值。

|---|---|

| R3 | 96帧、184320输出样本/声道；实际引擎输入230400样本，含原生视频覆盖内19200采样的音频EOF静音。没有声称R3输出波形与未伸缩输入无损相等 |
