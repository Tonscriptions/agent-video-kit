# 本地智能剪口播与静音裁切契约 v0.1

| 项目 | 内容 |
|---|---|
| 文档编号 | SPEC-SMART-CUT-001 |
| 版本 | 0.1.0（实现版本 `smart_cut_version=0.2.0`） |
| 日期 | 2026-10-15 |
| 状态 | 有效 |
| 运行边界 | 原生 Windows、Python、FFmpeg `silencedetect`；网络关闭 |
| 关联命令 | `media smart-cut` |

## 1. 目标

`media smart-cut` 是面向 Agent 的本地“智能剪口播”底座。它使用素材自身的 FFmpeg 静音检测结果，并可叠加项目内字幕中的显式短语时间段，把源片段时间轴拆成保留区间和删除区间；Agent 可以先读取 JSON 计划，再选择只报告或应用。实现不调用云端 VAD、ASR、LLM 或剪映运行时。

静音部分只表达可解释的振幅证据。短语部分只对本地 SRT/VTT/ASS/SSA/TTML cue 做大小写折叠后的字符串包含匹配，并按整条 cue 删除，不猜测词级边界；它不等同于语言理解、语义分类或自动填充词识别。

## 2. 输入与参数

```powershell
python -X utf8 -m ai_ad_editor media smart-cut `
  --project .\work\demo `
  --sequence-id seq_main `
  --track-id track_video_1 `
  --clip-id speech_clip `
  --linked-track-id track_audio_1 `
  --linked-clip-id speech_audio `
  --min-silence-seconds 0.6 `
  --keep-padding-seconds 0.12 `
  --apply
```

`--linked-track-id` 可以重复。每个联动轨道默认查找与视频相同的 `clip-id`；若项目使用全局唯一且不同的片段 ID，必须用对应数量的 `--linked-clip-id` 明确绑定。命令不会根据数组位置或素材文件名猜测音画关联。

显式短语裁切可以追加：

```powershell
python -X utf8 -m ai_ad_editor media smart-cut `
  --project .\work\demo `
  --track-id speech_video `
  --clip-id speech_clip `
  --transcript .\work\demo\validation\captions.srt `
  --remove-phrase "嗯" `
  --remove-phrase "这个" `
  --dry-run
```

`--transcript` 必须位于项目根目录内，支持项目已有的 SRT、VTT、ASS、SSA、TTML/DFXP 解析器；`--remove-phrase` 可重复，命令先校验 cue 的范围、顺序和媒体时长，再保存字幕路径/哈希、匹配 cue 和未匹配短语。只提供 `--transcript` 或只提供 `--remove-phrase` 都会返回参数错误。
参数约束：

- `min_silence_seconds` 最小为 `0.05` 秒；只有达到该时长的静音区间才进入删除候选；
- `keep_padding_seconds` 在静音两侧保留环境声，删除区间为 `silence ± padding` 的内侧部分；
- `min_segment_seconds` 防止生成过短的片段；
- `silence_db` 直接传给本地 `silencedetect`；
- `--remove-phrase` 只匹配字幕 cue 文本，命中后将整条 cue 的时间范围加入删除候选；
- 所有时间均以源片段局部时钟计算，最终写回项目 tick；
- 输出报告必须位于项目目录内，项目写回前创建 `before-smart-cut` 快照。

## 3. 计划语义

计划包含：

| 字段 | 语义 |
|---|---|
| `engine` | 固定为 `ffmpeg-local-silencedetect-v1` |
| `network` | 固定为 `disabled` |
| `kept_ranges[]` | 源片段局部时钟中的保留区间 |
| `removed_ranges[]` | 源片段局部时钟中的删除区间 |
| `removed_seconds` | 删除区间总时长 |
| `output_duration_seconds` | 应用后的估算时长 |
| `source_sha256` | 分析时的本地输入哈希 |
| `warnings[]` | 未闭合末尾静音、无可删除区间、字幕 cue 粒度和未匹配短语等可解释边界 |
| `semantic` | 本地字幕路径/哈希、规范化短语、匹配 cue、删除区间和未匹配短语；没有字幕时为空证据对象 |

未检测到可删除静音或命中的字幕短语时，计划保持对应原片段并返回 `SMART_CUT_NO_REMOVABLE_SILENCE` 或 `SMART_CUT_PHRASE_NOT_FOUND` 警告。命中字幕短语时始终返回 `SMART_CUT_SEMANTIC_CUE_GRANULARITY`，提示删除范围是整条 cue；FFmpeg 只给出 `silence_start` 时，末尾静音按素材结束时间闭合并返回 `SMART_CUT_UNCLOSED_SILENCE`。字幕文件缺失、编码或 cue 时间轴不合法时返回 `SMART_CUT_TRANSCRIPT_INVALID`。

## 4. 应用语义

应用只允许直接媒体片段。每个保留区间会生成一个带 `.smartN` 后缀的新片段：

- `source_in_tick/source_out_tick` 按常速或倒放映射到源素材；
- `timeline_start_tick` 重新连续排列，删除区间不会留下时间线空洞；
- 片段关键帧会切片到新的局部时钟，并在边界补采样点；
- 首尾之外的转场句柄会被清除，避免把被删除的静音边界误当作转场；
- 字幕短语时间段与静音候选合并后生成同一组保留区间；
- `--linked-track-id` 与 `--linked-clip-id` 的每个目标使用同一保留区间，保证音画同步；
- 应用后重新执行 Schema/语义校验，记录操作 ID、报告和快照 ID。

以下输入当前明确拒绝并返回结构化错误：嵌套序列、`speed_curve`、`freeze` 或空保留结果。这样不会用未知时间映射静默破坏关键帧。

## 5. Agent 交付门禁

1. 先用 `--dry-run` 读取计划，检查 `source_sha256`、保留/删除区间和 `linked_clips`；
2. 应用后检查 `validation`、快照和操作记录；
3. 使用 `render --dry-run` 检查最终滤镜图，再实际渲染；
4. 使用 `quality check --require-audio` 验证联动音频、时长和音画差；
5. 若需要按本地字幕中的明确短语裁切，使用 `--transcript` + `--remove-phrase` 并复核 `semantic.matches`、`semantic.ranges` 和 `SMART_CUT_SEMANTIC_CUE_GRANULARITY`；该入口按 cue 粒度工作，不能冒充逐词时间或语义理解。
6. 若需要模型级填充词识别、按词切句或说话人语义判断，仍需单独登记和验证的本地 ASR/语言适配器。
