## 3. 已修复的实际问题

- 原生 Python 混入用户 site 的另一套 Torch，引发 torchaudio DLL 加载失败：改为 `-I -B` 隔离启动。
- 上游 tokenizer 默认缓存缺失时会下载：固定本地文件及官方版本哈希，替换下载 resolver，保持网络审计钩子。
- urllib3 导入时探测 IPv6 端口：禁用本进程 IPv6 可用性标志以避免探测，未开放 bind/connect。
- 音频片段字段与 Schema 不一致：统一使用 `source_in_tick/source_out_tick`，按自然 WAV 时长应用。
- URI 形式的权利 ID 被本地策略正确拒绝：改为普通 `tts_adapter_<id>`、`tts_voice_<id>`，没有添加网络例外。
- 候选校验先读取旧权利台账而产生缺记录误报：同一元数据事务中先保存候选台账，补充精确回滚断言，最终 148/148 回归通过。
- 自定义预览画幅与质量检查默认画布不同：smoke 显式传入一致的尺寸，不修改质量门槛。

失败样例保留在其他独立 smoke 目录中用于诊断，最终证据采用通过全链路的 `-d` 项目。

## 4. 验收边界与下一步

本轮没有进行人工逐字试听、CER/错读测量、情绪/方言/多声线或长文本验收，也没有确认完整模型商业许可证。因此“生成出可读且可渲染的中文音频”已获得证据，“达到剪映全部配音效果”仍未达成。

后续需固定授权中文语料与听感样例，验证错读、断尾、音色稳定性、长文本拆批、语速/情绪控制、字幕对齐及跨设备资源预算。当前 Python 网络审计是运行约束，不是对任意恶意原生库的 OS 沙箱。
