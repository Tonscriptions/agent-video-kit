# OpenFilm 当前复用决策

结论：**适合拆模块，继续使用现有 Agent Project + Python/FFmpeg 主链。** 最有价值的分句、关联规则、片段组、帧时钟和 HTML 参数规则已有受控接入；再次搬一套相同主链不会降低成本。新的投入优先放在缺少的创作流程、互操作和明确的质量边界。

本次公开 API 快照为 **853 stars / 91 forks**；准确 UTC 请求时间、原始回复与摘要见[机器证据](validation/evidence/openfilm-release-review-20261018/verification.json)。main 仍为固定 `eefd6a8d379289102141359a4718dbab12170526` / CLI 0.2.0；固定 ZIP 与本地整树 **702 文件**一致。星数是当次快照，不能赋给每份 Skill。未运行上游安装脚本、GUI、provider、浏览器或模型，也未把历史上游测试计成新通过数。

费用判断继续采用[原同范围工期假设](OpenFilm_v0.2增量复用与接入建议_2026-10-18.md#2-面向项目的复用顺序r02-研究时估算)：一名熟悉 Python/Node/FFmpeg 的工程师、每人日约六小时有效开发。历史 O15 单套流程适配约 1–2 人日、XML 约 3–6 人日，均不包含缺少的模型算法、自然画质、目标编辑器全面兼容或整个剪映功能。没有实测总人时，不宣称节省百分比，各项共享工作不能简单相加。

下一批建议先做一个可回放的参考片或录屏工作流，再按实际交付需求决定 XML；继续补本地 AI 自然画质和声音。离线发行的随包 Schema、明确依赖和原生安装入口属于单独的 V47 产品增量，不由本次源码研究冒充实现或测试。

十份 Skill 已进一步整理为[逐项本地 CLI 与能力缺口映射](OpenFilm官方Skill本地能力映射_2026-10-18.md)。本轮只核对固定说明文件和实际分发命令名，没有安装新的 Skill 或执行这些创作工作流。

配套 `openfilm/examples` 另查到描线文字、文字点采样及 WebGL 后处理代码，已记录在[示例与动效内核复用评估](OpenFilm示例与动效内核复用评估_2026-10-18.md)。优先验证独立描线/产品信息卡；WebGL 内核与当前 HTML worker 不兼容，需要单独原型。本轮只读取目录与文本，没有下载示例媒体或接入这些内核。
