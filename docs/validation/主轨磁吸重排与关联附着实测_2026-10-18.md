# 主轨磁吸重排与关联附着实测

2026-10-18 V53。新增 `timeline edit` 的 `reorder` 动作：选中的主轨完整片段形成插入块，所有主轨镜头从零紧邻排列；被挤动镜头的关联配音也跟随。原作者内容、关键帧、嵌套和输出窗口保留。断开的转场默认拒绝，显式 `drop_broken` 才移除。完整剪映功能和效果目标仍开放。

执行前声明的 [MR01–MR18](../specs/主轨磁吸重排与关联附着契约_v0.1_2026-10-18.md)。本地原生 Windows、Python 与既有 FFmpeg；本功能不调用模型、浏览器、Docker、WSL 或网络服务。

## 2. 原输入与实际输出

原创源为 **160×64、10 fps、60 帧/6 秒**的二值黑白计数、移动框与六位条码。没有中间灰阶，适合在当前 H.264 YUV444/CRF0 交付中精确比较切片身份；这不是任意 RGB/YUV 色彩转换无损承诺。独立 48 kHz、双声道 float32 数组有随时间变化的频率与偏置，不能用周期音“碰巧同相”替代源选择。四镜头 A/B/C/D 分别使用物理源 1–2/2–3/3–4/4–5 秒。

## 4. Agent 使用方式与拒绝规则

```json
{"action":"reorder","clip_ids":["c"],"before_clip_id":"a","options":{"linked":true,"linkage":true},"transition_policy":"preserve"}
```

```powershell
python -X utf8 -m ai_ad_editor timeline edit --project <工程> --input <请求JSON> --dry-run
python -X utf8 -m ai_ad_editor timeline edit --project <工程> --input <请求JSON> --expected-project-sha256 <计划摘要> --idempotency-key <请求ID>
```

`before_clip_id:null` 表示末尾；sync/linkage 默认沿用序列，linked 默认 true。计划公开所有主轨变化、被挤动镜头的关联配音、保持锚定的副轨、换轨、字幕补偿、跟踪重绑定、转场移除与最终时长。marker 保持绝对时间。`compose` 的 `linked_edit` 可放进现有单事务批次。

| 条件 | 实际处理 | 核验 |
|---|---|---|
| 锁定关联成员需要移动 | 整体拒绝，不绕开锁 | 专项与最终 CLI 负例 |
| 同一关联组的主轨成员要求不同位移 | 明确关联冲突 | 专项，不静默解除链接 |
| sync 片段跨越不同位移/原主轨空隙 | 拒绝，要求先显式拆分 | 专项与最终 CLI 长床负例 |
| 关联前置音频重排后落入负时间 | 整体拒绝 | 专项与无额外重叠的最终 CLI 负例 |
| 副轨碰撞 | 可用兼容轨或克隆普通音量轨；效果/ducking 总线拒绝换轨 | 专项，包括绑定引用更新及锁定依赖 |
| 真源声明/旧式转场的邻居变化 | 默认拒绝；显式 drop_broken 才移除实际受影响项 | 两种声明的专项；最终 CLI 断开转场负例与新硬切 |
| 幂等/旧摘要/操作记录失败/compose 后序失败 | 重放成功、旧摘要拒绝、失败整体回滚 | 专项实际 CLI 与原生媒体脚本 |
| 超过 20000 片段 | 资源错误，不缩减输入 | 准入专项；不是长片总 RSS/吞吐验收 |

## 7. 发布核验与剩余范围

[独立媒体复核](evidence/magnetic-reorder-real-r5-20261018/media-audit.json)重新解码所有主输出、源视频/PCM、Alpha 和前置参考，核对 CLI 原日志、GIF 时长和公开文件 SHA-256。[静态检查](evidence/magnetic-reorder-real-r5-20261018/static-review.json)记录实际看到的时刻、字幕和复杂作者图；没有连续播放或听审。发行与回归绑定见 [最终审计](evidence/magnetic-reorder-release-final-20261018.json)。

此动作是明确的整片段主轨重排，不实现持久磁吸模式、屏幕距离吸附、全部任意拖拽、自动跨剪口拆声。轨道/根级效果会在新时间重新求值，不声称所有全局自动化的旧声音保持。自然素材/AI、字体塑形、HDR/VFR、4K 长片性能、另一台机器、内容库以及完整剪映功能/效果仍未验收。

新排序/附着算法由本项目实现，继续使用此前经过审查的关联编辑基础设施；没有新增 OpenFilm 原码采用、星数查询或未经测量的工期节省比例。
