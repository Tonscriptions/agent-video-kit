# 项目转换报告规范 v0.1

| 项目 | 内容 |
|---|---|
| 文档编号 | SPEC-CONVERT-001 |
| 状态 | 有效 |
| 版本 | 0.1.0 |
| 日期 | 2026-10-13 |
| 关联需求 | PRD-003、PRD-006 |
| 适用范围 | Agent Project JSON、OTIO、MLT、公开草稿适配器和其他外部项目格式 |
| 互操作边界 | 受限；复杂效果、字体、嵌套结构和外部工程语义必须通过转换报告显式标注 |

转换报告是互操作的事实产物。转换器不能只生成一个“成功”字符串，因为时间线可打开不代表效果、字体、关键帧和权利语义被保留。

## 1. 转换 envelope

```json
{
  "report_version": "0.1.0",
  "conversion_id": "conv_20261013_0001",
  "source": {"format": "otio", "version": "1.0", "sha256": "sha256:…"},
  "target": {"format": "agent-project", "schema_version": "0.1.0"},
  "policy": {"mode": "best_effort", "bake_effects": false, "fail_on_unsupported": false},
  "summary": {"status": "success_with_warnings", "exact": 12, "mapped": 5, "approximate": 2, "baked": 0, "unsupported": 1, "failed": 0},
  "items": [],
  "artifacts": [],
  "warnings": [],
  "errors": [],
  "provenance": {}
}
```

`source` 必须包含格式、版本、文件哈希和适配器版本；`target` 必须包含目标格式/schema；`policy` 必须声明遇到不支持能力时是失败、近似、固化还是保留原始数据。

## 2. 能力状态

每个被发现的轨道、片段、效果、关键帧、字体、音频处理和模板变量都要生成一条 `items[]`：

| 状态 | 语义 | 是否可编辑 |
|---|---|---:|
| `Exact` | 字段、时间和行为可以直接保留 | 是 |
| `Mapped` | 映射到目标格式等价能力，参数变化有说明 | 是 |
| `Approximate` | 视觉或行为近似，存在已知差异 | 通常是 |
| `Baked` | 效果被预渲染成媒体，原始参数保存在报告中 | 否 |
| `Unsupported` | 目标格式或引擎当前不支持，原始数据被保留或跳过 | 否 |
| `Failed` | 转换发生错误，目标项目不可宣称完整 | 否 |

`Unsupported` 和 `Failed` 不能被汇总成成功；如果策略是 `best_effort`，总体状态也必须是 `success_with_warnings` 或 `partial`。

## 3. 映射项字段

```json
{
  "item_id": "clip.video.003.effect.002",
  "source_path": "sequence[0].tracks[2].clips[3].effects[1]",
  "target_path": "sequences[0].tracks[2].clips[3].effects[0]",
  "capability": "motion_blur",
  "status": "Unsupported",
  "reason_code": "TARGET_CAPABILITY_MISSING",
  "message": "目标引擎没有可验证的运动模糊实现",
  "preserved_source": "extensions/source-items/clip.video.003.effect.002.json",
  "suggested_action": "bake_or_remove",
  "evidence": []
}
```

必须记录源路径和目标路径；嵌套项目、复合片段和逐词字幕也必须能定位到具体节点。`reason_code` 使用稳定枚举，例如：

`SOURCE_FORMAT_UNKNOWN`、`SOURCE_VERSION_UNSUPPORTED`、`MEDIA_MISSING`、`TIMEBASE_CONVERSION`、`FONT_MISSING`、`EFFECT_MAPPING_MISSING`、`KEYFRAME_INTERPOLATION_UNSUPPORTED`、`LICENSE_BLOCKED`、`TARGET_CAPABILITY_MISSING`、`ADAPTER_ERROR`。

## 4. 转换策略

- `strict`：出现 `Approximate`、`Unsupported`、`Baked` 或 `Failed` 即失败，适合回归和发布前验证；当前 CLI 的 `--strict` 只在明文草稿适配器实现。
- `best_effort`：允许 `Approximate`/`Baked`，但必须生成报告并在输出包中保存原始数据。
- `metadata_only`：只读取结构和能力，不产生可发布媒体或目标工程。
- `bake_effects`：允许对明确列出的效果固化；每个固化项要保留原始效果参数、输入哈希和渲染命令。

转换器不得解密、绕过登录、伪造访问令牌或抓取受限制的在线资源。私有草稿格式只能在拥有合法授权和公开可读输入的情况下做适配；报告必须保留版本和失败边界。

## 5. 成功判定

转换总体状态：

| 状态 | 判定 |
|---|---|
| `success` | 没有 `Approximate`、`Baked`、`Unsupported` 或 `Failed` |
| `success_with_warnings` | 有近似/固化/不支持项，但按照策略输出且报告完整 |
| `partial` | 生成了项目或媒体，但关键轨道/能力失败 |
| `failed` | 没有可用目标项目，或严格策略被触发 |

转换成功不等于版权成功。发布仍需单独执行 `rights check`。

## 6. 回归样例

每个适配器至少要有：单片段、双轨、关键帧、变速、字幕、字体缺失、转场、透明素材、音频淡入淡出、嵌套/复合片段和缺失媒体样例。样例必须固定输入哈希、适配器提交、目标 schema 和预期状态计数。

## 7. 当前本地适配器边界

2026-10-14 的 OTIO JSON 导出使用标准 `Timeline.1 → Stack.1 → Track.1 → Gap.1/Clip.2` 层级。时间用项目 tick 值与 `ticks_per_second` 构成 `RationalTime.1`，前导与片段间空隙写为 Gap；轨道种类、ID、order 和完整 Agent 片段写入 `metadata.ai_ad_editor`。内联文字使用 `GeneratorReference.1`，其实际文字、样式与动画仍保存在本地 metadata，外部 OTIO 播放器不因此自动拥有这些渲染能力。

OTIO 导入接受 canonical Stack 及旧的顶层轨道数组，保留顺序轨道的 Gap、Clip 与本地 metadata；相对媒体引用以 interchange 文件所在目录解析，并先经过本地协议门禁。若没有本地 metadata，导入只能映射媒体、源范围与基础时间；复杂效果、嵌套 Stack、Transition 与高级动画仍需要具体适配器或 bake 证据。重叠片段超出顺序 Track 的原生表达范围，必须报告 `Approximate`，不能用“能导出”证明外部编辑器会保持相同合成结果。

MLT XML 导出声明 profile 帧率，playlist 前导/片段间空隙写为 blank，entry 的 in/out 使用闭区间帧范围；完整 Agent 片段保存在 `ai_ad_editor_clip_json`。MLT 导入按 profile 帧率读取 blank 和 entry，保留可辨识的本地轨道 ID/order/kind 并对媒体路径去重；目前仍是受限 MLT 结构映射，复杂 filter/transition、嵌套 tractor、字幕生成器、代理和多序列工程不能标记为 Exact。

2026-10-15 新增 `jianying-draft-json` 本地明文双向适配器。报告包含 `source/target/policy/summary/items/warnings/errors/provenance`，兼容保留既有的 `source_format/target_format/failures`；每个条目有稳定序号、源/目标定位、能力、状态及原因。未知版本、文字商业排版、Bezier 语义和独立音轨视频容器标为近似，私有资源及未映射结构标为不支持；缺失素材为 Failed，总体 `partial`，CLI 不能返回成功。strict 拒绝通过错误 envelope 的 `cause` 返回损失条目，不发布目标。未映射源参数存入脱敏旁车，不下载私有资源、不保留可执行端点，当前不做自动烘焙。完整映射与验证范围见[明文草稿适配器契约](./本地明文草稿双向适配器契约_v0.1_2026-10-15.md)。
