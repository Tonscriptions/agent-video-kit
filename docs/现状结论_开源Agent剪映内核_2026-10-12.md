# 现状结论：开源、面向 Agent 的“剪映类型”内核


| 文档编号 | RESEARCH-2026-10-005 |
|---|---|
| 状态 | 有效 |
| 本次审计复核 | 2026-10-13 |
| 证据性质 | 阶段性结论；需随上游版本刷新 |
核查日期：2026-10-12。这里的“剪映类型”按功能拆成四层：时间线/工程内核、Agent 控制接口、AI 能力、模板与交付体验。

## 直接结论

**有一个项目明确把自己定位成开源 CapCut 替代品，并且提供给脚本和 Agent 使用的 API：Concat。** 当前上游 README 声明它包含本地字幕、文本转语音、声音克隆、背景移除、关键帧、170+ 效果/转场/文字动画、多轨、4K 导出，并提供 JSON-RPC、gRPC、MCP 和 CLI；代码采用 AGPL-3.0。这个回答“有没有面向 Agent 的开源剪映类型功能内核”时，答案是 **有，首要候选就是 Concat**。

**但目前没有经过本机和独立样片验收、可以负责任地称为“全面达到剪映成熟度”的完整开源产品。** Concat 上游明确标为 beta；其 v0.2.6 Windows x86_64 发布二进制问题 #303 仍是开放问题。README 的功能列表证明项目方向和接口存在，不能单独证明每一项在当前 Windows 构建、中文素材和广告工作流中都稳定可用。

所以要区分两句话：

1. **“有没有这样的开源内核项目？”——有：Concat。**
2. **“有没有开箱即用、稳定、完整等同剪映并可直接交付广告的 Agent 产品？”——目前没有被核实到。**

## 候选内核的准确位置

| 候选 | 内核/Agent 能力 | AI 与剪映式功能 | 当前判断 |
|---|---|---|---|
| **Concat** | 原生 Rust/GPU 编辑器；JSON-RPC、gRPC、MCP、CLI；Windows 可用方向 | 上游声明本地 Whisper 字幕、TTS/声音克隆、背景移除、关键帧、170+ 效果、标题、多轨、4K | **产品定位最接近；Beta，需先验收 Windows、模型许可、渲染和 Agent API** |
| **Shotcut + shotcut-mcp** | 已有保存工程编辑、预览、联系表、渲染、事务保护、MLT 工程交付；关键帧/速度接口具体 | Shotcut 本身有大量 MLT 效果，但本地 AI、模板和语义剪辑需外接 | **当前最容易做成可交付 Agent 编辑工作台；不是一体化剪映替代品** |
| **Kdenlive + Kdenlive-mcp** | 版本化 JSON、修订检查、撤销/重做、关键帧、效果、转场、字幕、渲染队列、QC、Kdenlive/OTIO 导出 | 本地 AI 分析仍为规划项；模型、Kdenlive、MLT、FFmpeg 需单独提供 | **结构化 Agent 编辑核心很强；AI 与模板层不完整** |
| **Kdenlive + DCC-MCP** | 项目、素材、时间线、特效、字幕、MLT 渲染等 typed tools；native 实时桥接为实验性 | 依赖 Kdenlive/MLT 能力，完整 AI 工作流仍需建设 | **现成 Skill 较多；实时桥接和部分复杂编辑不能算稳定全覆盖** |
| **video-recap-skills** | 场景理解、脚本、切片、配音、字幕、FFmpeg 组装和 QC | 默认 AI 路径需换成本地开源模型；画面关键帧和模板较弱 | **内容流水线，不是剪映式编辑内核** |
| **run-concat** | 编译、启动和开发验证 Concat | 不负责广告选段、模板、字幕、运镜预设 | **研发辅助 Skill，不是生产核心** |

## 为什么 Concat 仍不能直接宣布“等同剪映”

- 上游自己把当前应用标为 Beta。
- Windows x86_64 的 v0.2.6 发布二进制有公开的未关闭问题；需要验证后续构建，不能把“支持 Windows”当作本机已通过。
- “170+ 效果”和“本地 AI”是项目功能声明；还需要逐项确认模型、权重、声音和第三方依赖的许可证，不能只看主仓库 AGPL-3.0。
- Agent API 存在，不代表自然语言规划、广告模板、品牌规范、镜头选择、失败恢复和批量版本管理已经达到剪映的产品体验。
- 本项目尚未使用 Concat 完成真实广告样片，也没有做同素材、同字幕、同运镜的对照验收。

## 对本项目的选择

如果只选一个项目继续研究：

- **要“最像剪映、最像一个完整产品”：选 Concat。** 建议本地入口名 `$video-cut-concat-editor`，但先做 Windows 可运行性、MCP/JSON-RPC 最小闭环、关键帧、字幕、背景移除和 MP4 导出验收。
- **要“现在更稳地给 Agent 做广告”：选 Shotcut + shotcut-mcp。** 建议入口名 `$video-cut-shotcut-pipeline`；它的保存工程、预览、渲染、事务写入和 Windows 集成证据更清晰，但需要另外建设 AI、模板和预设层。
- **要“可审计、可批量、可回滚”：选 Kdenlive + Kdenlive-mcp。** 建议入口名 `$video-cut-kdenlive-batch`；版本化 JSON、修订和 QC 设计适合批量广告，但本地 AI 分析尚未实现。

最终建议是：**Concat 作为“目标内核/对标对象”，Shotcut-MCP 作为当前生产主线，Kdenlive-MCP 作为批量和审计备选。** 这样不把 Concat 的产品愿景误报成已经验收的生产能力，也不把 Shotcut 的 MCP 适配器误报成完整剪映。
