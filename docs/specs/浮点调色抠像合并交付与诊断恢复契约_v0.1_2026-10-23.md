## HTML 总期限与诊断语义

`motion html-render --timeout-seconds` 继续表示从项目加载、源与运行时准备到渲染共用的总期限。本轮不延长产品默认期限，不把昂贵准备工作移出总期限。

完成准备后已超时、或取消文件已存在时，不能启动渲染 Job 或创建应用快照；返回原有 `HTML_TIMEOUT`/`CANCELLED` 及对应退出码，并在 `validation/html-motion-*.json` 保存诊断。两者同时可观察时取消优先。

未启动渲染的报告明确 `phase="before-render-job"`、`render_processes_started=false`、`cleanup.native_job=false`、`not_started=true`、空 PID 集合和无活动进程；这只是渲染阶段未启动，不能伪装成已创建和清理真实 Job。若之前已完成 strict 布局检查，将其完整成功报告、原始路径和 SHA 嵌入失败报告的 `layout_evidence`；独立成功文件会随事务回滚删除，不返回失效的活动链接，也不把布局成功事实改写成失败。项目与版权账在失败后保持原字节。dry-run 不写失败报告或创建进程。

冷 CLI 的四秒超时测试允许真实地在准备阶段耗尽期限；另外新增已经准备完成的本机无限帧测试，明确要求真实 Node/FFmpeg/Chromium 后代已启动，并验证全数回收。不能只用零进程报告替代浏览器故障清理验收。

模拟抠像 worker 的 wait/cancel 模式先处理协议控制，再导入 NumPy；诊断触发测试在实际 worker 启动后明确写取消请求，生产总期限仍为原来的两秒。它校验取消优先、原始元数据和所有已启动角色清理，不以机器导入速度充当取消时钟。

## 包、全量与发布门禁

1. 全部依赖来自固定本地 wheelhouse；原生 Windows、普通目录安装，禁止 Docker、WSL、容器和虚拟环境。运行不下载依赖、模型或媒体，不调用云 provider。
2. 330 产品输入不可在 owner 运行时改动。八个离线轮包、197 个运行资源、931 个 NumPy 文件及许可原文必须与源码/轮包/新安装目录逐字节一致。
3. 804 项安装验证包括 796 项浮点/预览/队列方法和 8 项专门的准备诊断、真实浏览器超时、抠像取消/超时检查；必须使用 `-I -S -B`，运行模块来自新安装 site。
4. 最终 2,897 项必须针对同一冻结候选实际执行、0 跳过；八项外部媒体/字体夹具、HTML 与音频原生工具链及所有验收脚本前后固定。未通过则停止发布，保留真实日志。
5. README、构建进度、需求/差异/验收矩阵、CLI 契约同步编号证据和原片/GIF，区分历史分项和最终组合结果。先审阅新的本地 Git stage 与链接，再合入 main、普通自动推送；不再次 force。

## 继续保留的产品目标

显式 `float32-native-v1` 选择共同路径；默认后端迁移、所有效果/转场/字幕/跟踪的共同精度、自然素材本地 AI 质量、HDR、长片并发与峰值 RSS、完整开放素材/模板库，以及剪映全部功能和观感等价继续保留为开发和验收要求。方法数、合成图和单帧 4K 通过均不能替代这些要求。
