# 逐帧调色参数自动化契约 v0.1

本契约约束差异矩阵 #33（效果参数关键帧）、#45（调节层）与调色能力的后续实现。V57 的色温、色彩平衡、三向色轮、曝光和色阶仍为静态滤镜；V58 应在既有本地 FFmpeg 主渲染链执行这些参数的实际动画，保留普通可编辑工程字段。

| 编号 | 必须满足的行为 |
|---|---|
| EA-01 | 支持 `color_temperature.kelvin`、`color_balance.red/green/blue`、`color_wheel` 九个 shadows/midtones/highlights RGB 数值、`exposure.amount/black`、`color_levels.input_black/input_white/output_black/output_white`，共 19 个数值通道；原有类型别名、参数别名及效果关键帧命名空间保持兼容。布尔/枚举、曲线字符串和 LUT 强度不由本条推出可动画化。 |
| EA-02 | 使用现有 `effects[].keyframes` 或 `effects[].parameters.keyframes`；顶层数组优先。关键帧保持作者输出局部 tick，支持 hold、linear、ease_in/out/in_out、Bezier；静态参数继续走原滤镜，不改旧画面。 |
| EA-03 | 动态参数以实际 CFR 显示采样时刻求值。裁切/倒放/速度曲线/复合定格在完整作者输出路径与嵌套路径中保持原时钟。不得用片段平均速度或归零后的新剪口时钟替代。 |
| EA-04 | 每一动态滤镜使用确定性的独立实例名；完整递归图共用命令预算与实例分配器。重复子序列、窗口、同名效果堆叠与并行轨道不得互相修改。命令放在相邻采样之间，首帧显式初始化。 |
| EA-05 | 直接视频、独立文字层、复合容器和序列调节层均接入。时间区间调节层沿用局部时钟；未经验证不得声称为序列绝对时钟。堆叠顺序与既有滤镜一致。 |
| EA-06 | 新支持的动态参数只接受有限数字、合法参数范围、严格递增整数 tick、非重复规范通道和合法 Bezier。未知动态属性明确拒绝，不得继续静态执行并宣称成功。Bezier 超调在逐帧采样后按对应参数范围截断，须在证据中记录。 |
| EA-07 | 新命令只允许本地固定滤镜与数值参数；不开放 Agent 原始 FFmpeg 命令、路径或任意 target。执行前核验本地二进制身份及所需运行时选项；缺少能力明确失败，不退化为静态值。 |
| EA-08 | 命令文件放在项目缓存，以内容 SHA-256 标识，遇到同名异字节拒绝。计划/manifest 记录二进制摘要、CFR、时钟、参数、帧采样数、命令数、文件摘要与资源限制；工程包保留作者数据，换工程重建命令，不依赖旧缓存。 |
| EA-09 | 根渲染图递归累计至多 2,000,000 次参数状态采样、200,000 条数值命令、16 MiB 命令文本与 1,024 个动态实例；超限在启动正式媒体执行前拒绝。该配额不是总进程 RSS 或长片性能验收。 |
| EA-10 | 真实损失受控样例逐帧与独立静态 FFmpeg 参考比较；必须覆盖五类效果、九色轮通道、非整帧起点、29.97 fps、并行/重复实例、嵌套时间映射、输出窗、定格、区间调节层、文字 Alpha、工程包及原生离线安装。完整回归和静态路径控制另计。 |
| EA-11 | 发布原输入、实际 MP4/GIF、可编辑工程包、生成脚本、失败记录和 SHA-256；README 编号行、能力声明、进度与技能同步。程序通过、逐帧像素、目检、连续播放、听审与自然画质分别报告。 |

静态 FFmpeg 参考仅证明同一固定 FFmpeg 工具链的接线、时钟和参数执行，不证明剪映色彩算法等价。色温沿用原有 Kelvin→阴影 RGB 映射；它不是物理色适应或白平衡校准。所有处理仍在现有编码 RGB /滤镜像素格式语义内；HDR、色彩管理、自然广告审美与完整剪映功能/效果等价继续按总需求单列验收。

本地依据：`sources/upstream/ffmpeg/doc/filters.texi` 的 sendcmd、colorbalance、exposure、colorlevels；本机原生 FFmpeg `-h filter=<name>` 的运行时 `T` 标志。此功能不新增网络服务、模型下载、GUI、Docker 或 WSL。
