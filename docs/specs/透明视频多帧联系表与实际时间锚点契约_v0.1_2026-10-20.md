# 透明视频多帧联系表与实际时间锚点契约 v0.1

状态：V71 原生联系表、实际 PTS、透明像素、离线安装与相同 217 输入的隔离完整回归限定通过；自然素材/HDR/连续质量/完整剪映等价未验收。

## 目标与来源

给 Agent 提供可复查的本地画面锚点、透明边缘和 Alpha 证据，供抠像、遮罩、叠加和时序检查使用。
参考 [OpenFilm 7192264 的 look.mjs](https://github.com/openfilm/openfilm/blob/71922644da5d6b67db2cc796d4e057f98999944f/packages/openfilm/src/look.mjs) 的透明解码、先缩小再组成联系表组织方式；保留产品中的 `OPENFILM_LICENSE.txt`。
由原生 FFmpeg/FFprobe 与 Python/Pillow 实现，没有引入 OpenFilm GUI、浏览器、模型或在线请求。

## 调用与返回

```powershell
ai-ad-editor media contact-sheet --project E:/work/demo --asset-id alpha_source `
  --output validation/contact-review --at-seconds 0 --at-seconds 0.17 `
  --at-seconds 0.75 --at-seconds 1.5 --view checker --view light --view dark --view alpha

ai-ad-editor media contact-sheet --project E:/work/demo --input assets/clip.webm `
  --output validation/contact-auto --count 8 --start-seconds 0 --end-seconds 2 --dry-run
```

`--asset-id` 与 `--input` 二选一；输出必须是项目内尚不存在的目录。
实际调用返回 JSON envelope、`operation_id`、`contact`、`manifest`、帧数与 manifest SHA-256。
只登记核验操作，不改写 `project.json` 的创作字节；`quality_accepted` 始终为 false。
`--dry-run` 仍执行本地探测，自动采样时仍读取包时间戳；不解码输出图片，不创建目标目录或创作变更。

## 时间语义

1. 显式 `--at-seconds` 相对首视频流起点，保留调用顺序和重复值。选择目标时刻或其后的首个可解码帧；允许 FFmpeg 微秒寻址产生的 1 微秒量化误差。它不是播放器中覆盖该时刻的前一呈现帧。
2. 样例 12 fps 视频请求 0.17 秒，实际帧为 0.25 秒。图片标题和 manifest 同时记录请求值、实际相对值；不得把请求值当作实际 PTS。
3. 从 `showinfo` 的整数 PTS 与有理数 time_base 计算实际时刻，同时保留文本值、有理数值和时基。不能仅采用显示精度有限的 `pts_time` 文本。
4. 视频流起点与容器起点分别记录；相对 seek 使用 `origin + requested - container_start`。Matroska 缺少流时长时，记录 `format.duration - video_start` 的时长依据。
5. 自动采样先流式读取 packet PTS，仅保留各目标的最小候选和末帧候选，再实际解码核对；处理包顺序与呈现顺序的差别。包时间戳不是已解码图像质量证明。
6. 自动 `count` 是上限；重复候选去重，尾部没有下一候选时回退范围内末个候选。显式锚点落在最后显示帧之后且没有后继帧时，整次失败并清理输出，不伪造时间或复制末帧冒充成功。
7. 变帧率、非零起点和 1200 秒偏移有独立已知帧测试；不据此声称所有容器、旋转元数据和损坏码流均已兼容。

## 透明通道与图像

默认四种视图：`checker`、`light`、`dark`、`alpha`，也可重复传入不同的 `--view` 选择子集；重复同一种视图拒绝。
棋盘格为 12 像素、灰度 96/192，浅色底为 255，深色底为 0；Alpha 面板为独立灰度值。
VP8/VP9 检出 `alpha_mode=1` 时显式选择 libvpx 解码器，防止透明通道静默丢失。
按源比例缩小，不放大，规范到方形像素；需要缩放、SAR 或旋转时通过浮点预乘 Alpha、缩放、反预乘后转 8-bit RGBA。
每帧记录原 PNG、RGBA 和 Alpha 摘要及 Alpha 极值；每个面板记录坐标、尺寸和 RGB 摘要。

标注使用现有 Pillow 12.1 内嵌 Aileron Regular 默认字体，记录字体字节摘要，不依赖宿主字体回退。
字体由现有 Pillow wheel 提供，本功能没有另行分发字体文件；来源视频的 CC0 声明不扩大为第三方字体授权声明。
这些图是 8-bit 预览，不能用来验收源精度、HDR、色彩管理、自然人像质量或连续运动。

## 输入、预算与进程

| 项目 | 契约 |
|---|---|
| 输入 | 本地单文件、非空、最多 2 GiB；实际容器白名单，ffconcat/HLS 等多文件引用拒绝 |
| 视频 | 源最长 7200 秒，宽高各最多 8192；静态图片支持单帧 |
| 锚点 | 1–32 个，有限非负值，位于 `[0, duration)`；显式锚点不能合用 start/end |
| 单元格 | 宽高各 32–640；列数 1–8 |
| 联系表 | 最大边长 8192、最多 1600 万像素；含每组 42 像素标题区 |
| 探测/索引 | 各自 60 秒原生受控进程；索引单行最多 512 字节，候选状态与 count 有界 |
| 解码 | `--timeout` 0.1–3600 秒，默认 300 秒；作用于解码组合过程，不是整个命令的总期限 |
| 取消 | 项目内 `--cancel-file`；不能位于待发布输出目录；已有标记与子进程启动后标记都生效 |
| 字节绑定 | 源、FFmpeg、FFprobe 实际 SHA-256，执行范围内持读锁并在解码前后复查 |
| 进程清理 | 原生 Windows Job 管理子进程；成功/取消/超时记录 cleanup，不使用虚拟化环境 |

PNG 尺寸/文件大小和单帧 256 KiB stderr 在步骤结束后检查；它们不是进程峰值内存或落盘总量的绝对硬预算。
源/工具绑定不声称枚举所有系统 DLL 或所有 Python 运行实现；发行回归另冻结产品源码、测试与资源字节。
探测和自动索引虽然有时间限制，也会读取长文件，未提供长片吞吐基准。

## 发布与失败

输出先在相邻私有临时目录生成，全部帧与清理完成后将整个目录重命名为目标；已有目标拒绝，不覆盖。
包含 `contact.png`、`frame-NNN.png`、逐帧 stderr 和 `manifest.json`。
失败清理本次拥有的临时目录；操作收据登记失败时清理本次已发布的媒体目录。此承诺不延伸为整个项目所有历史媒体的事务。
错误 envelope 使用 `CONTACT_*` 或既有路径/取消错误；取消退出码为 8、执行失败为 6、媒体不支持为 4。调用方应读取实际 code/exit code，保留诊断，不把有图片残留当作成功。

## 核验边界

当前 [实测报告](../validation/透明视频多帧联系表与Alpha核验实测_2026-10-20.md) 包含 25 项针对性、四锚点/十六面板的独立像素对照、原生 CLI 和离线安装。
进程取消使用真实 FFmpeg/FFprobe 子进程；超时分支使用受控阻塞原生 Python 子进程，不冒充真实 FFmpeg 挂死测试。
保留早期正起点寻址失败和 ffconcat 测试夹具失败，不累加重跑次数。
不自动通过任何 selected/clear、广告权利、自然素材、音频听审或完整剪映效果验收。
