## 1. 修正的问题

旧 `split_clip` 按源跨度比例拆源点，并截断关键帧，没有在边界保留原曲线状态；倒放、非线性速度、淡入淡出和音频处理可能改变。旧 `ripple_delete` 删除片段中段时只是缩短尾部，保留的内容错误；跨删除右边界时还可能使用完整删除长度代替片段内实际删去长度。旧插入要求先手动拆开片段。

新操作保留完整作者片段，再选择其**已经完成倒放、曲线变速、定格、动画、字幕、蒙版和片段级音频处理之后**的输出时间窗。中段删除明确保留左右两段。源时钟、原始曲线控制点和关键帧不按比例重建，也不烘焙成新媒体。

这是有限的原生时间线功能交付，仍需继续实现源范围外扩、滚动/专业滑移、插入覆盖、完整磁吸联动和性能优化。

## 2. 持久表示与时钟

原有 `clip.timeline_start_tick` 是可见窗口的新落点，`clip.duration_tick` 是可见时长。新增：

```json
{
  "presentation_window": {
    "version": 1,
    "authored_start_tick": 90000,
    "authored_duration_tick": 360000,
    "offset_tick": 180000
  }
}
```

`authored_start_tick` 保留原序列的作者起点，尤其用于文件字幕。`authored_duration_tick` 保留完整输出时长，包含已有定格；`offset_tick` 是该完整输出内的选区起点。可见范围为 `[offset_tick, offset_tick + clip.duration_tick)`，必须非空且完全位于作者时长内。字段精确匹配、整数类型且非布尔，未知字段与 null 拒绝；语义校验不依赖可选 JSON Schema 执行器。

`source_in_tick/source_out_tick` **仍表示完整作者输入**；`speed_curve` 继续使用原源轴，关键帧、效果/crop/mask 轨道使用完整作者局部轴。不能从顶层源范围直接推断窗口可见源范围。低层 `update_clip` 的这些字段编辑作者数据；运动预设则把调用时的可见局部范围加上窗口 offset 后保存。连续裁切只累计 offset，保留同一作者时长和起点。

## 3. Compose 操作

统一入口为 `timeline compose --project <本地工程> --input <JSON>`。使用既有 dry-run、快照、事务、操作记录和幂等键；批次任一步失败不保存工程。窗口请求不忽略未知字段。

| 操作 | 参数 | 行为 |
|---|---|---|
| `split_clip` | `clip_id`、片段内 `at_tick`；可选 `left_id/right_id`、`track_id/sequence_id` | 内部非空切点拆为两个窗口；默认原 ID 加 `_a/_b`。生成 ID 检查整项目的资产/序列/轨道/片段冲突 |
| `trim_clip` | `clip_id`；可选 `start_tick/end_tick` | 选择当前可见区间中的半开子区间，保留该 clip ID；默认落点为旧落点+start |
| `trim_clip` 重新落点 | 可选 `timeline_start_tick` | 直接指定裁后落点，例如 0；不是自动波纹 |
| `ripple_insert` | 序列 `at_tick`、正 `duration_tick` | 交叉片段自动拆开；右段与后续片段右移，插入空隙。超出旧结尾时先保留至插入点的空白，再增加完整空隙 |
| `ripple_delete` | 序列 `at_tick`、正 `duration_tick` | 删除整段、中间或交叉边界的正确内容，后续左移；不能删除到原序列之外；全空序列保留 1 tick |
| 波纹轨道范围 | 可选 `track_id` | 省略则全部轨道；单轨不能拆开跨未选轨道的关联组。未选轨道不裁切，不因波纹缩短序列而被截断 |

例如将当前片段第 1–3 秒放到序列 0 秒：

```json
{"operations": [{"op": "trim_clip", "clip_id": "clip_1", "start_tick": 90000, "end_tick": 270000, "timeline_start_tick": 0}]}
```

该示例假定工程 90,000 ticks/s。操作不会自动缩短全序列；需要时另用 `set_sequence_duration`，且不能截断其他片段。锁定轨道拒绝受影响编辑，标记保持绝对序列 tick。切片保留原 link ID；本 API 不自动执行完整主轨骑乘/同步锁规则，整片段联动仍走[既有 planner](关联片段与主轨联动规划契约_v0.1_2026-10-17.md)。

## 4. 渲染顺序与资源

1. 在分离的内存工程中恢复完整作者片段、原始起点和时长；作者片段仍引用原资源或原嵌套序列。
2. 同一 FFmpeg 图计算完整片段，原始速度/倒放/定格、变换、片段效果与字幕、片段音频处理在每个窗口支路内只执行一次。透明画布的实际 pad 为 RGBA；内部使用既有 alpha 模式选择，不导出子文件。隔离表面透明，但保留作者片段原先的 opaque contain 黑边策略，不能因此透出下层。
3. 以作者序列绝对显示帧索引和 48 kHz 采样索引选择窗口，再移到新的序列落点。视频起止采用 ceil 显示帧索引；目标声音为目标半开全局采样区间，遇非对齐相位可能按一个采样的差异补齐。
4. blend 留在与其他背景层合成的外侧，保留其原作者动画时钟。轨道效果、轨道混合/闪避和所选根序列全局调节保留在剪口外侧，按新时间线执行，不能将它们当作裁切前全序列的固定采样承诺。
5. 含窗口的后代序列先原生合成完整音画，再供祖先采样；包括子总线处理后的声音。已有仅转场子级仍沿原始音频叶片路径。渲染图标签及物理输入命名空间隔离，未使用端口明确回收。

清单 `sequence-inline-surface` 的 `purpose=clip-presentation-window` 记录作者/可见时长、offset、帧和采样选择、子输入/警告及 0 中间文件。每个直接序列最多 64 个窗口，窗口递归最多 16 层，并计入既有栅格工作预算；预算不是进程 RSS 上限。完整作者处理可能重复、多倍增加工作量，长片、倒放缓存和大量切口尚未做性能验收。

## 5. 组合边界

| 情况 | 处理 |
|---|---|
| 已有常速、倒放、曲线、定格、动画或片段级音频处理后裁切 | 保留原作者数据与完整处理状态；受控实测见验证文档 |
| 独立文件字幕 | 保留原文件 cue 与作者起点；后续整片段移动不再重复改字幕 offset |
| 窗口内新增运动预设 | 可见局部 tick 加 offset，保留完整作者的校验边界 |
| 部分窗口的 `set_clip_speed/set_clip_speed_curve/reverse_clip/freeze_frame` | 明确拒绝；先在完整作者片段编辑再裁切，不能静默改变作者区间或重排定格/动画 |
| 完整零 offset 窗口的速度/曲线/定格 | 更新完整作者时长；继续执行已有这些功能的边界，不据此接受所有联合时钟 |
| 既有/新建跟踪绑定把窗口作为源或目标 | 拒绝；原跟踪几何尚无窗口映射 |
| `media smart-cut/reframe` 在窗口上执行 | 拒绝；源分析时钟尚未映射到输出选区。先处理完整作者片段 |
| 影响真实源句柄转场端点 | 拒绝，先移除该声明；窗口还不能扩展真实源句柄 |
| 同轨含旧式跨片段转场 | 拒绝，不因隔离计算而丢掉邻居；局部 fade/fade_in/fade_out 可保留。可裁切包含完整转场的嵌套容器 |
| 祖先对已处理的窗口子级再次要求文件型 R3 伸缩 | 拒绝；FFmpeg 内联音频路径仍可使用。未增加临时音频文件来绕过约束 |
| 跨项目片段组 | 保存完整窗口作者信息与资源/权利闭包，仍可编辑；V37 库原有上下文与插入约束继续适用 |
| 外部 OTIO/Kdenlive/明文草稿 | 损失报告标记 `clip.presentation_window` 为 Unsupported；保留 metadata 不代表外部执行等效 |

正例保证的是选定同一已完成作者片段的输出，不是独立证明原曲线音频质量、自然视觉、字词对齐、HDR/VFR 或所有剪映特效。非显示帧边界的窗口是显式离散采样，不声称连续视频无损或与任意剪辑器子帧策略相同。

## 6. 权利与验收

窗口不新增资产或绕过原资产、字体、字幕、LUT、模型依赖及发布门禁；片段组仍收集其闭包。机器测试、固定旧版本渲染原片的逐帧/PCM 对照、公开 MP4/GIF、连续播放/听审及自然广告质量分别记录，不合并计数。失败和中止日志同样保留。

完整剪映功能和效果目标继续有效，尚未达成；本模块不替代整项验收。
