## 1. 运行边界

- 开发、测试、构建和发布使用原生 Windows 工具；严禁 Docker、WSL、容器或其他虚拟化环境。
- 构建脚本必须记录 PowerShell、Rust/Node/Python、FFmpeg 和显卡驱动版本；不能假设用户机器有隐式工具。
- 产品运行期禁止网络访问、模型/素材下载和遥测；模型、媒体、字体和依赖只能来自显式已有本地路径。开发调研的来源获取须独立记录，不能成为运行期下载入口。
- 发行包不得包含剪映/Jianying 私有运行时、破解组件或未授权资源。

## 2. 依赖锁定

当前上游源码快照和提交清单见 [仓库与运行依赖锁定](../仓库与运行依赖锁定_v0.1_2026-10-13.md) 及机器可读的 [`sources/upstream-manifest.json`](../../sources/upstream-manifest.json)。产品 P0 的本地实现与命令示例见 [产品实现入口与 P0 使用说明](../产品实现入口与P0使用说明_v0.1_2026-10-13.md)。

每个发布候选必须保存：

| 类别 | 最低记录 |
|---|---|
| 本项目源码 | Git commit、构建时间、构建脚本哈希 |
| 上游引擎 | 仓库 URL、commit/release、补丁、许可证 |
| FFmpeg/编解码器 | 版本、配置、编译选项、许可证和第三方通知 |
| Python/Node/Rust 依赖 | lockfile、平台、来源和哈希 |
| AI 模型 | 模型仓库、revision、权重许可、推理库版本和量化方式 |
| 字体/效果包/插件 | 资产哈希、许可证、依赖、允许用途 |
| 测试素材 | Rights Ledger ID、哈希、生成脚本或许可证据 |

依赖清单不能只保存包名和版本号；如果上游没有不可变版本，必须保存源码快照哈希并在风险表中注明。

LaMa 可选引擎登记已有 TorchScript、原生 Python 和证据，绑定 9 项实现/输入摘要；实际运行 Python/Torch/numpy、设备、权重哈希和 CUDA 峰值见[实测](../validation/LaMa本地区域修复与物体移除实测_2026-10-16.md)。权重不随包分发，禁止调用 IOPaint 下载器/GUI/HTTP。逐帧修复的自然残影/纹理/时序缺口和未核验商业权利仍阻断整体质量及发布验收。

VACE 可选引擎使用显式本地 Wan2.1-VACE-1.3B 固定 safetensors 清单、原生 Python 和 CUDA；17 个模型文件与 Python/证据/十项执行实现共 29 项摘要，命令内持只读锁才可复用，退出后释放、下一命令重新核验。依赖版本、文本权重分配预算、BF16/FP32 混合精度、窗口及质量边界见[契约](../specs/本地VACE联合视频编辑契约_v0.1_2026-10-16.md)和[实测](../validation/VACE本地多帧编辑与生成填充实测_2026-10-16.md)。模型执行、编码成功和窗口混合不能代替自然时序、生成内容与商业许可验收。

## 3. 许可证与供应链检查

发布前生成依赖清单、许可证清单和第三方通知。检查至少包括：

1. 许可证文本存在且与代码/模型/素材版本相匹配；
2. AGPL/GPL/LGPL、Apache、MIT、BSD、模型和字体条款分别按分发方式审查；
3. 未声明许可证的仓库或素材不得进入默认发布包；
4. 插件和模型的下载哈希与锁定记录一致；
5. 许可证或上游版本变化会阻断发布候选并触发 ADR/风险更新。

## 4. 版本策略

- 产品 CLI、Agent Project schema、转换报告和插件 manifest 分开版本。
- CLI 遵循 SemVer；schema 主版本升级必须有迁移器；效果包/模板包版本必须可回滚。
- 每个发布包包含 `version.json`、依赖锁、能力清单、构建来源和验证摘要。
- 运行项目时记录实际 CLI、schema、引擎和模型版本；加载不兼容项目时先迁移副本。
- 上游升级先进入 `canary`，通过 P0 样例后才能进入 `rc`；不能直接从最新主分支构建生产包。

## 5. 发布阶段

| 阶段 | 允许用途 | 必须通过 |
|---|---|---|
| `dev` | 本地开发 | lint、schema、最小 doctor |
| `canary` | 固定样例和少量内部任务 | 依赖锁、许可证、P0 自动检查 |
| `rc` | 预发布验收 | P0 全量、回滚、转换和权利门禁 |
| `release` | 对外或可发布生产任务 | RC 无阻断项、第三方通知、归档证据 |

## 6. 回滚与恢复

- 发布包、配置、schema 迁移器和模板包必须可独立回滚。
- 发现媒体质量、许可证、供应链或数据损坏问题时，先停止新发布，再恢复上一通过版本。
- 项目文件迁移前创建快照；迁移失败不能覆盖原项目。
- 失败操作、临时文件和日志按操作 ID 保留，清理策略不能删除恢复所需证据。

## 7. 发布门禁清单

发布负责人必须逐项勾选并附证据路径：

- [ ] 原生 Windows 构建成功，未调度 Docker/WSL/容器；
- [ ] 工具、依赖、模型、字体、效果包和素材都有锁定版本/哈希；
- [ ] 许可证和第三方通知已复核；
- [ ] P0 黄金样例通过或所有失败已获 ADR 批准；
- [ ] 转换报告没有未声明的 `Failed` 或权利阻断；
- [ ] Rights Ledger 对目标渠道通过；
- [ ] 输出文件、manifest、日志和 provenance 可读取；
- [ ] 回滚包和恢复步骤在同一 Windows 环境验证；
- [ ] 文档索引、版本号、已知限制和变更日志已更新。
