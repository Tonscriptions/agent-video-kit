# OpenFilm 最新源码复核与降本清单

**结论：继续拆取小模块，保留 Agent Project + Python/FFmpeg 主链。** 当前工程已经采用了其字幕分段、帧时钟、模板和部分剪辑规则，再搬入完整执行链会增加两套工程模型的适配工作。新增价值主要是模板解析修复、工程交换和创作工作流，不能直接补齐本地 AI 特效。

本轮编号为 **R04（源码研究）/V54（模板解析小修复）**。仅同步一处实际适用的正则修复；FCPXML、GPU 选择和官方创作 Skill 保留为候选，没有作为新产品能力发布。

## 降本顺序与工期边界

建议按 **现有模块去重 → 单套创作流程 → GPU 小原型 → 有实际需求的 XML 互通**推进。近期可规划三套创作流程合计 **3–6 人日**的调用适配。流程缺少的视觉理解、对齐、自然画质必须另立实现任务，不能藏进 Skill 工期。FCPXML 主要服务外部工程交换，全开源生产链应优先投入本地 AI、声音和关键帧/运镜质量。

估算假设：一名熟悉现有 Python/Node/FFmpeg 的开发者，每人日约六小时有效工作，包含所述受控范围的实现、文档和定向验证；不包含授权素材/模板内容制作、长片/HDR、多设备发行或完整剪映效果验收。共享的模型映射、资源闭包、测试不能重复加总。本轮没有实际人时对照，**不宣称已经降低整个项目某个百分比的成本**。
