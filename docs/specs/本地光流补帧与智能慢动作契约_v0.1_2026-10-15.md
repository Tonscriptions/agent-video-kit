## 1. 目标

为 Agent 提供可审计的“光流补帧/智能慢动作”底座。项目效果 `frame_interpolation` 映射到本机 FFmpeg `minterpolate`，通过运动补偿或受控帧混合把片段输出帧率提升到目标值。它服务于慢动作、时间重映射和运动平滑，不调用剪映运行时、云端视频服务或在线模型。

## 2. 项目 JSON 形状

效果可以写在片段 `effects[]` 或序列调节层中：

```json
{
  "type": "frame_interpolation",
  "parameters": {
    "fps": 60,
    "mi_mode": "mci",
    "mc_mode": "aobmc",
    "me_mode": "bilat",
    "me": "epzs",
    "mb_size": 16,
    "search_param": 32,
    "vsbmc": false,
    "scd": "fdiff",
    "scd_threshold": 10
  }
}
```

`minterpolate`、`optical_flow`、`smooth_slow_motion` 和 `slow_motion` 是兼容别名；Agent 应优先使用规范 ID。所有数值在渲染前限制在目录声明范围内：`fps=1..240`、`mb_size=4..16`、`search_param=4..512`、`scd_threshold=0..100`。枚举值只允许本机 FFmpeg 过滤器接受的固定集合。

## 3. 执行与安全

1. 渲染器生成单个本地 `minterpolate` filter，不把用户参数拼接为 shell 命令；枚举和数字先经过白名单与范围校验。
2. `mi_mode=mci` 使用本地运动补偿；`dup` 和 `blend` 可作为低成本或兼容 fallback。`mc_mode`、`me_mode`、`me`、`vsbmc` 和场景切换检测映射到 FFmpeg 的同名受控选项。
3. 效果不改变音频采样，不自动声称完成音频变速。片段同时存在 `speed_curve` 时，音画时基仍由时间线时钟决定，补帧只是视频滤镜层；质量门禁必须复核最终音画时长。
4. 效果参数关键帧当前不逐帧执行，渲染器保留 `RENDER_FEATURE_APPROXIMATE` 并使用静态参数，不能把它描述为动态光流参数动画。
5. 本地 FFmpeg 未编译 `minterpolate` 时，渲染失败并保留结构化失败证据；不会下载替代滤镜或调用线上服务。

## 4. Agent 规划与验收

Agent 先调用 `effects inspect --name frame_interpolation`，读取后端、参数范围和限制，再写入计划。dry-run 必须能看到完整的 `minterpolate=` filter；正式渲染必须在 manifest 中保留 FFmpeg 版本、参数和 warning。

固定回归覆盖：

- 本地效果目录返回规范 ID、别名和参数边界；
- `mi_mode=blend` 的低成本 filter plan 能生成且没有 unsupported warning；
- 48fps 目标参数被完整传入本地 FFmpeg filter graph；
- 本机实际渲染成功后，质量检查仍可读取视频流和音画时长。

## 5. 已知边界

`minterpolate` 是 FFmpeg 的局部运动估计器，快速遮挡、镜头切换、透明素材、滚动字幕和大幅运动可能产生重影或撕裂；`scd=fdiff` 只能降低一部分场景切换伪影。运动补偿可能显著增加 CPU 和内存消耗，发布前必须按设备基线运行 `quality check` 和人工抽帧复核。GPU 光流、逐对象模型补帧、自动选择最佳运动估计器和跨设备视觉 golden 仍是后续独立能力。
